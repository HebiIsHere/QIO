# R9-H9 共同根因与执行入口覆盖表

基线 r9h8/main 92c7688b（代码 967401c2）。

## 1. 为什么 H8 记录根因后仍遗漏共同规则

H8 修复集中在具体分支和 helper，未把所有执行入口收敛到同一检查结果：

- 内部目录 content_deferred 分支新增了元数据摘要比较，但把“摘要相同”当成执行前提，没有单独检查 complete；两次都不完整也能通过。
- program_name helper 只判断“对象是否相关”，未复用限制操作集合；write-only 限制也会进入程序拒绝分支。
- 程序名称检查被放在非只读模式条件内，只读模式的固定查询先返回。
- program_name 匹配每次调用 shutil.which、路径仅 realpath 比较：PATH 顺序变化会转移对象；硬链接 realpath 不同。
- H8 测试主要验证同一进程、同一路径和最终拒绝，没有覆盖：批准后执行、执行时完整性、硬链接、PATH 顺序、只读固定查询、write-only 限制。

## 2. 共同检查顺序（所有真实执行入口）

1. 要求绑定：id/version/status/chain 仍有效；
2. 限制操作范围：operations 空=全部，否则匹配实际操作；
3. 限制对象与身份：objects 空=全部；具体对象用路径 + 文件身份/生命周期；program_name 用保存时固化绑定；
4. 完整性：目录影响 complete 必须为 true；缺失/截断/枚举异常均不可执行；
5. 已知限制优先级：早于固定查询、历史授权、模型允许、人工批准和内部确认；
6. 模式：read_only/restricted/unrestricted 既有规则，unrestricted 不进普通审查；
7. 审批/确认/期限/单次执行；
8. 读取顺序：读取权限 -> 内容读取 -> 内容/前置状态 -> 授权确认。

## 4. 旧重复判断与保留职责

- 合并：程序名称对象相关性 + 操作范围；目录完整性只由共同审批/执行检查；程序对象身份统一用文件身份 helper。
- 保留适配：工具提供真实 effect/detail/目录快照；审批执行器提供要求绑定/期限/确认阶段；读取探测只提供“读取权限”事实，不自行授权。
- 不再允许：content_deferred 自行绕过完整性；program_name 分支自行忽略 operations；read_only 分支跳过限制；执行时重新 which 改写绑定。

## 5. 防回归测试

- 目录 502 项不完整不创建审批；执行时新增超限也不执行；完整/变化/无额外限制覆盖。
- 真实硬链接同一 Python 对象拒绝；同内容复制件允许；路径限制和名称绑定都按对象身份。
- 保存绑定后改变 PATH 顺序：原 A 绝对路径仍拒绝，名称入口不自动转移；重启从 JSON 恢复绑定。
- write-only 程序名称限制不阻止运行。
- 三种模式明确程序禁止阻止固定查询；普通固定查询仍正常。
