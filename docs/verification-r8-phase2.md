### 2.1 r7 报告里「带附件发送 no-request」的定性（问题一成立的最直接证据链）

r7 阶段二实测：界面点发送后**没有任何 \`POST /api/turns\`**（请求级缺失 + 输入框内容未被清空 + 台账无预留行），当时记为「装置限制」。
本轮定性：**根因是 CORS 预检被拦**（\`allow_headers\` 缺 \`X-QIO-Prepare-Id\` → 浏览器在预检阶段就拒绝了这次跨来源写请求）。证据链：

1. 后端预检用例：同一请求（可信来源 + 该头）**基线 400 \`Disallowed CORS headers\` → 修复后 200**；
2. 实机同一路径（页面 5199 → 接口 8734）本轮 \`postCount=1\`、\`prepareHeaderSeen=true\`、\`sendStatus=200\`、\`allowOrigin=http://127.0.0.1:5199\`、\`corsErrorCount=0\`；
3. 同一台机器、同一套脚本装置，r7 时失败、r8 时成功 —— 差别只有这一行 CORS 允许头。

→ 结论：r7 的 no-request **不是装置问题**，是产品缺陷；本轮已修复并有请求级证据。

## 4. 边界与未验证清单（如实）

1. **真实硬件级损坏**：磁盘坏道 / 掉电 / 文件系统损坏未测；本轮的破坏都是**真实文件操作**（truncate/append/delete），但不是硬件故障。
2. **多实例共写 tmp**：两个进程共用同一 \`<data>/tmp\` 时的清理与命名竞争未验证。
3. **100MB 兼容路径**：只验证了小文件；接近上界的兼容路径（等待窗口长、超时边界）未验证。
4. **引用型（changed）时序**：契约 §1.3 点名的「归属变化 / 引用型变更」未构造用例。
5. **超时边界**：有界等待的生产等待值未被真实等待到（只验「不放行不执行、放行后执行」）。
6. **重新打开对话后警告是否仍可见**：取决于轮次事实持久化；保持**未验证**（不把说明塞回正文）。
7. **准备期「中止」窗口**：本机复制是硬链接/亚秒级、界面会挡住未就绪发送 → 浏览器里难以复现「请求已发出但仍在准备」的窗口；替代证据是后端 \`test_r8_cancel_target_verify.py\`（准备中 → cancelled，且带本次 turn_id）。
8. **Windows 原生窗口 / 安装包 E2E**：不具备 → 未验证。**明确不用浏览器预检/浏览器链路冒充原生实机。**
9. **HTTP/2 或反向代理下的 CORS/断连行为**：未验证（本轮是 HTTP/1.1 直连）。
