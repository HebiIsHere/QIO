## §1 冻结契约

### §1.1 问题二：内容角色协议（消除完整答案重复生成）

**角色必须在正文展示前确定，且只能由模型显式声明**（禁止用延迟、字数、是否含代码块等启发式猜角色）。

**协议**：模型给出最终回答时，正文**以角色声明开头**：`[[QIO:ANSWER]]`（大小写不敏感，其后可跟换行）。声明本身**不作为正文展示**。

**判定规则（流式，按最长可能前缀缓冲，最多 32 字节即可判定）**：
1. 缓冲与声明**完全匹配** → 该调用是**回答调用**：声明之后的所有正文**实时**进正式回答区（`interim=false, streaming=true`），保持真流式。
2. 缓冲与声明**前缀不再匹配** → 该调用是**工作调用**：正文按进度说明**实时**进过程区（`interim=true`）。
3. **未声明（无标记）**：该调用的正文**先不展示**（有界缓冲，上限 64 KB；超过上限即判定为工作调用并实时放行，绝不无界缓存）：
   - 调用结束**有工具调用** → 缓冲文字是过程说明 → 放行到过程区（不丢字）；
   - 调用结束**无工具调用** → 缓冲文字是正式回答 → **一次性**交付到正式回答区（同 `delta_id`、`{interim:false, streaming:false}`），**不重新生成、不搬动、过程区不留副本**。这是**协议未遵守的降级路径**，如实记录，不冒充流式。
4. **声明之后的迟到工具调用**：**不执行**该工具，发一条**可见警告**（`WARNING` 事件），整轮按已声明的回答收尾。绝不隐藏或忽略真实工具调用来让测试通过。
5. **冲突/非法**：声明不在开头、被拆坏、重复出现、出现在已放行正文之后 → 按「未声明」处理（不猜测、不改写、不重发）。
6. **兜底（有触发条件的额外调用）**：整轮结束时**完全没有回答内容**（无声明、无缓冲正文）→ 最多发**一次** `tools=[]` 的调用要求给出最终回答。这是唯一允许的额外回答调用，触发条件写进文档与注释。

**成本**：合规模型下，直接问答只需 **1 次调用**（删除现在「每轮固定多一次回答调用」的代价）；额外调用只在「模型确实调用过工具」或「整轮没有回答内容」时发生。

**保留不变**：`delta_id` 稳定、累计快照、`(delta_id, seq)` 单调去重、断线重连、历史恢复、`TURN_END.final_content` 只做校准（**结束事件不是正文首次出现的来源**）；不支持流式的 provider 如实 `streaming=false`。

### §1.2 问题一：接收端与工作线程共同收敛（B 独占上传路由）

- 接收循环必须在**等待下一块网络数据时**同时观察：作业终态、取消信号、请求取消。做法：把 `request.stream().__anext__()` 包成 task，与终态事件做 `asyncio.wait(..., FIRST_COMPLETED)` 竞争；每轮**清理 pending task**，不泄漏。
- 工作线程失败后，**不需要客户端再发送任何字节**即可进入失败收尾（关键断言必须在客户端闸门仍关闭时成立）。
- 用户删除上传中的附件时，即使客户端暂停发送，接收任务也能收尾。
- **原因归属互不覆盖**（保留首要原因）：写盘失败 > 超限 > 客户端断开 > 用户取消 > 服务关闭。
- **只有实际退出的工作线程才能被报告为已退出**：退出事实由工作线程自己置位；操作系统磁盘调用无法立即取消时保留真实状态、阻止迟到结果提交 ready，并安排可靠清理。
- 收尾：取消并回收读取/等待任务；清理临时文件、孤儿副本；行不得停在 `prepared`，不得提交 `ready`；活动作业注销。
- 保留：有界队列、上传大小上限、工作线程只做文件 I/O、**SQLite 只在事件循环线程访问**。

### §1.3 问题三：重试克隆的文件 I/O 异步化（C 独占 attachments 服务）

- **冻结接口**（路由接线由 Lead 做）：`AttachmentService.bind_for_turn(...)` 改为 **async**，语义分三段：
  1. **事件循环线程**：校验（存在/同话题/状态/未绑定或绑定在来源轮）+ 建新行（`preparing`）+ 计算目标路径 → 得到 `ClonePlan`；
  2. **工作线程**（`asyncio.to_thread`）：只做文件 I/O（`os.link` 优先，失败退化为**复制**；含必要的 stat/校验），返回结构化结果；**绝不触碰 sqlite**；
  3. **事件循环线程**：按结果定稿（`ready`/`failed` + 原因）并完成绑定，返回 `BindOutcome(bound, rejected)`。
- **不得**把含数据库操作的整个 `bind_for_turn` 塞进 `to_thread`。
- 取消/失败：不留 `prepared`、不留临时文件、不留无人认领副本；**迟到结果不得提交 ready**（代次/取消标记校验）。
- 硬链接按**不可变内容**使用：删除一个历史附件不得破坏其他轮次（硬链接删链接不删内容 → 安全）；不得用共享可变内容降低独立保留语义。
- 保留：原轮归属不变、原轮历史仍可打开、重试用已保存内容（原文件删除后仍可读）、回执准确、缺失副本/跨话题/失效引用**不静默降级成无附件执行**、附件未就绪时不允许模型开始处理该请求、重复点击/并发/排队/取消/刷新一致、≤ `100,000,000` 字节存副本、超过阈值登记真实本地路径。

## §3 验收（D 独立执行，Lead 亲自复跑关键三条）

**问题一**（用 `asyncio.Event`/`threading.Event` 控制时序，超时仅作失败判定）：建目录失败+请求体暂停、打开临时文件失败+暂停、写入中途失败+暂停、删除取消+暂停、请求取消/服务关闭+读取待决、队列满+工作线程提前退出、失败与最后一块/成功提交的竞争。**关键断言在客户端闸门仍关闭时**；至少一组走**真实 HTTP/ASGI 上传路由**；收尾后检查附件状态、活动任务、工作线程状态与目录文件；同期其它 API 能推进。

**问题二**：受控流式 provider 在正式正文第一段后暂停（未发结束事件）时 —— 正式回答容器已显示正文、过程区**没有**这份完整答案的副本、**工具列表非空时同样成立**、**不发生为同一答案再次生成正文的调用**（记录每次调用的内容角色与次数）。覆盖：工作调用直接给出完整答案的**当前反例**、新协议下的合法直接回答、合法过程说明+工具+回答、声明缺失/非法/被拆成多个分块、迟到工具增量、空回答、取消、断流、重连、text 兼容档、中文/长文本/代码块/表格。若协议改变 provider 返回格式，**必须同时测非法/旧格式**。

**问题三**：强制 `os.link` 抛 `OSError` 确保真实进入 copyfile 退路；在复制内部用线程事件闸门暂停并**记录实际执行线程**（必须不是事件循环线程）；闸门仍关闭时其它 API 与受控 SSE 能推进；完成后新轮与原轮都能读出正确内容；原文件删除后仍通过；复制途中失败/取消/并发重试/目标已删除/源副本缺失均准确收尾。性能证据优先用**线程身份与事件推进**，不以毫秒阈值作唯一依据；至少一次用**接近阈值（100,000,000 字节）**的真实文件验证内容完整性与清理结果，并报告是否覆盖等号边界。

**Lead 亲自复跑**：三条关键反例（上传暂停收尾、回答不重复生成、硬链接失败时的复制线程身份与并发推进）。
