## §1 冻结契约

### §1.1 问题一：新请求头纳入 CORS 允许列表（Lead 实施；A 负责前端与验证）

- `X-QIO-Prepare-Id` 进入 `allow_headers`（与既有三项同列）；**保留既有认证、可信来源与 Host 检查**（不放开全部来源、不关认证）。预检通过后**正式请求仍走原有认证**；不改 prepareId / 取消协议本身。
- 前端发送真实失败 → 可理解原因、保留草稿与附件；不留永久「发送中」、不误报已发送。
- **验证口径（硬性）**：对开发来源（`http://localhost:1420`）与**三个既有 Tauri 来源**做含新头的预检 → 200；不可信来源 → 拒；未授权正式请求 → 拒。并且**必须有一条真实跨来源浏览器链路**：起前端+后端+假 provider → 选/传文件 → 就绪 → 点发送 → **POST 真到达后端** → 回执绑定正确 → `read_attachment` 读到内容 → 回答完成。**不得**用 Node/httpx 直 POST、同源代理、禁 CORS 或路由 mock 代替。
- r7 报告里「带附件发送 no-request」必须**重新定位**：本轮根因是这一条（CORS 预检阻断），不得再当装置问题结案。

### §1.2 问题二：中止必须指向本次取消确认返回的 turn_id（A）

- `already_started` 回执里的 `turn_id` 就是**要停止的目标**；覆盖：准备中 / 已入队 / 运行中 / 已结束。
- **身份缺失或无法确认 → 明确说明**，**不得静默退回** `stopActiveTurn()`；普通「停止当前任务」按钮语义不变。
- 文案依事实：取消请求发出 ≠ 已停止；失败不宣称成功；**已执行的轮次不得说「没有发送」**；已完成轮次如实说明当前状态。
- 竞态：取消确认 vs 发送回执/SSE 先后、重复点击、页面切换、另一轮并行运行 —— 取消只影响所选轮次。
- **验收**：组件测试**断言精确取消目标 ID**，并断言**另一运行任务没收到取消**；后端实机构造「A 运行、B 已入队但发送回执未到前端」的时序，在界面中止 B → **B 取消、A 继续运行、B 不得随后开始执行**；覆盖 B 已运行 / 已完成 / 取消失败 / 身份缺失；核对请求目标、台账、事件与提示一致。**禁止**只断言「某个停止入口被调用过」。

### §1.3 问题三：兼容路径的固定附件集合 + 整体拒绝（B）

- 进入本次兼容发送时**明确并固定**本次应携带的附件集合（进入时枚举一次，等待期间**不重新枚举**）；该集合内任一附件在等待期间**失败 / 取消 / 删除 / 超时 / 不可读 / 被其他轮占用** → **结构化拒绝整轮**（rejected 带准确 id、人话原因、可用操作），**绝不静默缺附件执行**。
- **复用显式路径的校验与拒绝契约**（同一份就绪判据 / 原因 / code），两套规则不得漂移；被拒后**不调用模型/工具、无 TURN_START、不留部分绑定**；草稿可重试。
- 集合政策：**只针对「进入本次请求时本话题未绑定的附件」**（进入时枚举快照）；**不**把历史失败记录变成阻断纯文字发送的条件；**显式 `attachment_ids: []` 仍表示不带附件**。
- 保持：有界 + 事件驱动等待、不复制第二份、不阻塞事件循环、DB 只在既定线程。
- **验收**：兼容路径分别覆盖**等待期间失败 / 取消 / 删除 / 超时 / 不可读 / 归属变化** → 结构化拒绝、模型/工具 **0 次**、**无 TURN_START**；多附件任一失败 → **整轮拒绝**且无半绑定，其它附件仍可正常重发；首次准备成功后正常执行 + 显式列表 + 显式空列表 + 重试 + resend 同时通过；**关键断言在磁盘闸门仍关闭时与失败事实发生后**。

### §1.4 问题四：暂存完整性按字节事实核对（C）

- `collect()` 核对**实际读回内容与成功写入的字节事实**：暂存**缺失 / 截短 / 异常增长 / 无效 UTF-8**（含**中文末字被截断**的多字节边界）→ **不得**当正常完整交付，**不得用 replacement 字符掩盖损坏**。
- 只交付能**确认**的内容，走既有不完整契约：可见事件（**存储损坏不得说成「正文超过上限」**）+ 轮次警告 + 最终结果一致；**不重新调用模型**；校准不得抹掉不完整事实；清理不得丢原因。
- **三个数字分开**：原生成字节数 / 成功保存字节数 / 实际交付字节数 —— 警告中的统计名称必须真实（**不得把「成功保存量」说成「完整生成量」**）；`BufferOutcome` 字段按此扩（冻结字段由 C 实现并报 Lead 备案）。
- 保持有界缓冲、工作线程 I/O、正常内容完整、真流式；**不扩大为存储架构重写**。
- **验收**：实文件截短/清空 → 真实 AgentLoop：交付长度与故障事实**准确**、可见警告存在、模型只 1 次、**无「完整」误报**；覆盖中文末字截断、异常文件长度、读取异常，原因不得混为硬上限；正常 ASCII/中文超 256 KiB 仍原样完整 0 警告；硬上限与创建/写入/读取失败原因保持；成功/故障/取消/断流收尾正确。
