## 启动不再白屏（已推送、本次一并打包）

- **系统命令有了硬超时**：读系统代理最多等 3 秒、更新前结束后端最多等 5 秒；
  超时就杀掉子进程并当作"没拿到"，不再被一个卡住的命令行工具把启动流程钉死。
- **后端没就绪时不再白屏**：窗口先显示"正在启动 QIO 后端…（已等 N 秒）"，
  等太久会说明原因、日志位置并给出重试；后端应答之后才渲染主界面。
- 启动各步骤的耗时写进日志（代理探测 / 内置模型 / 拉起后端 / 合计），下次慢能直接归因。

## 凭据：选厂商、填 Key、点「保存」

- **基础表单只有四件事**：服务厂商（可搜索）、API Key、用途、保存。用途默认就是
  「主对话」，要改再点「修改」。地址、连接协议、模型、显示名称、用量上限、自定义
  标签、内部标识都收进默认收起的「高级设置」。
- **选完厂商自动补齐**地址、协议、建议模型与显示名称；选「其他 / 自定义服务」
  会直接把必填项展开；取不到模型列表时可以手动填写模型名称。
- **不再有自动识别厂商**：以前它会把你粘贴的 Key 依次发给十几家服务去试探。
  现在厂商由你选，Key 前缀只用来在本地给你一句提示，验证请求只发给**你选定的那一个地址**。
- **「保存成功」与「验证通过」分开说**：
  - 保存且验证通过 →「已保存，模型可用」；
  - 保存成功但验证没过 →「已保存，尚未通过验证」，写明原因（Key 无效 / 没有该模型权限 /
    服务不可达 / 额度不足 …）并给出「重试验证」；
  - 写入失败 →「保存失败」，不会留下半条记录，也不会显示成功。
- **默认用哪把钥匙是明确的**：卡片上标出「当前默认」；第一条验证可用的主对话凭据会
  自动成为默认，之后新增的凭据不会悄悄顶替它，你可以用「设为默认」显式换。
  默认只影响选择的先后，**不会绕过**停用、撤销、用量上限、用途与验证状态。
- **没通过验证的凭据不会被自动拿去用**：它留在设置里等你重试，但不会被选进主对话，
  首次引导也不会因此判定"已经配置完成"。
- 「换钥」改叫「**更换 API Key**」：先验证新的 Key，再在原记录上原子替换 ——
  验证或写入失败时，原来的凭据照常可用，不需要"新建一条再手动撤销旧的"。
- 凭据卡默认只给结论（名称/厂商、模型、中文用途、当前默认、启用状态、验证状态），
  地址、内部标识、版本与审计记录收在「详情」里；用量按 **token** 显示（不再显示成钱）。
- 文案说清楚：在 QIO 里停用、撤销或删除凭据，**不会**吊销厂商账户里的 API Key。

## 首次引导

- 「连接模型」这一步与设置页的凭据弹窗**是同一个表单**：默认值、校验与提示语不再有
  第二套实现，两处行为一致。
- 这一步只有一个主按钮：该保存时它是「保存」，保存并验证通过后自动进入下一步；
  已经有可用凭据、你也没在填新的时它就是「下一步」，此时不再重复出现「跳过」。
- 同一个表单里如果已经写入过，后续保存一律作用在那条记录上：Key 没变 = 只重试验证，
  Key 变了 = 原子替换，不会因为"改掉打错的 Key 再点一次保存"多出一条凭据。

## 老数据兼容

- 数据库只在末尾追加了一条迁移。**已有凭据不会被标成"未验证"或停用**：
  它们按既有行为继续可用，其中第一条可用的主对话凭据会记为默认项。
- 已经撤销、停用、过期的凭据保持原样；专项用途（看图、研究等）的路由与回退规则不变。

## 已知限制

- 预设里的"建议模型"只是推荐值。它是否真的能用，以保存后那次实际调用为准；
  没有可靠默认模型的服务（第三方转发、自定义服务）会要求你自己选一个模型。
- 用量上限按 token 计量并与实际的用量口径一致，但运行期仍未按调用累计用量，
  所以"已用量"这条进度在真实使用中基本保持在 0。
- 真实凭据的读写只在 Windows 凭据管理器上验证过；无可用凭据库的环境里，读路径
  会如实报告"没有可用凭据"，写路径会直接报错而不是假装成功。
- 历史凭据的验证状态记为"按老行为可用"，不会自动重验；想重新确认就点「重新验证」。
