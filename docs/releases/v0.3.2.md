# QIO v0.3.2

本版在 0.3.1 之后重写窗口框架：**20px CSS 圆角窗口 + 亮暗阴影 + 三模式（css/dwm/native）+ 原生 overlay 命中 + poll 穿透 + 全窗浮层/视口适配**。
0.3.1 及更早版本的功能与修复继续适用。

- 集成规格（唯一规格源）：`docs/qio-window-frame-integration-032.md`
- 安装与运行：`docs/SETUP.md`
- 已知限制见文末

## 一、窗口框架（默认 css 模式）

- 窗口改为**程序化创建**（`tauri.conf.json` 的 `app.windows: []`，由 `main.rs` setup 用 `WebviewWindowBuilder` 建窗）：
  透明窗 + 无系统装饰 + 页面加载完成后再 `show()`（有界兜底 2s），避免启动白闪。
- **20px CSS 圆角** + 28px 留白带 + 亮/暗两套 soft·A 阴影（新增 `--window-radius`、`--window-frame-pad`、
  `--window-shadow`、`--window-frame-inset` 令牌；实底从 `body` 移到 `.window-frame__surface`）。
- 最大化/贴靠时留白、圆角、阴影归零（`html[data-window-state]`），由壳的 `qio://window-state` 驱动。
- **三模式**：`QIO_WINDOW_FRAME=css`（默认）/ `dwm`（0.3.1 等价：系统圆角 + 去边框，不透明、无留白、无 overlay/poll）/
  `native`（完整系统窗框）。Windows build < 22000 自动强制 `native`（无系统圆角时不启用 css）。
- **回退**：css 初始化任一步失败（builder / transparent / DWM / WebView2）→ 记录结构化失败原因 →
  销毁已建窗口并以 `native` 重建（同一进程不能改透明属性）；`QIO_WINDOW_TEST_FAIL_CSS=1` 仅测试用。

## 二、原生 overlay 命中与 poll 穿透

- **overlay 子窗**（类名 `QioWindowOverlay`）：标题栏 HTCAPTION 拖动/双击、最大化按钮 HTMAXBUTTON、
  八方向缩放环；`interactive` 洞（设置入口 / 权限模式 / 全局异常入口 / 互动挂载点）从 titlebar 中挖掉，
  保持 DOM 可点；press 期间 defer 重排，每次 sync 重新压到 WebView2 之上。
- **poll 穿透**：css 模式默认开启（`QIO_PASSTHROUGH=poll`，8ms 轮询）。光标在可见圆角内容区之外
  （阴影带/圆角外）时给主窗与 WebView2 子窗加 `WS_EX_TRANSPARENT|WS_EX_LAYERED`
  （`SetLayeredWindowAttributes(0,255,LWA_ALPHA)` 保持视觉不透明），回到内容区立即撤掉；
  `QIO_PASSTHROUGH=none` 可关闭。最小化 / 托盘隐藏 / 拖动缩放期间强制交互；
  退出与主窗销毁时 `stop_poll` + `destroy overlay`（补齐 spike 缺失的清理点）。
- `forward_click` 本版**不接**（保留扩展点）：poll 是唯一已验证的穿透路径。

## 三、窗口状态、事件与命令契约

- 事件：`qio://window-state`（state/zone/rect/workArea/dpi/scaleFactor/padding/radius/frame/passthrough/titlebar）、
  `qio://caption-hover`（overlay 覆盖最大化按钮期间的 hover 回传）、`qio://frame-ready`（运行时配置）。
- 命令：`qio_set_hit_regions` / `qio_get_window_frame` / `qio_window_action` / `qio_set_passthrough`
  （最后一个仅供验收/诊断，产品 UI 不暴露）；像素一律物理像素。
- 关闭协议（ask/tray/quit、ACK 兜底、托盘显示/隐藏、所有权 lease）**零改动**。

## 四、浮层与视口适配（菜单越界修复）

- 11 处全窗 `fixed` 层统一内缩 `var(--window-frame-inset)` 并加圆角：弹窗/确认遮罩、统一审批、引导向导、
  关闭确认、维护撤销、互动影响确认、星球页/启动占位、全局提示层等；native/dwm 下 inset=0，行为同 0.3.1。
- 12 处 `innerWidth/innerHeight` 改为**内容视口**（统一 `utils/windowFrame.ts`）：锚点菜单/提示/浮层按内容区
  clamp，修复留白带内菜单越界/被裁切；三态（normal/snapped/maximized）定位与裁切逐层核对。
- 最大化按钮 hover 由 `qio://caption-hover` 补齐（overlay 覆盖后 DOM hover 失效）；native 模式隐藏 DOM 窗口按钮。
- 最小窗口 800×600 内容仍可用。

## 五、稳定性与工程

- 两份冲突契约测试改写为**双模式守卫**（`design-guards.test.ts`、`window-outline-native.test.ts`）；
  新增全窗层 inset 守卫与 viewport 守卫，防止后续改动把留白/裁切改回去。
- 关闭协议、所有权判定、卸载契约、更新链路均不变；卸载帮助程序仍按 lease 所有权收进程。
- 日志可观测：启动记录 mode/passthrough/pad/radius/dpi/build；overlay sync 数量、passthrough 每次切换
  （reason/exStyle before→after/子窗数）、css 回退原因；`QIO_WINDOW_EVIDENCE=1` 时写 window-frame 证据 jsonl。

## 七、升级与安装

- 已安装 0.3.1 及更早版本的 Windows 用户：应用内「检查更新」会下载本版，校验更新签名后安装；
  用户数据与设置保留，数据库按既有迁移前进，二次启动幂等。
- 全新安装：运行 `QIO_0.3.2_x64-setup.exe`；卸载默认保留用户数据，可在卸载向导中显式选择删除应用数据。
  系统要求见 `docs/SETUP.md`。
- 回退开关（无需重装）：`QIO_WINDOW_FRAME=dwm`（0.3.1 等价外观）/ `native`（系统窗框）；
  `QIO_PASSTHROUGH=none`（关闭 poll 穿透）。

## 八、已知限制

- 本机仅 Win11 25H2 Build 26200、单屏 200%：Win10（build < 22000，自动 native）、混合 DPI 双屏、RDP 未验证。
- overlay 命中精度：本机以真实光标逐点扫描复核（等安静桌面）；若出现 1px 偏移如实记录并附证据。
- `dwm` 模式的 DWM 边框颜色读回不可靠（仅影响验收读回值，不影响视觉）；三种模式的最终外观以真机截图为准。
- `forward_click` 不接；poll 是唯一已验证穿透路径；透明窗 + poll 下 3D 星球/动画性能仅真机观察。
- 安装包未做 Windows Authenticode 代码签名（与既往版本一致）。
- `release_gate.py` 只做签名结构 / key id 核对（不做密码学验签）；本轮额外用内嵌公钥做 Ed25519 真实验签。
- 更新加速节点是第三方服务、可能再次失效；如 `latest.json` 下载失败可直接从 GitHub Release 下载安装包。
- 真实厂商模型调用成功路径、返回质量与浏览器端到端界面核对不保证覆盖全部环境；自动化验证以 fake/mock provider 为主。
- 更多历史限制与未验证边界见 `docs/status.md`。
