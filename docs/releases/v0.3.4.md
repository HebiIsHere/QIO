# QIO v0.3.4

本版是 0.3.3 之后的修复版：修正互动板首屏加载回归、大文件上传收尾超时，并新增 **Command Code / OpenCode** 两家可选厂商（区分套餐与 API 调用）。
0.3.3 及更早版本的功能与修复继续适用；窗口框架（0.3.2 的 20px 自绘圆角、三模式、poll 穿透）不变。

- 安装与运行：`docs/SETUP.md`
- 逐里程碑记录与边界：`docs/status.md`
- 已知限制见文末

## 一、互动板首屏加载修复

- 首次加载时，服务端可能把默认板面 id 规范化为真实 id（例如 `board_default` → `board_t`）。旧代码把这次规范化误判成「切板」，导致首屏的任务清单、意图视图、恢复入口、提交区批量入口都不出现。
- 本版在板面读取落定后沿用服务端给出的有效 id，继续读取可见范围 / 任务清单 / 意图视图；切板保护逻辑保持不变（只有真正切走才会丢弃旧响应）。
- 新增 store 级回归用例，锁死「首屏任务不能丢、清单读取必须落地成功」。

## 二、大文件上传收尾超时修复

- 浏览器上传（≤ 100 MB）在收尾阶段要等工作线程完成落盘与 sha256。旧实现中，**正常上传**与**取消/关闭**共用 5 秒收尾等待上限：慢盘或杀软扫描下，接近 100 MB 的文件「拷贝 + 哈希」超过 5 秒会被误判成「磁盘调用没有返回」，返回 500 且不保存数据。
- 本版把两条路径分开：正常上传按最大上传体积给出 **30 秒**收尾预算；取消/关闭仍保持 **5 秒**短超时（防止卡死在不可中断调用上无限等待）。
- 收尾超时后的清理与「迟到结果不得提交 ready」等既有契约不变。

## 三、凭据厂商：Command Code / OpenCode

新增两家可选厂商，并按「套餐（订阅额度）」与「API 调用（按量计费）」拆成独立选项，避免拿订阅 Key 往按量地址发：

- **Command Code（套餐）**：`https://api.commandcode.ai/provider/v1`，GOAT / Pro / Max / Team 套餐的 API Key 计入套餐用量；**Go 套餐不含 API 访问**。
- **Command Code（API 调用）**：同一地址，Provider 按量套餐按实际调用计费。
- 两者都支持 Claude 系列模型：在「高级设置 → 连接协议」选择 **Anthropic** 即可（同一 base）。
- **OpenCode Go（套餐）**：`https://opencode.ai/inference/go/openai/v1`，Go / Go Plus / Go Teams 订阅含固定月额度。
- **OpenCode（API 调用）**：`https://opencode.ai/inference/openai/v1`，Console 充值按量计费；免费模型仅 OpenCode 客户端可用。

预设只给默认地址/模型；「能否调用、额度多少」仍由保存后的一次真实请求与服务端账单决定。

## 四、工程与 CI

- Windows-only 的 `window_frame` 窗口层做了 `#[cfg(windows)]` 隔离，非 Windows 只建普通主窗口；Linux `cargo check` 不再因 Win32 API 失败（不影响 Windows 安装版行为）。
- v0.3.3 的后台 CI 回归（首屏板面规范化、windowFramePlacement 陈旧断言、Linux 编译）已修复。
- 发布前完整 CI 已全绿：10/10 job 通过（frontend / backend py3.11、py3.12、windows / rust windows、ubuntu / install e2e / docs / frozen worker 等）。

## 五、升级与安装

- 已安装 0.3.1 / 0.3.2 / 0.3.3 的 Windows 用户：应用内「检查更新」下载本版，校验更新签名后安装；用户数据、设置与数据库迁移保留，二次启动幂等。
- 全新安装：运行 `QIO_0.3.4_x64-setup.exe`；卸载默认保留用户数据，可在卸载向导中显式选择删除应用数据。
- 回退开关（0.3.2 起，无需重装）：`QIO_WINDOW_FRAME=dwm` / `native`；`QIO_PASSTHROUGH=none`。

## 六、验证与发布

- 发布闸门 `scripts/release_gate.py`：安装包/哈希/latest.json/更新签名 key id/NSIS 载荷/sidecar 新鲜度/内置模型/构建 manifest 等逐项 PASS（结果写入 `docs/releases/release-history.jsonl`）。
- 受测提交、安装包 SHA256 与逐项闸门结果以 `docs/releases/release-history.jsonl` 为准；本说明不写会过期的计数。
- CI：完整矩阵在发布提交上全绿（run 记录见 GitHub Actions）。

## 七、已知限制

- 跨 Windows 账号 / 登录会话的「只唤醒 / 提示后退出」仍 **UNVERIFIED**（单账号开发机无法制造第二会话）。
- 真实签名更新链路端到端（latest.json 下载 → minisign 校验 → 自动安装）未在本轮完整跑；覆盖升级与更新重启交接用「真实 IPC + 原生覆盖安装 + 新版二进制」验证。
- 0.3.2 窗口框架的真机外观/DPI/穿透矩阵（Win10、混合 DPI 双屏、RDP、真实光标拖拽）沿用 0.3.2 口径，其余 **UNVERIFIED**。
- Windows Authenticode 代码签名未做（与既往版本一致；更新签名与 Authenticode 是两件事）。
- 真实厂商模型调用成功路径与返回质量不保证覆盖全部环境；自动化验证以 fake/mock provider 为主。
- OpenCode Go 建议的 `x-opencode-session` 会话头 QIO 未发送；第三方客户端可用，但配额/路由统计以服务端为准。
- 更多历史限制与未验证边界见 `docs/status.md`。
