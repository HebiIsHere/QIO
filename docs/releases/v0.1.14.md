# QIO 0.1.14

## 放弃开发：不会再出现「界面上没了、重启又回来」

- **保存失败不再报告「已放弃」**。以前写盘失败被吞掉、`abandon()` 改完内存就返回成功：用户看到条目消失，
  重启后任务又回来了。现在放弃走严格路径（同目录临时文件 → `flush`/`fsync` → 原子 `os.replace` → 回读校验），
  任何一步失败都如实返回 `persist_failed`，内存回滚到与磁盘一致，并说清「任务还没有被放弃，可以重试」；
  已经收回的那部分长期授权会如实告知 —— 不假装成功，也不假装什么都没发生。
- **放弃时一并作废挂着的凭据授权确认卡**。以前 `credential_grant` 审批没有任务标识，任务放弃了卡片却还挂着。
  现在放弃会同时作废测试执行 / 工具创建 / 凭据授权三类未决审批：卡片与待审批入口**立即消失，不需要刷新**，
  作废后的旧审批再点「允许」不会被受理。
- 放弃仍是**终态且不可逆**：不删除工作区文件、不删除数据库记录、不删除已注册的工具。
- 边界如实记：`can_stop` 依旧为 `False` —— 当前架构没有「只停这一个任务」的能力，界面不提供假选项。

## 启动、更新与后台计算期间：窗口不再被挡住

- **外壳**：`qio_prepare_for_update`、`qio_refresh_updater_proxy` 以前是同步命令，会在主线程上做系统命令等待、
  DNS、多地址连接尝试与进程结束等待，这段时间窗口拖不动。现在两条都是异步命令 + 后台线程执行；
  启动阶段只做日志插件与状态注册，代理探测、模型准备、拉起后端都在后台任务里完成。
  启动的依赖顺序没有被打乱：仍然是**拉起后端 → 指派任务对象 → 写归属记录**，写失败仍然让启动停下（fail-closed）。
- **后端**：话题预判与后台整理按「只读输入 → 执行器里算 → 回到循环提交」重组，提交前校验取消与代次。
  真实测量（真实模型 + 真实 uvicorn + 真实 HTTP，在阻塞窗口里并发打探针）：

  | 请求 | 修复前在事件循环上 | 修复后 |
  | --- | --- | --- |
  | `GET /api/health` | 228.7 ms | 6.7 ms |
  | `POST /api/turns/cancel` | 228.0 ms | 5.0 ms |
  | `GET /api/events` 建立连接 | 227.9 ms | 5.0 ms |

- **前端**：完整历史与更早分页在成功 / 失败 / 收尾三处都校验归属（请求代次 + 发起时的话题 + 分页票据），
  慢的旧结果不会把话题改回去、旧分页不会串进新话题；写操作（发送、审批、工具执行、设置）**永不自动重试** ——
  超时只说明没等到响应，操作可能已经生效；读操作可以有限重试一次。事件同步缓冲有明确上限，
  溢出会标记「需要重新同步」并重拉权威快照，不再静默丢事件还宣称同步成功。

## 「回到最新消息」按钮：贴到输入区上方，滚动收口

- 按钮位置按**真实元素边界**计算：下缘距输入区面板上缘 10px，水平对齐对话内容列中心；
  不再被「消息区底边」抬高（修复前实测高出约 148px）。
- 空着的底部内容块不再写无效内边距；输入区尺寸只量一次，三处共用，不再各挂一个观察器。
- 滚动相关的异步回调都有归属与句柄：切话题或卸载后不再改位置，用户一操作就作废「恢复阅读位置」。

## 多实例共享资源的两处修复

- **模型文件同步**：改为「唯一临时名 → 校验临时文件 → 同目录原子 `rename`」，`.ready` 最后发布；
  快路径要求指纹一致**且**逐个文件校验通过。失败或中断不会留下假的 `.ready`，过期临时文件会被清理。
- **所有权记录**：改为按实例区分 `sidecar.lease.<shell_pid>.json`，先退出的实例不再删掉后启动实例的记录；
  同一安装目录重复启动会识别并列出已有实例（不阻断合法的多实例），只清理外壳进程已不存在的死记录。

## 验收（实测，不是推断）

- 后端：`cd backend; uv run --frozen pytest` 全绿。
- 前端：`npm test` 全绿；`npx vue-tsc --noEmit` 通过；`cd frontend/src-tauri; cargo check` 通过。
- 文档：`python scripts/check_docs.py` 通过。
- 真实界面（隔离实例 + 真实浏览器 + 截图）：按钮只在上翻阅读时出现、点它才回到最新、按钮中心的命中元素就是按钮本身；
  宽窗口 / 窄窗口 / 多行输入下间距都是 10px；页面缩放 80% 与 125% 下同样是 10px。
- 受控验证（把实现换回旧版会让新用例变红，证明用例有判别力）：历史竞态、连接缓存与代次、事件缓冲上限、
  更新定时器与编排顺序、后端重活期间的健康探测 / 取消 / 事件流、模型同步与所有权记录。

## 已知限制（如实记）

- 真实 Windows **安装态**下的窗口拖动与缩放响应、真机端到端更新安装：**未跑**（NOT RUN）。
- 真实多实例并发（两个安装态外壳同时首启共享数据目录、同目录重复启动、掉电下的原子发布）：**未复现 / 未测**。
- 轮末与后台派生工作仍可能在事件循环上占住约 150ms；后台整理里不释放 GIL 的那一小段仍有约 17ms 停顿；
  后台整理一轮的总时长仍约 0.5 秒（工作量没变，只是不再压在事件循环上）。
- 停止后端「杀不掉的进程」分支、真实 VPN / 死代理场景没有构造条件，未测。
- 放弃的**掉电**场景只做如实声明（进程崩溃 / 被强杀安全；Windows 上无法 fsync 目录项，不宣称掉电安全），没有实测。
