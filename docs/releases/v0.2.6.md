# QIO v0.2.6

本版是**互动模式的一轮实机测试修复**：十个问题逐个定位并修好，
外加一轮界面解释文案的精简。在 0.2.5 基础上，0.2.3 / 0.2.4 / 0.2.5 的功能与已修复项继续适用
（见 `docs/releases/v0.2.5.md` 等）。

## 一、互动板面

- **操作提示只显示一次**：板面顶部那条手势提示改成「本机没用过查看手势时显示一次」，
  做一次平移 / 框选 / 缩放后写入本机标记，刷新不再出现。
- **卡片坐标夹在画布范围内**：拖动 / 新建 / 调整尺寸与**加载归一化**都走同一个 `clampCardRect`。
  修复前实测有卡片被拖到 `y = −63.84`，顶部落在滚动区外、被页眉遮住且拖不回来。
- **图片卡改为「以图为主」**：附件是可显示图片的材料卡用封面式呈现（图片作背景 + 压暗层 + 说明），
  非图片材料与文字卡不受影响。
- **文件与图片合并成同一种材料卡**：互动模式只有一种材料卡 `kind="file"`；
  遗留的 `kind="image"` 在加载归一化时迁移成 `file`（`meta.image` 搬到 `meta.file`，老键保留）。
  添加菜单只剩「文字注释 / 文件」；卡片类型标签按**附件类型**显示（图片 / PDF / 表格 / 文本 / 代码…）。
- **卡片坐标越界与页眉遮挡**见上；**星球不再为空槽画融合环**（环属于话题，不属于窗口槽位）。
- **板面 chrome 不再启动原生选择拖拽**：舞台默认 `user-select: none`，
  卡片正文 / 对话面板 / 输入框显式开回 `text`。修复前在提交区按住 Ctrl 拖到窗口底，
  板面视口 `scrollTop` 会从 0 跳到 811。

## 二、对话窗口与底部工具栏

- **短窗口下不再裁掉输入框**：对话窗口最小高度按实测拆解重算（`CHAT_FRAME_MIN.h` 220 → 260）。
- **窗口尺寸变化后能恢复**：把「用户设定的框」与「当前生效的框」分开，窗口临时变小只收敛生效框；
  放大回来从用户框重新推导（修复前 520 → 244 后停在 260）。
- **底部工具栏左对齐、内容宽度**：不再在「剩余空间里居中」并固定占一大块宽，
  右侧整块让给对话窗口；可用区只在**横向真的相交**时才让位，右下角不再留白。
- **窄窗口下工具栏不再被压塌**：宽度上限改用 `--im-toolbar-chat-reserve`
  （宽窗口按几何计划的聊天宽度、窄窗口按 `--im-chat-reserve`）。
  修复前 480 宽时上限只剩约 12px，提交区宽度变成 0、按钮互相压住（用户报的「详情压住查看过程」）。

## 三、界面文案精简（按用户逐项点名）

删除：添加菜单的入口说明与底部边界说明、板内搜索的两段说明、提交区失败块下方的红色保留说明、
提交区详情里除「本次有效改动」以外的全部说明、工具栏「操作说明」入口与浮层、
对话帮助里的板面手势段、对话流空态说明、卡片元信息层的许可与所在组说明、
任务浮层里「待审批…运行中」那段说明。

仍然成立、只是换了承载处的保证：失败原因与保留情况在折叠区之外就能看到；
卡片许可状态仍可在卡片上辨认（`card-license` 徽章）并在卡片工具栏里改；
旧阶段说明不与当前状态并列。

## 四、提交与许可

- **新建文字卡默认提交给 QIO**（可取消）：勾选框默认勾上，材料卡不受影响（它们默认就在允许范围内）。
- **提交区详情默认收起**：不再因为「要补充 / 理解失败」自动展开。

## 五、验证

- 前端：`npx vue-tsc --noEmit` 0 错误；`npm test` 全量通过（377 文件 / 3333 用例）。
- 后端：`uv run --frozen pytest` 全绿。
- 实机核对：每一处改动都在 Chrome 真机（1400×900 / 窄窗口）复现 → 修复 → 复验，
  截图保存在 `docs/verification-shots/` 与本地核对目录。
