# QIO v0.3.1

本版发布 0.3.0 之后积累的对话页 0.3.0 开发/一致性修复、统一话题判断与申请流程、话题系统结构整理
及复核补修 R1—R19。0.3.0 及更早版本的功能与已修复项继续适用。

- 完整交付与验证记录：`docs/status.md`（发布台账）、`docs/topic-review-20261110.md`、
  `docs/topic-unify-20261111.md`、`docs/topic-unify-r17-20261111.md`、
  `docs/topic-unify-r18-20261111.md`、`docs/topic-unify-r19-20261111.md`
- 安装与运行：`docs/SETUP.md`
- 已知限制见文末与 `docs/status.md`

## 一、对话页 0.3.0（七项 + 状态一致性）

- 任务栏与失败提示按结构化事实过滤：过程说明、单次工具失败、可恢复失败不再糊成「未完成」；
  当前/历史/计数/徽标/顶部通知同源，执行记录与消息详情原样保留。
- 「返回阅读位置」改为话题 + 轮次稳定身份 + 轮内锚点 + 文本片段 + 视口相对偏移，按真实布局
  逐帧有界校正；用户接管、切话题、卸载互相隔离；目标不在已加载范围时按分页有界寻找并说明。
- 「回到最新」并入输入区辅助入口行固定末尾，只改变阅读位置，不取消接续选择、不影响草稿。
- 过程区区分「本轮回复结束 / 某次调用失败 / 用户目标完成 / 等待审批」；知识提交缺证据时给
  可读结论；最终答复不虚构未发生的提交或审批。
- 普通对话不再每轮重复话题名、工具任务折叠行不重复来源；元信息与时间统一使用等宽令牌。
- 窗口圆角使用 Windows DWM 原生系统圆角偏好并去白边，不在网页容器伪装。
- 同时修复 17 项 UI 与状态一致性问题（任务归属、阅读恢复、知识提交、弹窗与预览、输入区居中等）。

## 二、统一话题判断与申请流程

- 相似度只作证据，本轮主模型是话题判断的唯一来源（延续 / 切换 / 新建 / 无法判断）；旧预测器
  不再发布可执行切换建议。
- 切换 / 新建走统一申请：确认前推进导航版本并做写入前 CAS；拒绝 / 取消在原话题回答且不标
  「用户停止」；关闭只收起；等待期可写草稿但该对话发送禁用；确认后草稿跟随。
- 分步事实与可恢复失败：上下文装配异常/超时不再回落旧上下文；回答阶段失败单独记录并可重试，
  不重跑已成功的工具、不重复写用户消息。
- 话题阶段门：决策 / 等待确认 / 执行 / 上下文准备期间不发布正式正文；`answerable` 后才允许
  正式回答，停止与失败语义不变。

## 三、话题系统结构整理（统一位置状态 / 导航命令身份 / 逻辑答案执行权）

- **完整位置状态**：新增单行表 `position_state` 与 `navigation_commands`；位置由既有权威存储
  同源读取，`PositionStateService.apply()` 成为唯一写入口，单事务完成身份/参数摘要、CAS、Anchor、
  接续、两类版本与命令结果；`nav_version` 只表达真实导航决定，`position_version` 表达任何真实
  位置状态变化。
- **导航命令身份**：request / operation / internal 三类身份；同身份同参重放零写入并返回既有结局，
  同身份异参 409 冲突零副作用，依据过期 409 stale，失效旧请求 409 inactive；命令结果持久化，
  跨重启不复活旧控制权。
- **逻辑答案执行权与共享暂存**：`topic_answer_runs` 按 `answer_key` 收口执行权；模型调用期间
  心跳续租、不持写事务；生成成功保存失败时正文进入按 `answer_key` 共享的暂存，任意同 key 恢复
  记录只补存不重新生成；旧执行者迟到写一律 superseded 且零写入。前端 `acceptPositionState` 整份
  接受位置状态（旧/冲突不合并并触发权威恢复），业务代码不再直接写 Anchor。

## 四、复核补修 R1—R19

- **轮次受理依据链**：`TurnManager.submit/reserve` 受理时冻结归属/接续/两类版本；轮首补锚、
  内部落位、轮末推进、边界/容量分段全部以依据链 CAS，不再临时读最新版本洗白旧动作。排队轮次
  期间用户新导航后，旧轮位置写入被拒（零副作用零广播），回答仍按受理归属写回原话题/片段；
  普通发送、重发、互动板提交都冻结同一份受理快照。
- **取消与导航原子性**：取消接续必须携带目标身份，取消 A 不会隐式取消 B；所有带位置的取消响应
  先整份接受再更新，「返回开放片段 / 进入话题最新」一次点击只发一个导航命令，失败整份回滚。
- **普通正式回答统一答案身份**：普通保存与恢复入口共用 `answer_key`；唯一答案复用、同事务收口
  恢复记录/执行行；保存失败同事务写共享暂存 + 待恢复记录，既有「重试回答」入口可补存（只补一条、
  不再调模型、不重复写原问题），保存成功后用 `RECOVERY_INBOX_CHANGED` 事件通知前端刷新「未完成
  事项」清单（在途请求合并为完成后补拉，无需刷新页面）。
- **互动板提交归属**：提交受理时冻结受理依据；无当前位置时按既有兜底只读解析默认话题并冻结，
  不改写当前位置；排队期间用户切走后旧轮仍把问题与回答写入受理话题，位置保持用户新导航。

## 五、稳定性与工程

- 完整后端测试提速：模板数据库 + 受控并行/串行分组 + 唯一入口 JUnit 台账；长尾用例单独分组，
  并行组与串行组并集 = 全量、交集为空。
- 测试重复审计与合并、文档一致性检查（路径/命令/里程碑/硬编码数字）、第三方声明生成与检查、

- 修复工具导航 related 边恢复、快照导航版本断言、双连接并发测试等待顺序等稳定性问题。

## 六、验证与发布

- 发布前完整 CI 矩阵（backend py3.11/py3.12/windows、frontend、rust、frozen-worker、install-e2e、
  docs）在发布候选提交上执行；结果、受测 SHA、安装包校验与发布闸门结果见 `docs/status.md`

## 七、升级与安装

- 已安装 0.3.0 及更早版本的 Windows 用户：应用内「检查更新」会下载本版，校验更新签名后安装；
  用户数据与设置保留，数据库按既有迁移前进，二次启动幂等。
- 全新安装：运行 `QIO_0.3.1_x64-setup.exe`；卸载默认保留用户数据，可在卸载向导中显式选择删除
  应用数据。系统要求见 `docs/SETUP.md`。

## 八、已知限制

- 真实厂商模型调用成功路径、返回质量与浏览器端到端界面核对不保证覆盖全部环境；自动化验证
  以 fake/mock provider 与真实 HTTP 接线为主。
- 外部模型调用不保证严格 exactly-once；已保证同一逻辑答案唯一持久化与已暂存正文只补存。
- 受限子进程不是安全沙箱；工具扩大能力必须重新审批。
- 更多历史限制与未验证边界见 `docs/status.md`。
