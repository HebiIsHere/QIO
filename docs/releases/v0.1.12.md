# QIO 0.1.12

## 多份安装并存时，卸载不再误杀别人的后台

- 卸载器不再按**可执行文件名**（`qio-backend.exe`）找进程。安装目录里新增**所有权记录**
  `sidecar.lease.json`：外壳启动时写下自己与后端的 pid + 进程创建时间（100ns FILETIME）+
  映像路径，三者同时匹配才认（PID 复用会被创建时间挡掉）；外壳退出时删除。
- 新增 `qio-uninstall-helper.exe`（与主程序共用同一份判定实现）：先只读判定，再只收**本安装实例**
  的进程树。判定不了就什么都不动（退出码 3），**绝不**回退成按名字杀。
- 安装/卸载模板里那处「按名字杀 `qio.exe`」的检查（壳一死，它的 Job Object 会带走自己那份后端，
  但会误伤另一份安装）在构建期被替换成所有权守卫，并带**编译期门禁**：补丁没打上就编译失败。

## 安装包自带 Python 运行时，依赖型工具不再要求你另装 Python

- 安装包内置 CPython 3.11 运行时（`python-runtime`，33.9MB），外壳通过 `QIO_BUNDLED_PYTHON_DIR`
  交给后端；工具环境用**包内**解释器创建。CI 上已证明：屏蔽系统 Python 后，用包内运行时建出环境、
  装好依赖、并真的调用依赖型工具拿到正确版本（`pyvenv.cfg` 的 `home` 指向安装目录）。
- **首次使用需要联网**下载依赖（pip 从 PyPI 取包）；不需要你自己装 Python，也不是离线开箱可用。

## 顺带修掉的几个真问题（都是实测出来的）

- **日志通道在安装态完全不可用**：插件默认 targets 里的 `LogDir` 初始化失败会把整个插件拖死
  （`拒绝访问 (os error 5)`），`qio.log` 一个字都没有。改为显式替换默认 targets 并三级兜底
  （数据目录文件 → 插件默认日志目录 → 控制台）。
- **归属记录写不下时不再留下无归属的后台**：留明确原因（`qio-startup-error.txt`，首行稳定标记
  `QIO-LEASE-WRITE-FAILED`）→ 收掉本次启动的后台 → 退出码 1。
- **卸载不再残留 `python-runtime`**：venv 与工具用的都是包内解释器，import 时生成的 `__pycache__`
  会让「只删登记文件 + 非递归 `RMDir`」的卸载器留下整个目录。给所有 python 子进程钉
  `PYTHONDONTWRITEBYTECODE=1`（根治），并在卸载钩子里兜底清理该目录。

## 验收（真桌面 + CI）

- 安装后完整使用过程四步全过：① 归属记录内容与独立枚举的实际进程逐项一致；② 正常退出后记录被清理；
  ③ 保持运行直接卸载：本次安装的进程被结束、安装目录清空、用户数据逐字节不变、其它安装与诱饵进程不受影响；
  ④ 记录写失败时留明确原因并收掉后台。
- CI：backend 全平台、rust 双平台、frozen worker、frontend、docs、install e2e（含无系统 Python 的
  依赖链验收）全绿。

## 已知限制（如实记）

- 依赖型工具**首次**安装依赖需要联网；离线场景不可用。
- 容器（Docker）工具环境路径本轮**未覆盖**：CI runner 自带 Windows 容器模式的 Docker，
  产品 `auto` 会选容器路径并失败（`python:3.11-slim` 无匹配 manifest）；宿主路径已验收。
- 桌面/E2E 验证必须把被测程序放在**工作区之外的干净目录**：放在带沙箱 ACL 的目录（低完整性标签）下，
  WebView2 宿主进程起不来，会得到"界面静默消失"的假象（本轮踩过，见 `docs/status.md` 与 E2E §17.8）。
