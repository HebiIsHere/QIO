# QIO v0.1.5

修「应用内更新时安装被中止」的根因：后端进程残留导致 `qio-backend.exe` 被占用。

## 症状（v0.1.4 实测）

更新/覆盖安装时 NSIS 报：

```
Installation Aborted
Can't write: D:\QIO\qio-backend.exe
```

其它文件都写成功了，只有后端这一个文件写不进去 —— 目录里同时存在 4 个残留的
`qio-backend` 进程把它锁住了。

## 原因

后端是 PyInstaller 单文件程序，它自己会再起一个子进程跑真正的服务。壳退出时只结束了父进程，
**子进程活了下来**；而安装器要覆盖的正是这个被占用的文件，于是中止安装。

## 修法

应用内更新在下载完成、交给安装器之前，先调用壳的新命令 `qio_prepare_for_update`：
用 `taskkill /T /F` 结束后端**整棵进程树**，再让安装器动手。装完重启时后端会被重新拉起。

失败提示也补了一句人话：「若安装被中止（例如 Can't write ...qio-backend.exe）：完全退出 QIO 后重试安装。」

## 校验

```
SHA256(QIO_0.1.5_x64-setup.exe) = __SHA256__
```

## 已知限制（如实列出）

* **手动**双击安装包时（不是应用内更新），残留的后端进程仍会挡住安装 —— 这一步还没做
  "自动清理"（下一步：让后端自己监测父进程，父死子退）。遇到时先完全退出 QIO 再装；
* 安装包仍未做 Authenticode 签名；更新源仍是 GitHub Releases（网络不稳时用
  `%APPDATA%\qio\updater-proxy.txt` 配代理）；
* 不做差分更新与回滚。
