# QIO v0.2.3

这一版修掉「附了图、模型却拿不到画面」这条真实故障，并把窗口的系统页眉去掉、换成自绘标题条。

## 会话模式：附上的图片真的交给模型

真实故障（0.2.2 桌面端）：对话模式附一张 `.jpeg`，模型只收到「附加了文件」与元数据，如实回答
看不到画面。根因四处，缺一处都修不好：

- 媒体候选按 `classify_media_kind` 判定，而它按设计只认音视频 → 图片候选为空；
- `_media_candidate_entry` 没有图片分支，非音频会落到视频抽帧；
- 交付事实里没有 `image_delivered`；
- 主循环能消费 `ImagePart`，但对话路径没有生产者。

现在图片走自己的分支交付真实字节，视频显式走抽样、其余如实记 unreadable。边界不变：
对话轮**不**按 vision 标签切换链路（策略仍是主循环优先），「已交付」也不等于模型一定看懂。

## 媒体类型按真实文件名判断

线上那张 65KB `.jpeg` 暴露的第二个坑：展示标签只留 24 字符，长文件名（QIO 副本名 = 哈希_原名）
被截断成「…」，扩展名跟着丢 → 图片被判「无法确认媒体类型」而拒绝交付（音频/视频只是被通配类型
兜底救了）。现在类型判断用候选里的**真实 name**，展示文本仍用截断后的 shown；两条回归钉住它。

## 读不到就说出原因，不再静默丢弃

两处同类缺口，表现都是「模型既没有字节、也没有一句说明」：

- 引用型大文件（100MB+）：`content_target` 对非 copy 必然报错，而收集器 `except: continue`；
- 附件 state 非 ready（复现：绑定 turn 后删掉副本）：候选直接为 0。

现在两种情况都带原因继续走交付判定，产出带原因的 `image_unsupported`（音视频同理），
契约补 unreadable 行。**已知未覆盖**：候选池截断（limit=50）与前端未知 source 的渲染，已写进 P38。

## 互动板面：文件卡里的图片不再被假理由挡掉

板面用「文件」入口加一张 `.jpeg` 时走的是 `mode==image` 老分支：硬编码「当前模型链路没有视觉能力」
且从不读字节 —— 链路有视觉能力时理由是假的，用户也拿不到画面。修法两处必须同时改
（否则会出现「标了已交付却没有内容块」的假账）：图片交付事实拆成共用核心 `_image_fact`，
vision 能力一路传到文件卡分支；`resolve_images` 也接受 `kind=file` 的卡片
（`_deliverable_image` 只认可交付图片类型，docx/pdf 天然返回 None）。

## 无边框窗口与自绘标题条

- 窗口不再有系统标题栏（页眉）：`decorations: false`，保留阴影与 Win11 圆角。
- 新增自绘标题条：满宽拖拽面（双击由 Tauri 内置逻辑转最大化/还原）+ 右上角最小化/最大化/关闭。
  按钮**只在桌面壳里渲染** —— 浏览器预览里画了也点不动，那正是要避免的「看起来能用」。
- `capabilities` 补五个窗口权限（拖拽 / 最小化 / 最大化 / 关闭 / 读最大化状态）：少一个按钮就
  静默失灵，所以契约测试逐个点名。
- 条高只有一个来源（`--titlebar-height`），`App.vue` 用它让出顶部那一条；原本贴顶的提示条
  （待确认审批 / 没执行的操作 / 开发任务）、设置齿轮、设置页 toast、星球页「收起星球」与两条
  顶部状态条都跟着下移一个条高 —— 否则它们会落在标题条下面，变成「看得见、点不到」。

## 已知限制（不粉饰）

- 「已交付模型」不等于「模型理解正确」，本版不在该结论上做任何承诺。
- 对话轮的链路选择仍以主循环优先，不按 vision 标签切换；链路不支持图片时给的是带原因的
  unsupported 说明，而不是画面。
- 候选池截断（limit=50）与前端未知 source 的渲染仍未覆盖（P38 已记）。
- Windows 11 的「贴靠布局」面板（悬停最大化按钮弹出的那个）拿不到：它由系统画在原生最大化按钮上。
  拖拽只在结构上核对（`data-tauri-drag-region` 在位、权限与另外四个同批生效），没有用系统级合成鼠标实测。
- 自绘标题条上没有原生标题栏右键那份系统菜单；标题文字也不再由系统显示。
- 真实模型 API 的联网验收不在自动化范围内；媒体交付的协议形状、降级路径与交付事实由 fake/mock provider 覆盖。
