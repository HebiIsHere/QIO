# QIO v0.2.7

本版是**互动模式的一轮界面收敛与回归修复**：按用户逐项点名的要求把卡片表面收干净、
把 .md 文件卡改成真正解析、修掉尺寸把手向西 / 向北拉不动的问题，
并修回一处自己引入的回归（图片卡封面消失）。0.2.3 – 0.2.6 的功能与已修复项继续适用。

## 一、卡片表面收敛（按用户要求）

- **文字卡编辑态只剩「格式工具栏 + 输入框」**：输入框吃满整张卡片
  （`TextCardEditor` 新增 `fill` 档：`flex: 1 1 0%` + 自己滚动；非 fill 的独立用法行为不变）。
  删除 markdown 语法说明与「输入过程只保存草稿」两段常驻文字。
- **完成编辑 = 退出选中 / 再点一次编辑按钮**：工具栏的编辑按钮在编辑态变成「完成编辑」；
  点板面空白或点别的卡片同样收尾。**没有真实改动时不产生板面变更**；
  未决冲突仍保留选择入口，退出编辑不替用户做选择。
- **文件卡（非图片附件）只显示文件名**：「待补充文件说明」输入框、附件信息行、卡片内预览、
  完成 / 取消按钮行全部移出卡片；「完成编辑 / 重新关联附件 / 查看」收进卡片工具栏，
  「查看」走既有 `openAttachment`，结果如实写在工具栏状态行（打不开就说打不开）。
- **块渲染里的换行**：段落 / 引用块内的换行渲染成 `<br />`（此前被 HTML 折叠成一行）。

## 二、图片卡封面回归修复

- **封面判定不再看 `kind`**：互动板已不再创建 `kind="image"` 的卡片
  （`ADDABLE_CARD_KINDS = ["text", "file"]`，图片一律作为附件挂在**文件卡**上），
  上一版按 `kind === "image"` 判封面，结果**所有图片卡（含微信图片）的封面一起消失**。
  现在按「附件是不是能安全渲染的图片」判定：图片卡与「附件是图片」的文件卡照旧铺封面，
  非图片的文件卡仍只显示文件名。已加回归守卫测试。

## 三、尺寸把手：向西 / 向北拉不动

- **根因是循环依赖**：`BoardCanvas` 的 `planCards` 调 `displayRect`，
  而 `displayRect` 的槽位来自 `layoutPlan` —— 成环之后槽位恒慢一帧，
  西 / 北把手的**预览框位置**取到上一帧的槽位：向左拉时左边界不动、右边界反而向右
  （向上拉时下边界向下）。提交本身一直是对的，错的只有拖动过程中的预览。
- **修法**：`planCards` 只认这一帧的实时值（拖动坐标 / 尺寸预览框），不再回调 `displayRect`。
  真实浏览器实测：西把手 −60px → 左边界 −60、右边界 0；北把手 −60px → 上边界 −60、下边界 0。

## 四、Markdown 文件卡做解析

- `.md / .markdown` 附件不再按纯文本逐行显示，改为渲染成正文（标题 / 列表 / 引用 / 表格 /
  代码块 / 行内格式）。后端分类与载荷未改（仍按 `code` 类别给文本行）：
  `previewPlan.rendererFor` 按扩展名分到新的 `markdown` 渲染器，
  `renderers/markdown.ts` 复用 `code` 的视图解析（只有一处实现），
  解析由 `MarkdownContent`（remark-gfm 管线、链接白名单、代码高亮）完成。

## 五、界面说明文案继续删除（按用户逐项点名）

- 卡片内预览顶部那条「结构化正文预览，不是原版面：按正文顺序给出段落、标题、列表与表格的文字」
  （docx / xlsx / pptx 三处一并删除），渲染器里的 `*_NOTICE` 常量与 `notice` 视图字段一并移除。
- 对话窗口输入框下方的帮助整块删除：「文字发送不会提交板面」摘要、
  「帮助：可见范围 · 板面手势 · 媒体读取 · 附件限制 · 快捷键」入口与展开正文，
  以及标题栏那个已经没有内容的「帮助」按钮。

## 六、验证

- 前端：`npx vue-tsc --noEmit` 0 错误；`npx vitest run` 全量通过（381 文件 / 3372 用例）。
- 后端：`uv run --frozen pytest` 全绿。
- 实机核对（Chrome，1440×900）：图片卡封面恢复、西 / 北把手按上表数据实测、
  `.md` 卡片预览解析出标题 / 列表、对话面板输入框下方不再有帮助条、文件卡工具栏为
  「完成编辑 / 重新关联附件 / 查看 / 折成标题 / 更多」。
