# QIO v0.2.8

本版把两条并行开发线合并发布，并第一次在**带更新签名**的路径上产出安装包：

- **底部功能栏布局重构**（第三十六轮）：修掉「窗口较窄或提交说明较长时，说明被挤成极窄竖列、
  功能栏异常增高、按钮与文字分布松散」。
- **图片展示简化**（第三十七轮）：图片不再是独立卡片类型，统一为**文件卡附件**，常态即完整展示。
- 0.2.3 – 0.2.7 的功能与已修复项继续适用。

## 一、底部功能栏布局重构

**根因（真实渲染 + 静态 CSS 链，不是照截图猜）**

- 功能栏的行列关系原先由**视口**媒体查询决定（`@media (max-width: 1080px)` 等）。
  功能栏的实际宽度由
  `max-width: min(--im-toolbar-max-width, 100% − --im-toolbar-chat-reserve − 两侧留白)` 决定，
  所以「窗口很宽、但聊天保留宽度把功能栏压到 764px」时两条断点都不触发，仍按宽档挤一行。
- 提交区的长说明正文同时具备 `flex: 1 1 18ch` + `min-width: 0` + `overflow-wrap: anywhere`
  （`anywhere` 参与固有尺寸计算，min-content 可降到「一个字」宽），而同一行的范围 / 状态是
  `white-space: nowrap`、操作组是 `flex: none` —— 唯一还能继续缩的就是正文。
- `.u-line → .submit-cluster → .tb-submit → .tb-main → .board-toolbar` 五层都没有高度上限，
  于是「正文被压成极窄竖列」与「整条功能栏被撑高」同时发生。
  改造前实测：764px 下功能栏 151px、1178px 下 106px；同一段说明在 1178px 下正文反而只有
  146px 宽（4 行），3 张卡时 80px 宽（6 行）。

**改法**

- **按功能栏自己的实际可用宽度分档**（而不是视口宽度）：新增 `frontend/src/interactive/toolbarLayout.ts`，
  宽带 / 中档 / 窄档三档 + 40px 滞回；可用宽度用两个隐形探测器实测（`--im-toolbar-chat-reserve`
  是 `min()` / `vw` 组合，取不到像素），`ResizeObserver` 观察舞台、功能栏自身与保留宽度探测器。
- **两行主栏**：`.tb-submit` 与 `.submit-cluster` 都是 `display: contents`，
  「编辑操作 / 上次提交 / 本次统计 / 说明区 / 操作组」各自声明 `grid-area`，
  每一档的行列关系写死在 CSS 里，不随内容长度随机排列；
  按状态出现的内容不在时用 `:has()` 收掉那一行（空的网格行仍会占一条 `row-gap`）。
- **长说明不再参与主栏横向分配**：「上次提交结果 / 本次提交范围与改动 / 上次提交过程」三类面板
  互斥展开（同一入口再点收起、Esc 收起），绝对定位在主栏上方、宽度 = 功能栏完整宽度、
  **不参与主栏高度**，限高且只有一层纵向滚动；三块数据分家，不互相串用。
- **视觉与可达**：撤销 / 重做改图标按钮（保留悬停提示与可访问名称、禁用态更清晰）；
  功能栏左侧与底部留白同源；主提交按钮仍是唯一强调色。

**改造后实测**（1600×900，独立端口 + 全新数据目录）

| 功能栏可用宽度 | 档位 | 功能栏 | 主栏 | 网格轨道 |
| --- | --- | --- | --- | --- |
| 764px | mid | 764×91 | 73px | 2 条（默认态，无空行） |
| 1178px | wide | 1178×91 | 73px | 2 条 |
| 520px | narrow | 520 | — | 提交操作组独占一行、右对齐 |

两档点开「详情」面板时功能栏矩形**完全不变**（面板宽 762 / 1176 = 功能栏完整宽度），
主栏与页面横向溢出均为 0。

## 二、图片展示简化

- **图片统一为文件卡附件**：`kind="image"` 从前端类型、卡片默认值、创建 / 展示 / 编辑 / 保存 /
  提交 / 状态分支里删除；卡片侧读附件只看 `meta.file`，不再回退 `meta.image`。
  添加菜单只剩「文字注释 / 文件」，附件是不是图片由文件本身决定
  （判定口径只有一处：`frontend/src/interactive/materials.ts` 的 `cardAttachmentIsImage`）。
- **常态即完整展示**：封面变体改成 `object-fit: contain`（留白走 `--bg-inset`），
  去掉上下大面积蒙版与重复说明，只留一行真实说明 + 「查看原图」；图片层不吃指针事件，
  卡片尺寸 / 位置仍由用户设置，不因图片加载或查看原图而重排。
- **图片不进卡片内阅读**：`toggleCardPreview` 在入口拒绝图片（不假成功），展开集合过滤图片，
  板面变化时只移除「已变成图片」的 id；图片文件卡不再渲染展开入口，`CardInlinePreview` 的图片分支删除
  （PDF / Office / 代码 / markdown 原样保留）。
- **「查看原图」复用既有 `openAttachment`**：不新增高清接口、不挂第二套查看器；
  解码失败 / 取字节失败 / 文件丢失 / 超限都在原图片区域显示真实原因并给出重试与重新关联入口。
- **后端同口径**：`CARD_KINDS` / `MATERIAL_KINDS` / 材料解析 / 预览路由只认 `meta.file`，
  无调用方的旧图片分支删除；**保留** `image_delivered` / `image_unsupported` 的视觉交付契约。

## 三、验证

- 前端：`npx vue-tsc --noEmit` 0 错误；`npx vitest run` 全量通过（386 文件 / 3434 用例）。
- 后端：`uv run --frozen pytest` 全绿。
- 真实渲染（Chrome，1600×900，独立端口与数据目录）：见上表与横向溢出 / 控制台错误 0 的结论；
  改造前的对照基线一并留档。
- 发布闸门：见 `docs/releases/release-history.jsonl` 中 v0.2.8 那一条（安装包 sha256、逐项结果）。
