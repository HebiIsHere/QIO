# QIO v0.1.2

加能力的一版：工具执行过程不再是系统模板提示，改由 QIO 自己决定**要不要说、说什么**，
审批窗口同时获得模型写的说明。工具、参数、风险、审批权限与安全边界都没有改变。

## 安装

1. 下载 `QIO_0.1.2_x64-setup.exe`（106.8MB）；
2. 运行安装包。若 Windows 弹出「已保护你的电脑」，点「更多信息 → 仍要运行」（当前未做代码签名）；
3. 首次启动会把内置模型复制到 `%APPDATA%\qio\models\bge-small-zh-v1.5\`（一次性，约 90MB）；
4. 打开「设置 → 凭据 → 新建凭据」，填入你自己的 API Key，即可开始对话。

**环境要求**：Windows 10/11 64 位。Win11 自带 WebView2；Win10 若缺少 WebView2，安装阶段会联网下载。
**不需要**：Python、Node、uv 或任何其它运行时（后端是打包好的单文件程序）。

## 这一版新增了什么

### 1. 执行叙事层（Execution Narrative）

以前工具执行时，对话流里只有一句系统模板「正在使用工具」，加上系统按工具名拼出来的卡片。
用户看不出这一轮在确认什么、为什么先读这三个文件。

现在模型可以在工具调用里带一个可选信封 `_qio`，自己决定：

* **silent**（默认）：什么都不说 —— 不写就没有任何提示；
* **announce**：说明下一步准备做什么；
* **progress**：更新阶段进展；
* **warning**：说明异常或限制；
* **result**：说明上一阶段结果。

提示描述的是**当前意图**（"我先确认审批请求从后端到前端的完整路径。"），而不是复述工具名。
一次工具批次最多一条叙事，连续的低价值读取要么合并成一句、要么整批保持安静。

### 2. 工具调用收进叙事抽屉（默认收起）

每行叙事就是一个抽屉头，右边写着里面是什么状态：`2 次调用 · 620ms` / `1 运行中` /
`1 失败` / `1 已取消`。**默认全部收起，只有你点开才展开** —— 工具卡、参数、耗时、
失败原因都还在，只是不再一屏摊开。

失败与取消**不会**因为收起而消失：折叠头会用危险色把异常如实标出来。

### 3. 审批窗口显示 QIO 的说明

审批单里多了一段带来源标记的「QIO 的说明」：为什么需要执行、准备做什么、可能影响什么。
系统生成的字段（想做什么 / 会访问什么 / 会改变什么 / 授权范围 / 高级详情）一个不变，
模型文案不能替换它们；模型这次没写说明时，审批与现在完全一样、照常可以批准或拒绝。

### 4. 恢复与去重

叙事先落库再广播：断线重连、页面刷新、历史翻页都按同一条 `narrative_id` 去重，
不会出现重复叙事或重复审批。刷新之后抽屉里是**系统生成的调用摘要**
（工具名 · 状态 · 耗时 · 失败原因），不是原始工具输出。

## 边界（重要）

这一版只让 QIO 控制「如何表达」，**没有**放宽任何安全边界：

* 工具、参数、目标、命令、风险等级、审批按钮与最终权限仍完全由系统决定；
* 模型文案不参与任何执行判断，也无法修改或隐藏真实操作信息；
* `silent` 只表示"不输出说明"，不会改变审批是否弹出、工具是否执行；
* 拒绝、超时、单次使用、摘要校验、取消语义与 v0.1.1 完全一致。

打包内容复核（对产出的 sidecar 与前端产物各跑了一次）：

* 包内后端 `GET /openapi.json` → `info.version = 0.1.2`，`GET /api/instance` 同样报 `0.1.2`；
* 包内后端能接受 `NARRATIVE` 事件类型（`POST /api/events/test?event_type=NARRATIVE` 返回
  `{"type":"NARRATIVE"}`），说明执行叙事层的事件已经在包里；
* 包内前端产物含叙事抽屉（`次调用` / `qio-narrative`），且**不再包含**旧的机械提示
  「正在使用工具」。

## 已知限制（如实列出）

- **工具卡不落库**：历史里抽屉打开看到的是系统生成的调用摘要，不是原始工具输出；
  只有实时轮次里能展开工具卡详情（沿用既有边界，这一版没有扩大）；
- **叙事在取消/失败的轮次里会留在历史中**（如实反映"说明过、没做完"）；
- 叙事是展示记录：计入片段摘要输入，但**不计入**片段容量，不会让记忆提前封存；
- 语义分段仍是观察项（与 v0.1.1 相同）；
- 进程重启后排队中的消息不会自动恢复（队列未持久化）；
- 安装包未做代码签名；也没做首启向导（首次配置需要自己进设置页填 Key）；
- 模型来源与许可证：`bge-small-zh-v1.5` 由 BAAI 发布（MIT），ONNX 转换版来自社区仓库 Xenova；
  安装目录下的 `LICENSE-BAAI-bge-small-zh-v1.5.txt` 与 `NOTICE.txt` 是完整声明。
