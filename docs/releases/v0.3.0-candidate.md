## 二、本版包含的已完成修复

本版候选是 0.2.10 之后的完整发布前修复链（第一至第五轮 + 第五轮补充），并按第六轮做 Windows
安装包与真实服务验证。各轮的事实来源与完整证据以对应文档为准。

### R1 模型可靠性（`docs/release-step1-model-reliability-20261029.md`）

- 同一凭据下不同模型连接不再相互关闭：adapter 缓存按 `(key_id, model)` 槽位管理，运行期不关闭
  可能仍在使用的连接（被顶替者进入有界暂留名单），退出时统一关闭，缓存与暂留均有上限。
- 并行后台派生工作改为任务上下文隔离：`contextvars` 替代共享实例可变状态；入口快照本批配置；
  第一次异步等待前冻结整批目标与不可用结果，准备连接期间改设置只影响下一批。
- 模型目录 / 用途候选与真实调用对连接可用性同源（状态、启用、验证、预算、密钥可读），
  新增 `credential_unverified` / `secret_missing` 原因；目录只读本地事实，不联网。
- 「日常对话」一次选择整体保存并显示真实生效目标：批量事务接口（任一失败全部回滚），
  目录用与运行时同一 `resolve_shared_target` 计算 `effective`。

### R2 UI 一致性（`docs/release-step2-ui-consistency-20261029.md`）

- 关闭行为按最新有效选择生效：真正写状态与同步桌面壳的位置领单调序号，旧响应一律忽略；
  壳同步串行化；连续切换 / 迟到响应 / 保存失败回退真实生效值。
- 没有实际作用的独立模型选择改为只读（`code` / `research` / `video` / `audio` / `embedding` /
  `custom:<tag>`），后端两个保存入口结构化 422 `usage_not_effective`；历史覆盖只读标注可清除。
- 候选按用途判断能力：`usage_usable` / `capability_state`（supported / missing / unknown /
  not_required），明确缺能力禁选，能力未知可选并标注。
- 互动意图执行显示为可读记录：服务端按真实记录派生状态、尝试时间线、逐项状态、结果入口；
  前端渲染为默认收起的「意图执行记录」，无真实完成证据不显示「已完成」；确认 / 恢复 / 重试后
  无需手动刷新即出现并按 TURN_END 更新终态。

### R3 设置可靠性（`docs/release-step3-settings-reliability-20261029.md`）

- 同一区域不同设置的保存互不取消（每个设置独立身份与回滚），迟到初始读取不覆盖较新编辑/保存值，
  失败反馈按设置保留，连续保存回滚到真实已保存值。
- 模型获取归属：前端按配置签名 + 请求身份丢弃旧响应；后端按配置指纹校验，旧配置结果不写库。
- 连接保存后的自动获取分别处理成功 / 空列表 / 业务失败 / 网络异常，并说清「列表 ≠ 验证通过」。
- Key 保存重试复用请求身份（同身份同内容幂等、同身份不同内容 409）；搜索结果给真实命中总数、
  分批查看更多、第 9 条与最后一条均可定位；输出速度分别维护最新选择与实际保存值。

## 四、已知限制与保留项

- 停止轮的部分正文服务端不落库（刷新重开只保留「已停止 + 原因 + 重试」终态）；重试以同一用户消息
  新建一轮，历史中该用户消息出现两次——均为既有语义，不是缺陷。
- 意图执行记录的出现依赖「历史读取 + 续作轮事件」，不是消息级订阅；更早分页中的记录重试不主动重读。
- 模型发现只 upsert 不删除，服务商不再返回的旧模型行作为历史保留；界面暂无独立的历史模型浏览入口。
- 模型级验证成功不会提升连接级 `verify_state`；目录 GET 会按连接读本地 keyring 判断密钥可读性。
- 搜索「查看更多」是本地分批展示，不是服务端分页。
- 受限子进程不是安全沙箱；工具扩大能力必须重新审批。
