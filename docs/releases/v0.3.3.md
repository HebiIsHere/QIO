# QIO v0.3.3

本版是 0.3.2 之后的第一个正式版：**0.3.2 的 20px 自绘圆角窗口框架全部保留**，并合入 PM-QIO032 五组集成（互动板、星球、记录/反馈、设置、外壳导航）与 #46 互动板第七至第十轮返修。
0.3.1 及更早版本的功能与修复继续适用。

- 安装与运行：`docs/SETUP.md`
- 逐里程碑记录与边界：`docs/status.md`
- 已知限制见文末

## 一、桌面壳：全机单实例与更新重启

- **全机单实例**：同一台 Windows 机器上只允许一个 QIO 活动实例（`Global\QIO.SingleInstance.v1`），与安装路径、Windows 账号、登录会话、是否提权、版本无关；第二次启动只**唤醒已有主窗口**，不再创建第二个主窗口或拉起第二套后端。
- **正式构建固定产品锁名**：测试用的锁名后缀与跨进程探针只在测试构建（debug）生效；release / 安装版即使继承了测试环境变量，也始终使用同一产品锁名、按正式实例启动。
- **更新重启交接**：更新安装前结束后端并退出旧外壳；新版二进制启动时等待旧实例退出后接任（handoff），不再出现两个实例互相抢锁或旧窗口残留。
- 删除跨标签页草稿同步标记：桌面单实例下不再需要「另一个标签页正在编辑」的同步提示，并清理遗留标记；同一板面的草稿仍按板面版本保存与恢复。

## 二、互动板（PM-QIO032 互动组）

- 卡片、画布、分组、连线与批量导入的完整编辑链路：导入批次、卡片归属板面、画布缩放/平移与操作手势、分组与连线的选择/删除/撤销。
- 任务、审批与执行记录联动：影响确认层、待办任务、执行进度与工具卡（失败原因 / 下一步）按任务身份展示，不串任务。
- 附件与代码预览：文件读取/上传回执只关联到已加载的原板面，跨板竞态不再把 B 的卡片或附件写进 A；预览标签只在确认同一回复时迁移。
- 搜索、书签与窄窗可用性：800×600 下任务/执行记录可滚动、关闭按钮保持可见且可命中，焦点回到触发入口；全窗浮层随窗口内容区适配，不越界、不被裁切。
- 保存、提交、撤回全程按**原板面**归属：切板不串预判、保存状态、错误、待确认与撤回；在途请求可接回原板继续，不必重新编辑。

## 三、互动板修复（#46 第七至第十轮）

- **保存归属**：影响预判、PUT、409 冲突恢复与重试都带发起时的板面、候选内容与服务端版本；B 的回执只改 B，切到 A 不出现 B 的保存失败/未保存标记。
- **草稿保护与清理**：草稿按板面版本保存；失败清理不丢服务端已保存内容；后台保存有上限，达到上限后保持停止，切板/重读不重启自动保存。
- **提交归属**：提交回读与刷新归发起提交的原板；提交回执丢失时按同一请求身份查证（不重复 POST）；查证成功后，**本次新任务归入本次提交，旧任务留在原批次**（按发起提交时的任务基线或服务端明确归属）。
- **撤回与重新核对**：撤回提示跟随原板；「重新核对服务器事实」记住发起时的板面与本次撤回身份，结果只更新对应操作；同一次撤回已被服务器事实确认后，迟到的失败不再把它说回等待/失败。
- **任务隔离与附件状态**：跨板只影响原板任务；附件尝试、读取失败与重试只在所属任务下展示。

## 四、记录 / 反馈 / 设置 / 星球 / 外壳（PM-QIO032 其余四组）

- **记录与反馈**（#12 / #57 / #68 / #69 / #91）：执行记录与工具卡可诊断（原因、下一步、原始记录），反馈入口与记录面板按记录身份工作，不再串记录。
- **设置**（#21–#90 与文案清理）：模型、外观、数据、快捷键等设置项逐项复核；对话框与选项状态保持一致，设置改动即时生效并有明确回执。
- **星球**（#29–#35）：星球页/记录/搜索的布局、空态与加载状态修复，搜索与记录之间的往返不丢状态。
- **外壳与导航**（#36–#79 与文案清理）：导航、窗口控制、关闭行为（ask / tray / quit）、预览往返与恢复；关闭协议与所有权判定保持既有行为。

## 五、升级与安装

- 已安装 0.3.1 / 0.3.2 的 Windows 用户：应用内「检查更新」会下载本版，校验更新签名后安装；用户数据与设置保留，数据库按既有迁移前进，二次启动幂等。
- 全新安装：运行 `QIO_0.3.3_x64-setup.exe`；卸载默认保留用户数据，可在卸载向导中显式选择删除应用数据。
- 回退开关（0.3.2 起，无需重装）：`QIO_WINDOW_FRAME=dwm`（0.3.1 等价外观）/ `native`（系统窗框）；`QIO_PASSTHROUGH=none`（关闭 poll 穿透）。

- 本地定向验证：互动板/保存/草稿/提交/撤回相关 vitest、`vue-tsc --noEmit`、Rust 单实例跨进程契约测试均通过（计数不写入发布说明，见 `docs/status.md` 第八至十轮与 release-history）。
- CI：run `43828778826`（push main）10 个 job 中 8 成功，失败 2 个：`rust (ubuntu-24.04)` 与 `frontend`。
  - `rust (ubuntu-24.04)`：Linux 上编译 Windows-only 的 `window_frame` / `single_instance` 代码，39 个错误（`windows_sys` 未解析、`WebviewWindow::hwnd()` 不存在、`WM_*` 匹配臂未绑定）。**与 v0.3.2 发布 run 的同一 job 失败相同，属既有问题**（Linux 壳不是支持目标，CI 仍在 Linux 跑 `cargo check`）。
  - `frontend`：5 个测试文件 / 12 条断言失败（633 文件中 628 通过）。其中 11 条集中在 4 个页面级验收文件，根因是 #46 第六轮提交 `f9e08133`（`fix(#46): 切板时的草稿/读取/确认/撤回/附件归属`）在 `load()` 引入的上下文守卫：首次加载从默认板面 `board_default` 开始，服务端把板面规范化为 `board_t` 后 `contextIsValid()` 判为切板而提前返回，`loadIntents(board_default)` 也因 `boardId` 已变而丢弃回执（`intentsLoadState` 停在 loading、`fetchIntentViews` 0 次），导致虚拟意图 / 恢复入口 / 批量入口 / 任务面板不出现。**这些文件在 v0.3.2 CI 中是通过的，属于本版合入的 #46 回归，不是 0.3.2 既有问题**。另 1 条是 `windowFramePlacement` 的陈旧断言（fixture 传了 `bottom: 224` 却按未传 `top/bottom` 期望 `top=30`，实现按 `224+6=230`），v0.3.2 CI 当时唯一失败就是它，属既有测试错误。
  - 结论：v0.3.3 已按用户要求发布；上述前端回归需在后续版本修复（修复方向：首次加载接受服务端板面 id 规范化并沿用有效 id 读取清单/视图；更正 windowFramePlacement 断言；Linux CI 对 Windows-only 模块加 `#[cfg(windows)]` 或调整 job）。
- 发布资产：GitHub Release v0.3.3 已上传 `QIO_0.3.3_x64-setup.exe` / `.sig` / `latest.json`；公开 latest.json 实测 HTTP 200、`version=0.3.3`，下载后与本地文件 SHA256 一致（下载 URL 走 `ghfast.top` 加速）。

## 七、已知限制

- 跨 Windows 账号 / 登录会话的「只唤醒 / 提示后退出」在单账号开发机上无法制造第二会话，**UNVERIFIED**（代码路径未改：同会话激活、异会话提示）。
- 真实签名更新源端到端（latest.json 下载 → minisign 校验 → 自动安装）未在本轮完整跑；覆盖升级与更新重启交接用「真实 IPC + 原生覆盖安装 + 新版二进制」验证。
- 0.3.2 窗口框架的真机外观/DPI/穿透矩阵（Win10、混合 DPI 双屏、RDP、真实光标拖拽）仍按 0.3.2 时的口径：本机只验证了 Win11 25H2 单屏 200%，其余 **UNVERIFIED**。
- Windows Authenticode 代码签名与既往版本一致：**未做**（更新签名与安装包 Authenticode 是两件事）。
- 真实厂商模型调用成功路径、返回质量与浏览器端到端界面核对不保证覆盖全部环境；自动化验证以 fake/mock provider 为主。
- poll 穿透是唯一已验证的穿透路径（`forward_click` 不接）；透明窗 + poll 下 3D 星球/动画性能仅真机观察。
- 更多历史限制与未验证边界见 `docs/status.md`。
