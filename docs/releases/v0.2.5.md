# QIO v0.2.5

本版做的是**互动空间结构与自由尺寸调整**：卡片与互动对话窗口都能自由调整大小，
消息和材料拿到主要阅读空间，说明与低频操作按需展开。
在 0.2.4 基础上，0.2.3 / 0.2.4 的功能与已修复项继续适用
（见 `docs/releases/v0.2.4.md` 与 `docs/releases/v0.2.3.md`）。

## 一、所有卡片与对话窗口都能自由调整尺寸

- **八向拖动**：四条边 + 四个角都能拉；右下角有一个克制的位置标记。
- **键盘可达**：宽 / 高各一对「− / ＋」按钮，是真正的 `<button>`，有可读的无障碍名称，
  永远在 Tab 顺序里（鼠标下淡出，键盘聚焦时显现）。
- **改的是容器宽高**，内容按新空间重新排版：正文自然换行、图片保留比例、
  代码只在代码区横向滚动。**没有**用整体 `transform: scale()` 冒充尺寸调整。
- **三层状态互相独立**：卡片容器尺寸、阅读展开（临时让位）、画布缩放 ——
  调整一张卡片不会改变其它卡片或聊天文字的大小。
- **最小 / 上限**：卡片最小 180×96（标题、主要操作、必要状态与内容区仍然可用）；
  可用区域不足时最小值向内收敛，不强行套用超过屏幕宽度的最小值。
- **跟手**：拖动过程直接跟随指针、不播动画；松手后的让位与收起沿用既有非线性缓动，
  并遵守「减少动画」设置。
- **取消即恢复**：指针取消 / Esc / 窗口失焦 / 组件卸载都会回到本次拖动前的状态，
  清掉监听，不留半完成状态。
- **持久化**：卡片常态尺寸写在板面状态里（刷新、重启、收起再打开都恢复）；
  对话窗口的位置与尺寸按**板面身份**保存在本机，恢复时按当前可用空间收敛，
  不会把窗口恢复到屏幕外。

## 二、尺寸调整只改变布局与查看

- 调整尺寸**不调用模型、不产生工作意图、不申请审批、不暂停任务、不改变许可**。
- 后端本来就按「意思」与「版面」分开判断：卡片的位置与大小不属于 `_card_meaning`，
  纯几何变化一律归入显示型（`layout_only`），因此不会形成一条待理解的材料改动。
- 展开中或被让位的卡片只提交宽高，**临时显示坐标绝不写回板面**；收起后回到常态位置。
- 尺寸调整**不会**触发重叠成组，也不改勾选 / 隐藏 / 删除 / 书签。

## 三、对话窗口精简

- 顶部只留：标题、一句聊天运行状态、尺寸调整、帮助、收起；中间是连续消息流；
  底部把附件、输入框、发送按钮组合为**一个输入区**。
- 「文字发送不会提交板面」是一句短提示；完整的可见范围说明、媒体读取方式、
  附件限制与快捷键放进**可打开的帮助**，不再有常驻的多块说明。
- 没有附件时不显示附件条；选定后才出现，多个附件有高度上限并能滚动查看，
  状态、失败原因、移除与重试仍然可达。
- 「回到最新」悬浮在消息区底部：不单独占一行、不盖住正在阅读的内容或输入框；
  用户上翻时不会被自动拉回。
- 窗口缩小时仍保留足够的消息阅读区（附件、帮助、错误、审批都不会把它压成一行）。

## 四、板面提交状态与审批

- 提交入口附近显示**本次当前状态**（正在理解 / 待审批 N 项 / 本次无需任务 / 已完成），
  完整过程在这个入口展开，不再长期固定占据聊天窗口底部。
- 当前状态只表示**最新**事实：理解有结论之后，受理时那句「正在理解」只进可展开历史，
  不会与「本次无需任务」并列显示。
- 待审批出现时，提交区的审批入口**无需展开详情**就能批准、拒绝、定位；
  1—3 项（不到批量门槛）同样可以直接处理。聊天收起时审批仍可访问。
- 失败 / 中断保留简短原因与适当操作，详细记录可展开；**不伪造进度、不自动重试、
  不扩大既有执行权限**。
- 状态与审批按板面 / 提交 / 请求身份归属：切换板面、取消、重试或迟到回执都不会
  把别的提交结果展示在当前提交下。

## 五、卡片内部结构与版面

- 四种状态清楚分开：常态（标题 + 简短内容或缩略图 + 必要状态 + 阅读入口）、
  阅读展开（正文 / 真实预览成为主体）、编辑（一个**连续**编辑区）、折叠（标题 + 必要状态）。
- 统一文字卡继续承载文字、标题、列表、引用、代码与链接，仍然是**一个**连续编辑区。
- 文件展开后，文件名与说明压缩到标题附近，主体是真实预览；
  不会在预览上方重复铺开文件摘要、缩略图和大段说明。
- 「折成标题 / 展开阅读 / 进入编辑 / 外部打开」四个动作有明确区分；
  没有可读材料时不显示虚假的文件预览入口。
- 常用操作在卡片附近；复制、隐藏、书签、整理（分组）与删除收进「更多」，能力一个不少。
- 未选中的文字卡也能看出「允许 QIO 查看 / 未允许查看」，整卡许可覆盖卡里的全部文字、
  代码与链接；提交成功、失败、超时、重复、恢复、重启或模式切换都**不会**自动取消许可。

## 六、卡片、分组与浮层统一布局

- 阅读展开是**临时显示布局**：保留常态位置与用户自定义尺寸，收起后恢复；
  用户在展开期间主动移动或调整过的状态不会被旧快照覆盖。
- 支持**多张卡片同时展开**，展开卡之间互相避让；被让位的卡片之间出现的新碰撞会继续化解。
- 卡片、组框、关系线使用**同一套显示坐标**：让位或调整尺寸后，组框仍准确包围成员，
  连线仍接到对应卡片；显示让位不改变真实分组、关系、成员顺序或任务材料范围。
- 计算可用空间时会扣除平移 / 滚动后的可视起点、缩放、自绘标题栏、底部工具栏、
  对话窗口与审批浮层，不是只看视口宽高。
- 空间不足时收敛阅读尺寸或采用可对照的排列，**不会**靠遮住其他卡片、
  把对象推到找不回的位置、或自动关闭用户已展开的材料来解决。
- 新卡片优先落在**当前可见范围的空白位置**，不再按固定四列与数量取模安排。
- 组头常态只显示组名、成员数与是否有序，成员管理与顺序操作按需展开。

## 七、验证

- 前端与后端全量测试、`vue-tsc` 类型检查、文档一致性检查、发布闸门（18 项）全部执行。
- **真实应用验收**：起后端 + 前端 dev server，用无头 Edge 驱动真实交互，覆盖常规桌面、
  1024×768、800×600、明暗主题与「减少动画」；验证内容包括拖动改尺寸、键盘 −/＋、
  刷新后恢复、对话窗口移动与尺寸持久化、两张卡同时展开、最小尺寸下内容可用、
  窗口缩到最小时消息阅读区仍在、自绘标题栏避让。截图在 `docs/verification-shots/irl/`，
  脚本是 `scripts/verify-irl-shots.mjs`。
- 另有一轮**独立复核**（不参与实现）逐条核对尺寸与任务语义分离、持续许可、状态身份、
  临时布局恢复、平移缩放后的展开位置与草稿保护，报告见工作区根目录的
  `_IRL-REVIEW-E-1/-2a/-2b/-3.md`。

## 已知限制

- 与 0.2.3 / 0.2.4 相同（含无边框窗口那几条），见 `docs/releases/v0.2.4.md`。
- 真实应用验收是在 Windows 无头 Edge + dev server 上完成的，
  **未在打包后的桌面窗口上复验**：自绘标题栏的真机高度、真实指针 / 触控事件、
  输入法组合跨「收起销毁 / 展开重建」都还没有实测。
- 临时显示布局（展开或被让位）里的西 / 北把手按左上角锚定；折叠卡片与部分
  `height: auto` 状态不摆把手。
- 对话窗口的位置与尺寸是本机偏好（按板面身份绑定），**不做跨设备同步**。
- 浮层让开在竖直方向用的是「最大高度矩形」，偏保守；
  审批与聊天过程的真实链路只做了结构与状态复核，没有跑假厂商端到端对话。
- 光标位置、滚动位置与附件归属在尺寸变化后的保持，未单独复现（草稿维度已验证）。
