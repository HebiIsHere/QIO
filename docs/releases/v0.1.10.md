## 用量：按「进 / 出」分开累计

0.1.9 的已知限制里有一条「已用量在真实使用中基本保持 0」，这条限制现在没有了。

- 每次**真实**模型调用都把返回的进 / 出 token 记到「这次用的是哪把钥匙」上；
  主对话、子 agent、后台维护（做梦分析 / 工具草稿）走同一份归因逻辑，不会出现
  「主循环记了、子任务没记」。
- 凭据卡上分开显示进 / 出 / 合计。预算闸门仍然只看合计。
- 两条刻意的取舍：归因不到凭据（拿不到 key_id）的调用**不记账**——宁少记、不记错；
  写库失败只记日志，不会打断正在进行的回答。
- 数据库只追加迁移（新增进 / 出两列），已有凭据不会因此被判定失效。

## 按「停止」是真的中断

- 以前按停止只是「不再等它」，模型请求还在跑、结果到了再丢掉；现在是当场中断
  正在等待的请求，单飞队列里的下一条消息立刻开始。
- turn 仍按 cancelled 语义正常收尾。
- 服务端是否立刻停止生成由供应商决定：「不再占用等待时间、不再堵住下一条消息」
  有保证，「不再产生费用」没有。

## 顺手修掉一个会静默丢结果的缺陷

系统通知（子任务完成等）如果在「这一轮最后一次 planning 之后」才到达，以前会被
静默丢掉，于是那个子任务的结果永远等不到。现在这一轮会把它交还给上层，变成自己的
一轮继续处理。

## 凭据：确认之前不再把已存 Key 发到新地址

- 编辑已有凭据、只改了服务地址时，界面以前会自动拿**原来保存的 Key** 去新地址取模型
  列表——既发生在点「保存」之前，也发生在勾「确认发送到新地址」之前。现在已存的 Key
  只回答「它自己那个地址」；地址或协议变了又没有新 Key，就直接不取，提示保存后再取。
- 后端同样硬挡了一道：请求的地址与这条凭据落库的地址不一致（忽略大小写与结尾斜杠）
  就不解密、不外发，返回空列表加说明。前端漏改也漏不出去。

## 记忆摘要：一项给多了不再让整条派生出局

真实故障：模型一次给了 79 个实体，pydantic 判成结构违规，整个派生任务失败——这个
片段于是没有摘要、没有检索记录、没有实体卡、没有知识条目。

- 校验前先在本地做「去空白 + 去重 + 保序 + 截断」，再交给 pydantic；校验只负责挡
  真正的结构错误。
- 数量上限同时写进提示词：让模型知道要收敛，截断是兜底而不是常态。

## 工具沙箱：装了 Docker Desktop 但没启动，不再全线失败

以前判断「能不能用容器」只查 `docker` 命令行在不在 PATH 里，于是「装过 Docker
Desktop、当时没启动」被当成容器隔离可用：每次工具调用都选 docker，再以
`docker exit code 125` 失败，而不是改走受限子进程。

- 「可用」= 命令行在 PATH 里**且**守护进程应答（能报出服务端版本）。
- 自动模式下只有「容器根本没起来」（`docker run` 退出码 125，或 docker 进程起不来）
  才改走受限子进程——那时工具代码一行都没执行过，不存在重复执行；退出码来自容器里的
  工具自己、或容器超时，都不回退。
- 回退不会降级安全等级：高风险能力（联网 / 文件 / 进程 / 凭据）在没有容器隔离时照旧
  拒绝执行，要跑必须经过显式批准的 Trusted。
- 显式指定用 docker 时不静默降级，会报「守护进程没有应答」而不是退出码 125。

## 开发与 CI（不影响用户可见行为）

- Windows 后端任务与 rust 单测任务进 CI：`#[cfg(windows)]` 的启动加固用例（系统命令
  硬超时、杀子进程）以前一次都没被执行过。
- 剪掉 `agent.tools` 与 `agent.core` 之间的循环导入边：后端测试文件现在可以单独跑，
  不再必须整包一起跑。
- 文档一致性检查恢复通过：`status.md` 里两条指向未入库评测产物的路径，改成不带路径
  的说法。

## 已知限制

- 用量按调用累计；供应商没返回用量字段、或这次调用归因不到凭据时，那一次不计入。
- 停止只保证不再占用等待时间；服务端是否立刻停止生成、是否立刻停止计费由供应商决定。
- 预设里的「建议模型」只是推荐值，是否真的能用以保存后那次实际调用为准。
- 真实凭据的读写只在 Windows 凭据管理器上验证过；无可用凭据库的环境里，读路径如实
  报告「没有可用凭据」，写路径直接报错而不是假装成功。
- 沙箱的受限子进程**不是**安全沙箱：它只强制「声明」，不强制文件系统与网络隔离。

## 升级说明

- 0.1.9 → 0.1.10 的数据库迁移在启动时自动执行，只新增列，不改动已有数据。
- 从 0.1.8 及更早升级上来的用户，凭据行为仍与 0.1.9 一致。
- 0.1.2 及更早版本仍需手动安装一次才能用应用内更新。
