# QIO v0.2.9

本版合并并发布**互动模式第三十八轮集中修复**：结果卡真正解析 Markdown、卡片正式几何成为唯一权威、
统一的新建落点与尺寸约束、结果卡在用户许可后可继续参与协作、同一提交批次内新对象可被引用、
以及要求实际排列时排序真的改变卡片位置。

- 0.2.3 – 0.2.8 的功能与已修复项继续适用。
- 契约：`docs/interactive-mode-contract.md` **§17**（明确取代 §1.4 的 reply 行、§15.1 / §15.2 的临时槽位口径
  与 §15.6 的相关已知限制）；实现说明见 `docs/status.md` 的 **P66**。

## 一、结果卡真正显示 Markdown（P66 / F3）

- 结果卡（`kind="reply"`）的正文本体改走既有的 `frontend/src/components/MarkdownContent.vue`
  （**不**另写简化解析器）：标题、加粗、斜体、删除线、普通与有序列表、**任务列表**、引用、链接、
  行内代码、代码块与表格都按 Markdown 渲染；编辑与「复制原文」拿到完整原文，代码复制保留代码原文。
- 卡片正文仍是**唯一**纵向阅读区域：表格不超出正文两侧，代码 / 长链接 / 长单词不撑宽卡片，
  不引入横向滚动；安全口径不变（沿用 `markdownPipeline` 转义 + `isSafeExternalUrl` 白名单，
  不把模型原文当可信 HTML）。
- 结果撰写提示词明确允许用 Markdown 组织结果，程序负责解析。

## 二、卡片不再"自己动"（P66 / F1）

- `board.cards[].x/y/w/h` 成为卡片外框的**唯一**来源：`cardLayout.planExpandedLayout` 退化为恒等映射，
  删除展开时的原位放大、邻卡让位与**视野夹取**，以及 `BoardCanvas` 的会话内尺寸标记。
- 画布缩放 / 平移、窗口尺寸变化、聊天窗口 / 工具栏 / 审批浮层开合**只**影响查看方式与浮层自身布局，
  不再改变卡片坐标、尺寸、组成员与成员顺序，也不产生新的遮挡。
- 展开阅读只切换卡片**内部**内容呈现；卡片可以大于视野、可以部分在屏外，靠平移与缩放查看；
  只有用户明确点击「定位／完整查看」时视野才一次性调整（大卡只对齐左上角，不两边轮流对齐）。
- 拉伸保持固定边：东 / 南侧不动左上角，西 / 北侧保持对边；拖动与拉伸期间关闭位置与尺寸过渡，
  松手后的外框与最后一帧预览一致。

## 三、统一的落点与尺寸约束（P66 / F2、F7）

- 新增 `frontend/src/interactive/geometry.ts`：`resolvePlacement`（拉伸走 bounded —— 只把被拉伸的边停在
  邻卡边界 − 间距，**绝不移动别的卡片**；移动 / 新建走 free —— 确定性找附近空位）、
  `clampCardSize`（180×96 .. 1600×1200，**当前视野不是卡片上限**）、`placeRelative`。
- 后端新增 `backend/src/agent/interactive/placement.py` 统一新建落点与尺寸：默认尺寸按内容类型、
  显式坐标生效、冲突时确定性找空位、省略坐标时用 `place{relativeTo,side,gap}` 的相对摆放或冻结视图内的空白落点，
  **不再默认落到 (0,0)**，也不会静默变成 1×1；审批预览与执行共用同一份落点与尺寸。
- 用户界面「+添加」在可见区域挤满时，改为向右 / 下扩大搜索范围直到真正零重叠（新卡可能落在视野外，
  平移即可看到），不再直接压在既有卡上。

## 四、结果卡可以继续参与协作（P66 / F4）

- 结果卡有了整卡「允许 QIO 查看」许可：**默认关闭**（QIO 自己的产出不等于获得许可），
  用户主动打开后进入下一次提交；许可持续有效（提交成功不自动取消），隐藏 / 删除 / 手动取消立即退出范围。
- 提交交付**实际正文与来源**（`meta.reply` 的 intentId / understandingId / executionId 与更新时间），
  不再只给编号或任务标题；据此可以说「根据上次这张结论继续分析 / 整理清单 / 与新材料比较」。
- 后续成果仍新增为结果卡，不据此开放覆盖原卡正文；不自动再次提交、不自动派生任务、不绕过审批，
  也不把同一成果反复写入记忆。

## 五、同一批新对象可被后续操作引用（P66 / F5）

- 引入带类型、作用域受限的临时引用：`card:<symbol>` / `group:<symbol>`（裸符号按卡片）。
- 新增 / 成组操作可声明 `ref`，只能引用**同一意图内更早声明、类型正确**的符号；
  理解校验先收集声明再校验引用，拒绝不存在、重复、前向、自引用、跨意图、类型错误与未获准依赖。
- 正式对象 id 由服务端在批准计划时稳定分配：重复批准、刷新、暂停继续、重启恢复与重试都不会重复创建，
  审批预览与执行后暴露同一份「临时符号 → 正式对象」映射。

## 六、几何上下文与实际排列（P66 / F6、F8）

- 提交快照可带**冻结视图**（板面坐标下的可见区域与缩放），`build_context.geometry` 只覆盖本次获准范围，
  量不到时为 `null`（不编造）；纯缩放 / 平移 / 浮层变化不构成新意图、不调用模型。
- `order_group` 不带 `arrange` 时只改**逻辑顺序**，并明确说明；带 `arrange: "row" | "column"` 时
  真实写入成员 `x/y`（从左到右 / 从上到下一列），组框按既有口径更新。

## 七、验证

- 前端：`npx vue-tsc --noEmit` 0 错误；`npx vitest run` 全量通过。
- 后端：`uv run --frozen pytest` 全绿。
- 独立验收（无头 Chromium + 离线假厂商 API 闭环，不用真实模型凭据）：
  浏览器与 API 双侧的必转项（结果卡 Markdown、展开不推走邻卡、拉伸碰撞边界、新建落点、
  许可结果卡进入后续上下文、相对摆放、空间排序）均已 FAIL→PASS；
  验收发现的两条缺陷（边把手正中被连接点抢命中、新建卡压住既有卡）已修复并复验通过。
- 发布闸门：见 `docs/releases/release-history.jsonl` 中 v0.2.9 那一条（安装包 sha256 与逐项结果）。

## 九、已知限制

- 结果卡正文在前端没有展示层长度上限（因此没有前端截断标记）；后端上下文对结果卡正文有上限并带显式截断标记。
- 用户拖动落点仍走 `frontend/src/interactive/board.ts` 的既有下落策略（保留「拖到卡片上自动成组」语义）；
  `geometry.ts` 覆盖拉伸与新建落点，QIO 侧在服务端复用同口径。
- 矮卡（约 170px 高）的上边连接点圆点会落在卡头文字行附近（可点、可拖线，纯观感）。
- 未验证：批量新建卡；引用的未批准依赖、半途暂停继续、取消、失败撤回、重启恢复；纯逻辑排序的用户可见文案；
  桌面壳（Tauri）内复验。
