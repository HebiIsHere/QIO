# QIO 0.1.13

## 没做完的开发任务可以「放弃」了（终态不可逆）

- 「有 N 个工具开发任务没做完」清单里，每一行新增「放弃开发」：就地展开确认（不是浏览器原生弹窗），
  一次说清三件事 —— **结束这项开发并从未完成列表移除**、**工作区文件与记录保留、不删除已注册的工具**、
  **同时收回这个任务的执行授权、没回答的确认会失效**。确认文案会点名是哪一项任务。
- 放弃是**终态**：写入 `abandoned` / `abandoned_at`，阶段变为「已放弃」。此后任何写操作
  （改阶段、记测试结论、标提交、写文件、归档、发放/消费执行授权）对它**一律无效**，
  迟到的测试结果与迟到的提交请求都不能让它复活、也不能注册出工具。重启后仍然是已放弃。
- **正在执行时不允许放弃**：跑测试或提交的过程中点放弃，界面会如实说明「现在没有只停止这一个任务的能力，
  请先停止当前执行」，并且**不做任何状态改动**，也不会顺手停掉别的任务。
- **等审批时允许放弃**：未决的那条审批会被作废（库里结局记为 `cancelled`，不是「你拒绝了」），
  界面上的确认卡随之自己消失，后续执行不再发生、工具不会注册；已经作废的审批再点「允许」不会被受理。

## 未完成任务列表：30 项也滚得动、读得清

- 面板高度跟随窗口可用高度（视口相对值，不是固定像素），列表**内部**滚动；滚动列表**不会带动**背后的对话
  （含滚到列表底部后继续往下滚的边界情况）。
- 滚轮、触控板小步滚动、键盘（PageDown / End / 方向键）、**拖动滚动条**都能滚动；滚到底部时最后一项的
  按钮完整可见、可直接点击。
- 长需求文字（含连续无空格长串）在窄窗口下换行显示，不产生横向溢出；失败原因显示在**滚动区域之外**，
  滚到任何位置都看得见。移除最后一项后，面板收起、入口整行隐藏。

## 边界与诚实表述

- 「没有只停这一个任务的能力」是**真实能力**的如实描述：当前架构里开发任务跑在主 turn 的协程内，
  没有留下单个工具调用的取消句柄，所以界面不提供「已停止」这种假选项。
- 放弃**不删除**数据库记录、不删除工作区文件、不删除已注册的工具；要移除已注册的工具，仍走「撤销工具」那条路径。

## 验收（实测，不是推断）

- 后端：`uv run --frozen pytest` → **1901 passed / 0 failed / 3 skipped**。
- 前端：`npm test` → **87 个文件 / 843 条用例通过**；`npx vue-tsc --noEmit` 通过。
- 真实界面（隔离实例，1440×900 与 820×900 两视口）：**56 条检查 / 0 FAIL**，含滚动/键盘/拖动滚动条/
  背景不动/无横向溢出/最后一项可达/错误提示可见/放弃成功与重复点击只发一次请求/刷新与**重启后端进程**后不复活/
  审批卡在放弃后自己消失。24 张截图存 `frontend/e2e-shots/ui-catalog/dev-abandon/`。
- 三种难触发时序（真实进程 + 真实 HTTP + 强制退出）：执行中放弃与迟到结果、放弃与审批通过**真并发**（12 轮）、
  断电重启后任务与授权状态一致 —— **29 条 / 0 FAIL**。
- 独立验证方另有 33 条后端 + 16 条前端用例，在改动前是红的（证明用例有判别力）；
  详细结论见 `_lead-logs/verify-dev-abandon.md`。

## 已知限制（如实记）

- 依赖型工具与容器路径的限制沿用 0.1.12 的结论（见 `docs/releases/v0.1.12.md`）。
- 开发任务列表里显示的需求文字上限是 **200 字**（接口层截断），界面不再二次截断。
- 真实触控板/触屏手势、真实 OS 级输入路径本轮未覆盖（用滚轮小步滚动与 CDP 合成输入做等价验证）。
