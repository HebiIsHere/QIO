# QIO v0.1.1

修问题的一版：窗口尺寸相关的界面错位、星球入口球的三种失效（点不到 / 消失），
以及「本轮工具换话题后整轮归属不跟随」。功能与 v0.1.0 相同，建议直接覆盖安装。

## 安装

1. 下载 `QIO_0.1.1_x64-setup.exe`（106.8MB）；
2. 运行安装包。若 Windows 弹出「已保护你的电脑」，点「更多信息 → 仍要运行」（当前未做代码签名）；
3. 首次启动会把内置模型复制到 `%APPDATA%\qio\models\bge-small-zh-v1.5\`（一次性，约 90MB）；
4. 打开「设置 → 凭据 → 新建凭据」，填入你自己的 API Key，即可开始对话。

**环境要求**：Windows 10/11 64 位。Win11 自带 WebView2；Win10 若缺少 WebView2，安装阶段会联网下载。
**不需要**：Python、Node、uv 或任何其它运行时（后端是打包好的单文件程序）。

## 这一版修了什么

### 1. 中等宽度窗口下输入区错位（最明显的一条）

900–1400px 这段宽度里，输入气泡的位置是用 `calc(50% - 66px)` 手算的，漏掉了半个列宽：

| 窗口 | 修前：输入区相对消息列 | 修前：右边缘溢出 | 修后 |
| --- | --- | --- | --- |
| 1200×800（安装包默认） | 右移 418px | 溢出 194px（发送按钮出屏） | 0 / 0 |
| 1000×700 | 右移 410px | 溢出 266px | 0 / 0 |

改为消息流与输入区共用同一对列留白令牌：宽屏两侧 24px，≤1400px 时右侧让出 132px 的入口球通道。

### 2. 入口球点不到 / 消失（三种成因，全部修掉）

- **被输入气泡压住**：贴靠只避让「已贴靠的浮动组件」，而输入气泡（更上层、不透明）与冷启动停在
  右上角的设置齿轮都不在表内 —— 球停到它们底下就既看不见也点不到。现在这两者被显式声明为障碍；
  旧版本已经把球停在输入区底下的用户，升级后启动即自动挪出来。
- **离开对话页后被永久锁死**：星球开着（或正在长大）时切到设置页再回来，阶段状态会停在
  `ready`，入口球被置为「已交棒」（透明且不接收指针），既点不到也再也打不开。现在离开页面会把
  连续体收干净，并作废被打断的那次转场。
- **收起被打断后缩成一个点**：体量收缩的第一步按「整窗画布」算尺度；若随后球态接管而小球布局尚未
  落到 DOM，球会被乘成几个像素的点（看起来就是「消失了」）。现在球态会先确认画布已经落到
  `--ball-size` 再写尺度（最多重试 4 帧）。

### 3. 本轮工具换话题，整轮归属跟着走

v0.1.0 把「本轮归属」固定在轮前，副作用是模型自己调用 `create_topic` / `switch_topic` 时，
建话题那一轮仍留在上一个话题里（新话题的历史从第二轮才开始，追问看不到前提、检索也找不到）。
现在给**工具**导航开了一条受控例外：整轮（用户消息 + 回答）搬进新话题的开放片段；
**用户**自己的导航仍然一步不动，v0.1.0 的保证没有回退。

## 已知限制（如实列出）

- **语义分段仍是观察项**：容量与「明确开工指令」会实际分段，语义/嵌入相关的阶段判断只记录建议、
  默认不切分，也没有经过独立标注数据的校准；
- 进程重启后**排队中的消息**不会自动恢复（队列未持久化）；
- 旧数据里没有来源记录的片段只能作为「同话题背景」，不享受路径隔离；
- 安装包未做代码签名；也没做首启向导（首次配置需要自己进设置页填 Key，会给出提示与入口）；
- 模型来源与许可证：`bge-small-zh-v1.5` 由 BAAI 发布（MIT），ONNX 转换版来自社区仓库 Xenova；
  安装目录下的 `LICENSE-BAAI-bge-small-zh-v1.5.txt` 与 `NOTICE.txt` 是完整声明。
