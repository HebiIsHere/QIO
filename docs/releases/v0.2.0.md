# QIO 0.2.0

这一版的跨度比之前几版大：从 0.1.14 之后，main 上先后并入了「互动模式线」「流式回复与附件线」，
再加上一轮主线可靠性审计修复与两条线的整合。下面是**用户可见**的变化，以及如实标注的限制。

## 新功能：互动板面（可提交、可理解、可执行）

- **板面**：卡片（注释 / 文件 / 图片 / 代码 / 网址 / 回复）、分组与顺序、连线、可见范围选择、
  保存与提交，都是真实落库的；未勾选的注释与明确隐藏的卡片**不会**进入交给 QIO 的范围。
- **提交与受理是两件事**：提交成功后服务端会**明确回执**「已受理」并建立理解请求；
  受理与否、理解结果、任务执行是三种分开显示的状态，界面不会把「已受理」说成「已经理解」。
- **真实模型理解**：提交后 QIO 会**真的调用模型**理解本次表达，材料也**真的去读**（已保存附件的正文、
  网址正文等），并如实标注哪些没读到（例如只有文件名、图片当前链路没有视觉能力）。
  模型输出三种判定：提出意图 / 需要补充 / 无需开展任务——**不强制每次提交都生成任务**。
- **真实执行**：批准后 QIO 会真的执行板面操作（生成结果卡 / 文字卡、移动卡片、成组、排序、连线），
  只允许用户在互动模式里自己能做的操作子集；进度、暂停、继续、取消都作用于真实执行，结束会落结果卡。
- **提交身份稳定、结果可查证**：每次提交有一个稳定请求身份。如果回执在传输中丢了，
  QIO 会**按这个身份精确查证**，不会用「时间接近」「最近一条记录」去猜；查不到就如实说
  「结果未知」，并保留你的改动与勾选，**不会**自动重复提交。
  同一次提交重试不会重复创建提交、不会重复调用模型；同一个身份换了内容会被明确拒绝。

## 可靠性：主线审计修复 F01—F12

- **板面与草稿**：草稿改为逐键三态保存（未提到的键不动），两个窗口同时编辑不会互相覆盖；
  本地删除的组与关联不会被无关的服务器更新「复活」；已确认的服务器版本独立推进。
- **提交与读取分开**：提交明确成功之后，如果页面刷新失败，只会说「提交成功、页面刷新失败」并给
  只读的重试入口——**不会**把成功的提交改判成失败或未知（这是本轮整合中发现并修掉的真实缺口）。
- **未决发送**：发送快照不可变（原文 / 话题 / 显式附件 / 请求身份），未决台账持久保存、不做数量裁剪；
  **受理情况未知时不会把原文放回输入框**诱导你以新身份再发一次。
- **任务清单**：读取失败会保留最后一次成功的清单并标明「可能过期」，空白**不是**「没有任务」。
- **审批**：单项与批量审批都有防重复操作；数据可疑时先向服务端核验，核验不成就暂停、不用旧快照放行。
- **凭据验证**：验证结果绑定输入指纹；旧配置的迟到结果只记「历史结果」，不会改当前可用性与默认项。
- **记忆与关闭**：派生任务的写入与完成原子核验（不会被旧代派生覆盖新数据）；
  手动与周期维护纳入同一关闭流程；关闭时拒绝新任务、有界等待并如实报告是否真的结束。

## 串流、附件与界面

- 流式回复的失败与重试边界收口；附件上传/复制期间的界面卡顿修掉（后台线程做磁盘与哈希）。
- 事件同步有明确上限，溢出会标记「需要重新同步」并重拉权威快照，不静默丢事件。
- 「回到最新消息」按钮按真实元素边界定位；窄窗口、暗色主题与滚动相关的回归修复。

## 数据与兼容

- 数据库只**追加**迁移（本版新增互动板面、真实模型理解与执行、提交身份等对象；补偿入口同步）；
  历史迁移一字未改，历史数据与用户内容在升级中保留。
- 升级前建议**保存一份可恢复副本**（复制 `app.db` 与同目录的 WAL 文件）。
- 代码回退与数据回退是两件事：本版升级过的数据库**未经验证**不能假定能直接配合旧代码运行。

## 如实说明的限制（没有做完的部分）

- **真实模型的人工验收仍未完成**：本机没有可用且已授权的模型凭据，自动化证据全部来自
  fake/mock provider。也就是说「链路已接通并在模拟模型下验证」是真的，
  **「真实模型判断质量」没有在本版验收过**。
- 图片视觉理解未接入（当前模型链路没有视觉能力），界面与上下文都如实标注不支持。
- 引用型附件（没有副本、直接引用原文件）的读取路径没有专门用例覆盖。
- 迁移 39 之前的老提交记录没有提交身份，不参与幂等；对它们的历史查证会按「查不到」处理。
- 硬关机（未走关闭流程）留下的理解记录不会在重启时自动清扫，由重试或下一次关闭收敛。
