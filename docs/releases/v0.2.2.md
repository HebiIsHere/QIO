# QIO v0.2.2

这一版把「字符内容」收成一种卡片、把许可改成持续有效、让卡片本身能读真实文件，
并让两处聊天都能按实际多媒体内容回答。

## 统一文字卡：文字、链接、代码在同一张卡片里

- 三种字符卡片（文字注释 / 代码 / 网址）统一成**一种文字卡**。内容内部是块序列
  （普通文字 / 标题 / 列表 / 引用 / 代码 / 链接），但用户始终在**同一个连续编辑区**里操作：
  在文字里写字、插入链接、写一段代码、再回到上面的文字接着改 —— 光标、选择、撤销重做都不被打断。
- 工具栏对**选中文字或段落**设置格式（加粗 / 斜体 / 行内代码 / 删除线 / 标题 / 列表 / 引用 / 链接 / 代码块）。
- 代码保真：缩进、换行、行尾空白与语言信息逐字保留；卡片上显示语言并可复制。
- 链接嵌在正文里：显示地址、可编辑、可打开。
- 整张卡片共同保存、复制、移动、折叠、书签与建立关系；草稿恢复、保存失败与内容冲突沿用既有处理。
- 添加菜单里新建字符内容只需选「文字卡」；代码**文件**仍属于文件材料（只读预览），与卡内代码块不是一回事。

## 历史卡片逐张迁移

- 旧代码卡 → 文字卡里的一个代码块；旧网址卡 → 文字卡里的一个链接块；旧文字注释卡补齐块结构。
- **逐张迁移，绝不把历史上多个独立对象合成一张**；卡片身份、原文、语言、地址、位置、关系、分组、
  书签、草稿与任务引用全部保留。
- 可见范围保持原样：旧注释保留原许可（**未许可的注释迁移后仍然对模型不可见**）；
  原来默认在范围内的代码/网址映射为新卡的许可状态。
- 迁移幂等：重复启动不会反复写板面。

## 许可变成持续有效

- 一张文字卡只有一个**整卡许可**，覆盖其中的文字、链接与代码。
- **许可不会因为提交而自动取消**：提交成功、失败、重复回执、超时、受理结果未知、恢复、刷新、
  重启与模式切换都不会清除它；只有用户手动取消（或把卡片隐藏）才失效。
- 旧回执不可能把用户更晚的取消恢复成开启。
- 未许可的文字卡**整体不交付**给模型：其中的链接、代码与派生正文都不会绕过许可进入请求。
- 隐藏或删除的卡片仍然不进入提交范围 —— 隐藏不是「偷偷清许可」的替代手段。
- 提交用的仍是本次确定的材料版本与范围。

## 卡片内真实预览（图片 / Word / Excel / PowerPoint / PDF / 代码）

- 点卡片上的「展开预览」，**这张卡片本身**扩大阅读区域；「收起预览」收回。收起时仍显示文件名、
  类型、必要状态与缩略图。
- 图片按完整比例显示，可放大、缩小、适应。
- PDF **逐页**阅读，保留原页面外观（含图片与表格）。
- Word / Excel / PowerPoint 走结构化正文预览：段落/标题/列表/表格、工作表与单元格地址
  （公式与缓存值分开标注）、幻灯片文本与表格。**这是结构化预览，不是原版面渲染** —— 界面上写清楚了。
- 代码/文本文件保留缩进、行号与语言信息，**只读**（不执行代码）。
- 旧版 `.doc` / `.xls` / `.ppt` 不支持内嵌预览，界面如实说明并保留打开/下载入口。
- 多张卡片可以同时展开；附近卡片**临时让出**阅读空间，收起后恢复原布局。展开与让位只影响显示，
  **不写入板面内容、不产生关系或分组、不触发模型理解、不暂停任务**。
- 用户的摆放不会被恢复覆盖：展开期间手动移动过的卡片，收起后停在新的位置。
- 转换与渲染是异步的：不阻塞界面；切换附件、关闭卡片或取消时停止无用工作并释放资源，迟到结果不会写到别的卡片上。
- 保存了「原文件与预览的关联」「文件版本」与「可恢复的阅读位置」；源文件丢失、变化、损坏、加密或转换失败时给出真实状态与现有入口。
- **能预览和模型读到了是两件事**：打开预览不会触发模型分析，预览成功也不会被记成「QIO 已读懂正文」。

## 两处聊天都能读多媒体

- 对话模式的聊天，以及互动模式里的悬浮聊天，都可以在消息里附加图片、视频和音频，并按实际内容回答；
  两处共用同一套会话、附件与多媒体处理能力（悬浮聊天只发送当前消息与明确选定的附件）。
- 图片把**真实字节**交给有视觉能力的链路；音频在链路支持时交付真实音频，否则经派生转写得到文字
  （带**时段**与提供方）；视频在链路支持时交付真实视频，否则按**时间点抽样画面**并明确「不是逐帧」。
- 显式报告部分读取、抽样、转写与未能理解的部分：转写文字只代表实际得到的文字，**不代表**理解了语气、
  音乐与全部环境声音；抽样帧不代表读完整段视频。
- 判断依据是**本次真实使用的链路**：「接口能接受某种消息」不等于「所选模型一定能理解」。
- 上传、保存、准备、读取、模型回答的状态分别呈现；准备失败时保留用户输入与可重试入口。
- 真实材料会进入本轮回答**以及需要再次调用模型的后续步骤**，不会只在第一次理解时带上。

## 互动板面提交：本轮先完成图片

- 板面提交按提交时冻结的可见范围、材料身份与**版本**取图，交给有对应能力的模型；
  隐藏、删除、未许可的内容不会通过附件或派生结果绕过范围判断。
- 视频与音频本轮不在板面提交的理解范围内（界面如实说明），对话模式两处入口已支持。

## 预览与媒体的运行依赖（安装版不需要用户装任何东西）

- 接口转换、缓存与阅读位置：随安装包一起提供（后端 sidecar）。
- PDF 页面渲染在前端完成，随前端包一起提供。
- 音频抽取与视频抽样需要本机可用的转换程序：QIO 会依次查找 `QIO_FFMPEG` 环境变量、应用资源目录、
  PATH 上的 ffmpeg 与常见安装位置。**找不到时如实降级并说明原因**，不会假装完成了整段视频处理。
- 打包说明见 `docs/SETUP.md`。

## 已知限制（不粉饰）

- Word / Excel / PowerPoint 的卡片内预览是**结构化正文预览**，不是逐页原版面渲染；PDF 与图片保留原外观。
- 旧版 Office 格式（`.doc` / `.xls` / `.ppt`）不支持内嵌预览。
- 音频转写与视频抽样依赖可用的转换程序与所选链路的真实能力；缺失或不支持时只给出诚实结论。
- 「已交付模型」不等于「模型理解正确」，本轮不在该结论上做任何承诺。
- 真实模型 API 的联网验收不在自动化范围内；多媒体链路的协议形状、降级路径与交付事实由 fake/mock provider 覆盖。
