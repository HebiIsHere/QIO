# QIO v0.1.4

修 v0.1.3 更新功能的两个问题：**报错看不见真因**、**代理环境连不上更新源**。
功能层面没有其它变化。

## 安装

从 v0.1.3 起支持应用内更新：**设置 → 数据与维护 → 更新 → 检查更新**。
（v0.1.2 及更早的版本没有更新器，需要手动安装本版。）

## 这一版修了什么

### 1. 更新失败时显示真实原因

v0.1.3 里，无论"连不上""代理不对"还是"清单解析失败"，界面上都只写「网络不可达」——
因为 Tauri 更新插件把底层原因统一成了一句固定文案，而前端把这句话猜成了网络问题。

现在错误文案会**带上原始信息**，例如：

```
更新源请求失败：可能是网络或代理问题（原始信息：Could not fetch a valid release JSON from the remote）
```

### 2. 装上文件日志（关键的一条）

更新插件的真实失败原因写在 `log` 里，而 v0.1.3 没有装日志，所以它被丢掉了 ——
这才是"只能靠猜"的根源。现在日志写到：

```
%APPDATA%\qio\logs\qio.log
```

### 3. 支持代理

更新用的 HTTP 客户端 **不读 Windows 系统代理设置**，只认环境变量
（`HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`）。现在除了环境变量，还可以写一行文本：

```
%APPDATA%\qio\updater-proxy.txt        # 内容示例：http://127.0.0.1:17011
```

壳启动时把它注入环境变量，更新请求就会走这个代理；文件不存在时行为与之前一致。
（这条是给"系统代理开着、但应用直连被拦"的情况准备的。）

## 校验

```
SHA256(QIO_0.1.4_x64-setup.exe) = __SHA256__
```

## 已知限制

* 安装包仍未做 Authenticode 代码签名，安装时 Windows 可能提示「已保护你的电脑」；
* 代理目前只能通过环境变量或上面那个文本文件配置，设置页还没有可视化的代理输入框；
* 更新源是 GitHub Releases；网络对 GitHub 不稳时需要自行配代理；
* 不做差分更新（每次下载完整安装包，约 108MB）。
