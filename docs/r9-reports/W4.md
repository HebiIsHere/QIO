## 1. 已实现

### A. 权限模式 UI（只读 / 受限 / 完全无限制）
- 新增 frontend/src/services/security.ts：
  - GET /api/security/mode → {mode,label,legacy_value}；新接口 404 时**只读兼容**退回 GET /api/settings/computer 并做旧值映射展示（compat=true），**写路径不退回旧接口**。
  - PUT /api/security/mode 固定请求体 {mode, user_confirmed:true}；旧值/未知值在客户端直接拒绝；失败原样抛出 SecurityRequestError。
  - 旧值映射：default→restricted、plan→read_only、accept-edits→restricted、bypass→unrestricted。
  - 切换生效边界：permissionModeSwitchNote() 明确「新操作立即生效；已经开始的执行沿用开始时的权限」；收紧不自动批准等待中的审批，放宽也不自动通过/复活审批。
- 新增 frontend/src/stores/security.ts：常驻状态、App 启动后唯一一次恢复（App.vue boot 后 security.load()）、失败保留原值不假装已切换。
- 新增 components/security/PermissionModeSettings.vue：三模式选择、当前模式、旧值映射展示、收紧/放宽边界说明、失败原因、「只有你能修改」与「受限子进程不是安全沙箱」诚实说明；除 App 启动恢复外只有用户点击「重新读取」才请求。
- 新增 components/security/PermissionModeBadge.vue：输入区常驻徽标（Composer / ChatDock 均已接入），显示服务端恢复的模式；未读到显示「权限模式读取中…」（不冒充默认值）；点击进入设置「工具与权限」。
- SettingsView.vue 权限段替换为组件；旧四值下拉移除（旧值只作为映射事实展示，不再作为可写入口）。

### B. 附件入口（桌面真实路径 / 浏览器 / 剪贴板）
- src-tauri/src/attachment_picker.rs 新增 pick_attachment_source（返回 path/name/size，与既有 pick_attachment_file 共用 Win32 选择器实现）；**注册行需在 main.rs 的 generate_handler 补一行（main.rs 归 W5/Lead，本分支未改）**。前端 pickLocalSource() 在新命令未注册时自动回退旧命令，功能不阻断。
- services/attachments.ts：
  - prepareAttachment(path, {sourceKind:desktop_path|dropped_path, origin, userNote}) → POST /api/attachments 登记源引用（不复制、不移动、不改名）；不传 sourceKind 保持旧兼容语义。
  - registerSourceAttachment() 供桌面选择/拖放使用。
  - uploadAttachment(file,{sourceKind:browser_upload|clipboard_image,userNote}) → 原始字节 + X-QIO-Source-Kind 头；文案明确「已保存为工作区材料源文件（来源：浏览器上传）」；>100MB 只作为**上传大小限制**说明（不再包装成副本规则）。
  - relocateAttachment(id,path,{confirmedIdentity}) 带 confirmed_identity；setAttachmentMaterialEnabled() 走 PATCH /api/attachments/{id}/material。
- 入口接线：Composer（路径输入/原生选择/拖放）、ChatDock（原生选择优先，浏览器回退字节）、AddMenu（桌面原生选择 → 源引用；浏览器 → 首次落盘；Tauri onPathDrop 真实路径拖放 → 每份材料新建文件卡并 source_kind=dropped_path 登记；浏览器拖放字节 → 首次落盘并标注来源）。

### C. 文件卡（源引用信息 / 作为互动材料 / 缺失修复 / 共享引用）
- 新增 interactive/fileCardRef.ts（纯函数）：payload→卡片 meta 只存 attachmentId/引用与展示事实；来源/归属/可用性/用户说明/材料开关的诚实文案；复制卡片共享 attachmentId；撤销/重做（整份 JSON 快照）不破坏共享；删卡只标 deleted、不删源文件。
- 新增 components/interactive/FileCardMaterialPanel.vue 并挂进 BoardCard.vue 文件卡：
  - 展示文件名 / 类型 / 引用 id / 来源（桌面选择、拖放、浏览器上传、剪贴板截图、历史副本）/ 可用性（可用、缺失+原因、位置待确认、已重新定位）/ 用户说明；
  - 「作为互动材料」开关：PATCH /api/attachments/{id}/material，只控制互动上下文，不是文件访问权限；失败恢复原值并说明未保存；
  - 源文件缺失/位置待确认：桌面端「重新指定位置」→ 用户确认「这是同一个文件吗？」→ relocateAttachment(...,{confirmedIdentity:true})；浏览器端如实说明无法拿真实路径；
  - 服务端事实取不到时用卡片 meta 兜底并明确标注「不是最新核对结果」。
- 预览/读取共用源引用：卡片预览、打开、内容读取继续使用同一 attachmentId（后端 W3 的 resolve_source 语义），前端不复制内容。

### D. 审批界面（复用既有公共组件，不另造弹窗）
- 新增 services/approvalLifecycle.ts（按 W1 5bc95c63 形状）：
  - GET /api/approvals/pending → {approvals:[...]}（normalize：state/confirmed_stage/requires_confirmations/purpose/operation/source/revisions…）；
  - POST /api/approvals/{id}/decide {decision, expected_revision?}；POST /api/approvals/{id}/confirm {stage, expected_revision?}；失败 detail{code,message} 的中文 message 可直接展示；
  - GET /api/approvals/history?limit= 只读历史（兼容 history/approvals 两种键）。
- stores/approvals.ts 扩展：recoverPending()（启动/断线恢复；老后端 404 静默跳过；恢复不抢焦点）、decide()、confirmNext()（stage=confirmed_stage+1，以后端 CAS 返回为准）、recordResult()（APPROVAL_RESULT 按 payload.phase：中间态保留待办并更新进度，终态收口并记最近结局）、loadHistory()；旧审批（无 state 字段）继续走既有 /respond。
- ApprovalFacts.vue 增加 v2 展示块：状态机标签、内部运行数据警告、已确认 N/3 次进度、用途、操作摘要、来源、过期时间（老审批不渲染，不伪造新状态）。
- ApprovalModal.vue：内部数据按钮为「继续确认（第 N/3 次）」而非一次批准；已批准/执行中只显示「等待后端执行结果/知道了」；执行结果历史折叠区；沿用既有焦点管理/队列门控/稍后处理。
- stores/events.ts：APPROVAL_REQUIRED 携带 v2 字段进待办；APPROVAL_RESULT 按 phase 处理（未新增 EventType，与 Lead 裁决一致；EVENT_TYPES 未改，后端事件协议守卫不受影响）。
- App boot 后调用 approvals.recoverPending()。

## 5. 契约 / 接口假设与对齐

- 附件（W3 答复）：POST /api/attachments 带 source_kind 走新语义；/upload 用 X-QIO-Source-Kind；relocate 支持 confirmed_identity；材料开关 PATCH /api/attachments/{id}/material；payload 同时含老字段与 §6.4 新字段（attachment_id/filename/media_kind/origin/source_kind/availability/size/user_note/material_enabled/missing_reason/reference_id）。前端新字段优先、老字段回退。
