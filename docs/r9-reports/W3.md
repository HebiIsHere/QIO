## 1. 已实现

### A. services/file_identity.py（新）
- Windows：GetFileInformationByHandleEx(FileIdInfo=18) 经 ctypes 读卷序列号（取低 32 位，已与 GetVolumeInformationW 交叉核对）+ FILE_ID_128；POSIX：st_dev + st_ino。
- identity_of / raw_identity / content_sha256 / same_file / identity_matches / iter_files_limited / find_by_identity；无法确认身份时返回 None，绝不退化成同名/同大小/同哈希。
- 真实自测入口：uv run --frozen python -m agent.services.file_identity。

### B. services/recycle_bin.py（新）
- Windows：SHFileOperationW(FO_DELETE)，FOF_ALLOWUNDO | FOF_NOCONFIRMATION | FOF_SILENT（另加 FOF_NOERRORUI 防自动化弹窗），pFrom double-NUL；返回码与 fAnyOperationsAborted 都核对，并核验原路径已消失才报 ok。
- POSIX：freedesktop Trash（files/ + .trashinfo，同卷 os.replace；跨卷 EXDEV 如实失败），失败保留文件。
- 任何失败都不永久删除；结果字段含 mechanism / deleted_permanently=false / reason。

### C. services/attachments.py（扩展，旧副本代码保留给历史数据回放）
- 新记录：register_source（不复制/不移动/不改名，stored_path=NULL、kind=reference、file_id/content_sha256/reference_state/user_note/material_enabled/last_verified_at/legacy_paths 落库）。
- 只有字节：write_material（首次落盘 workspace/materials/<yyyy>/<mm>/，临时文件+os.replace，只落一次；source_kind=browser_upload/clipboard_image，origin=user_saved_material）。
- resolve_source：读取/预览/媒体解析/历史回放的唯一解析入口；新记录只认源文件，源文件移动时在有限范围（原目录/父目录/工作区/用户指定根）按 volume+file_id 自动修复；仅同名/同大小/同 mtime/hash 只作为候选 → ambiguous，必须用户确认；历史记录只读回放（副本优先）。
- relocate_reference(confirmed_identity)：身份相同自动修复；身份不同必须用户确认后才采纳，差异写入 legacy_paths；set_material_enabled；remove_reference 只删引用行、绝不删源文件；write_back_source（生产入口，async）先经授权网关 WRITE effect，再重核对 identity+hash 并原子写，原子替换导致身份变化如实记录；_write_back_source_now 为已授权后的同步实现。
- payload/file_ref 暴露 §6.4 全部字段（attachment_id/filename/media_kind/origin/source_kind/availability/size/user_note/material_enabled/missing_reason/reference_id），老字段保留兼容。
- 新记录不参与 prepare/copy；_check 对新记录按源文件事实投影状态（ready/changed/missing/failed + reference_state）。

### D. storage/attachment_migration.py（新）
- inventory：attachments 行/真实文件/消息引用/卡片引用(board_states JSON)/预览引用(board_preview_state)/孤儿副本，只读。
- 审计：attachment_migration_audit(attachment_id, step, outcome, detail)，步骤 inventory / source_ref / cleanup_candidate，幂等覆盖、断点续跑。
- 迁移：有有效原路径→源引用并保留差异事实（content_differs_from_saved_copy 等）；无原路径但 QIO 保存文件仍在→登记为当前源文件（origin=user_saved_material，source_kind=legacy_copy，不删不复制）；全失效→missing + relocate 入口；保留附件 id 与引用关系；首次迁移不搬/不删任何文件，旧副本只登记 material_cleanup_candidates(state=candidate)。
- run_if_pending / pending_count 供启动后台触发；migrate(apply=False) 支持只盘点不写。

### E. api/server.py 附件段
- POST /api/attachments：**只有**源文件引用语义——有 source_path 就 register_source（不复制、不移动）；缺省 source_kind=desktop_path；无路径 → 400 指向上传入口（不再有「省略来源仍复制」的过渡分支）。
- POST /api/attachments/upload：**缺省按 browser_upload 首次落盘**到 workspace/materials/（不再有旧副本语义），响应标注 source_kind/origin；X-QIO-Source-Kind 只用于区分 clipboard_image。
- GET /content：新记录经 resolve_source 读源文件（409+原因/可 relocate），历史记录旧回放口径；读取产生 READ effect 经授权网关。
- GET /{id}：新记录触发一次使用时的有限范围解析（自动修复移动/改名）。
- POST /relocate：新记录 relocate_reference，身份不一致 409 + candidates，confirmed_identity=true 才采纳。
- DELETE：新记录 remove_reference（只删引用，源文件仍在）；历史记录旧清理（仅 QIO 管理目录）。
- PATCH /material + POST /material-enabled：互动材料开关。
- 维护接口：GET/POST /api/maintenance/attachments/migration（盘点/审计/清理清单，POST 可重跑 apply=false 只盘点）；POST /api/maintenance/attachments/cleanup（DELETE effect → 授权 → 系统回收站）。
- lifespan：启动后后台任务 run_if_pending 迁移一次（幂等），关闭时在 DB 关闭前收尾。
