## 2. 交付明细（对照契约 §11）

### A. 关闭行为
- 设置键 `ui.close_behavior`：`backend/src/agent/api/server.py` 的 `GET/PUT /api/settings/ui`
  - 默认 `ask`；非法值 400；旧客户端（无该字段）按默认，不报错；PUT 支持只改其中一项。
  - 只读入口保持 `typewriter_cps` 兼容。
- `frontend/src/components/WindowChrome.vue`：关闭按钮、系统 CloseRequested、Alt+F4 全部进入同一
  `handleCloseRequest`：ask → QIO 自己的确认框（最小化到托盘 / 退出 QIO / 取消 + 记住我的选择）；
  tray → `request_close("tray")`（壳 hide）；quit → 真正退出流程。每次关闭前从后端**重读**设置
  （API 改设置立即生效，真机脚本就靠这一点）。
- `frontend/src/services/quitGuard.ts`：退出守卫；`frontend/src/services/api.ts` 在退出开始后拒绝
  新的写请求（唯一例外是退出接口本身）。`backend/src/agent/api/server.py` 的 session_guard 在
  退出闸门开启后对新的写请求返回 503（读请求仍放行）。

### B. 托盘（`frontend/src-tauri/src/main.rs`）
- `TrayIconBuilder`（Cargo.toml 开启 `tray-icon` feature）+ 菜单「显示主窗口 / 退出 QIO」；
  左键点击恢复窗口；恢复动作 = `show + unminimize + set_focus`；只隐藏、不重建窗口，因此
  **不会重新拉起后端、不会产生第二个实例**。
- 托盘「退出 QIO」：发 `qio://tray-quit` 给前端走**同一个**真正退出流程；若前端 10s 内没有接手
  （WebView 卡死/未加载），壳按 pid 兜底收尾后退出（`TRAY_QUIT_FALLBACK_WAIT`）。
- capability 无需改动：生成的 `core:default` 已包含 `core:event:default`（allow-listen），
  已核对 `target/debug/build/tauri-*/out/permissions/default.toml`。

### C. 真正退出流程（前后端协同）
1. 前端 `quitting` 守卫 + 拒绝新写请求；
2. `POST /api/lifecycle/shutdown`（`backend/src/agent/api/lifecycle_routes.py`）：
   同步置退出闸门（之后写请求 503）；与 lifespan **共用同一个 aclose 任务**（后端收尾只执行一次、
   必定获得执行机会）；`SHUTDOWN_GRACE_SECONDS = 8.0` 有界等待，超时如实返回
   `{done:false,timeout:true}` 且**不取消** aclose；收尾完成后通过注入的 uvicorn Server 钩子优雅退出；
   退出前快照有效 waiting 审批，关闭后恢复被「取消 turn」连带结算成 cancelled 的行
   （已批准/已过期/用户此前取消的不碰；W1 审批 v2 接管后此兜底通常不再生效）。
3. 壳 `request_close("quit")`：`AtomicBool` 幂等闸门；先快照后端进程树（root + 全部后代，含
   venv launcher → 真正解释器这种两层结构），等其自行退出（预算 15s）；仍未退出才
   `taskkill /PID <pid> /T /F`，再按**事前 pid 名单**清孤儿，最后逐 pid 核验消失；
   失败如实记日志（壳退出时 Job Object 句柄关闭由系统兜底，但不谎称「已确认结束」）。
4. `app.exit(0)`；全程可重复调用不出错（第二次返回 `already:true`）。

### D. 后端接线

## 6. 既有真机验证资产适配（Lead 要求）

### `scripts/install_e2e.py`（shelllease 阶段）
- 原逻辑：启动真外壳 → 核对 lease → 健康检查 → WM_CLOSE → 断言壳/sidecar 退出、lease 删除。
  默认关闭行为改为 ask 后，无人值守 WM_CLOSE 会停在确认框上 —— 该脚本会失败/挂住。
- 适配（只改 shelllease 阶段，其他阶段未动）：
  1. 健康检查后，用 `PUT /api/settings/ui {"close_behavior":"tray"}` → WM_CLOSE：
     断言**窗口隐藏但壳与 sidecar 继续运行、lease 保留**（A-116a/116b/117a），并记录
     A-117b「隐藏后窗口可恢复」（用 Win32 `ShowWindow` 做托盘 show+restore 的 OS 层等价动作）；
  2. 再 `PUT ... {"close_behavior":"quit"}` → WM_CLOSE：沿用原 A-116..A-119 断言
     （壳退出、sidecar 消失、lease 删除）；
  3. DPI：没有端口/API 时如实记 FAIL 并继续，脚本不会悬住（原有 30s wait + kill 兜底保留）。
- 多实例「只收本实例」断言：未改，仍按 pid/lease 归属（`install_e2e_multi.py` 复用）。
- **运行结果**：本环境无安装包，未运行（仅 `py_compile` 通过）。
