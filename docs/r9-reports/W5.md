## 2. 交付明细（对照契约 §11）

### A. 关闭行为
- 设置键 `ui.close_behavior`：`backend/src/agent/api/server.py` 的 `GET/PUT /api/settings/ui`
  - 默认 `ask`；非法值 400；旧客户端（无该字段）按默认，不报错；PUT 支持只改其中一项。
  - 只读入口保持 `typewriter_cps` 兼容。
- `frontend/src/components/WindowChrome.vue`：关闭按钮、系统 CloseRequested、Alt+F4 全部进入同一
  `handleCloseRequest`：ask → QIO 自己的确认框（最小化到托盘 / 退出 QIO / 取消 + 记住我的选择）；
  tray → `request_close("tray")`（壳 hide）；quit → 真正退出流程。每次关闭前从后端**重读**设置
  （API 改设置立即生效，真机脚本就靠这一点）。
- `frontend/src/services/quitGuard.ts`：退出守卫；`frontend/src/services/api.ts` 在退出开始后拒绝
  新的写请求（唯一例外是退出接口本身）。`backend/src/agent/api/server.py` 的 session_guard 在
  退出闸门开启后对新的写请求返回 503（读请求仍放行）。

### B. 托盘（`frontend/src-tauri/src/main.rs`）
- `TrayIconBuilder`（Cargo.toml 开启 `tray-icon` feature）+ 菜单「显示主窗口 / 退出 QIO」；
  左键点击恢复窗口；恢复动作 = `show + unminimize + set_focus`；只隐藏、不重建窗口，因此
  **不会重新拉起后端、不会产生第二个实例**。
- 托盘「退出 QIO」：发 `qio://tray-quit` 给前端走**同一个**真正退出流程；若前端 10s 内没有接手
  （WebView 卡死/未加载），壳按 pid 兜底收尾后退出（`TRAY_QUIT_FALLBACK_WAIT`）。
- capability 无需改动：生成的 `core:default` 已包含 `core:event:default`（allow-listen），
  已核对 `target/debug/build/tauri-*/out/permissions/default.toml`。

### C. 真正退出流程（前后端协同）
1. 前端 `quitting` 守卫 + 拒绝新写请求；
2. `POST /api/lifecycle/shutdown`（`backend/src/agent/api/lifecycle_routes.py`）：
   同步置退出闸门（之后写请求 503）；与 lifespan **共用同一个 aclose 任务**（后端收尾只执行一次、
   必定获得执行机会）；`SHUTDOWN_GRACE_SECONDS = 8.0` 有界等待，超时如实返回
   `{done:false,timeout:true}` 且**不取消** aclose；收尾完成后通过注入的 uvicorn Server 钩子优雅退出；
   退出前快照有效 waiting 审批，关闭后把被「取消 turn」连带结算成 cancelled 的 **legacy 行**
   （`state IS NULL`，即 base `ApprovalService.request()` 那条同步等待路径）恢复为 pending；
   **W1 审批 v2 的 `state` 权威行一律不碰**（SQL 带 `(state IS NULL OR state='waiting')` 守卫，
   已用 `test_restore_does_not_override_approval_v2_state` 固化）。已核对 W1 分支：
   `ApprovalService.aclose()` 保留 waiting，但其 `request()` 的 CancelledError 路径仍会
   `_settle(cancelled)` —— 退出时取消在跑的 turn 正好会走到这里，所以该兜底在 W1 合并后
   **仍然必要**；对 v2 state 行则是无害 no-op。
3. 壳 `request_close("quit")`：`AtomicBool` 幂等闸门；先快照后端进程树（root + 全部后代，含
   venv launcher → 真正解释器这种两层结构），等其自行退出（预算 15s）；仍未退出才
   `taskkill /PID <pid> /T /F`，再按**事前 pid 名单**清孤儿，最后逐 pid 核验消失；
   失败如实记日志（壳退出时 Job Object 句柄关闭由系统兜底，但不谎称「已确认结束」）。
4. `app.exit(0)`；全程可重复调用不出错（第二次返回 `already:true`）。

### 8.2 根因（已用首轮证据逐条定位）
1. **前端启动握手失败 → 关闭行为整体落到默认 ask**（A-117a/117b/A-116/A-118/A-119 的共同根因）：
   install_e2e 注入 `QIO_SESSION_TOKEN`；后端在「已有令牌」时**不写令牌文件**（auth.py 设计），
   而壳只从令牌文件读 `qio_backend_info` → 前端等 30s 超时、停在「正在启动 QIO 后端…」，
   读不到 `ui.close_behavior`；关闭行为又完全由前端判定 → 两个 WM_CLOSE 都只弹 ask 框，
   tray 不隐藏、quit 不退出 → 脚本 30s 后强杀壳 → lease 没删。
   证据：壳日志只有两条「收到主窗口关闭请求」，没有任何 hide/quit 记录；A-115「没读到令牌」。
2. **壳侧没有独立执行关闭行为的兜底**：即使前端正常，依赖前端回传动作也是脆弱的
   （Lead 明确要求：真实用户点 X 不能因为前端异常而毫无反应）。
3. **A-118 的「sidecar 残留」是两棵不同的树**：A-114 按路径枚举列出
   173448(ppid=壳) 与 183596(ppid=187676)；后者是 **health 阶段 standalone backend**
   （父进程=脚本），`ensure_backend_stopped` 在受限令牌下 CIM 查询返回空 → 误以为已停止，
   被 A-118 当成壳的 sidecar。壳自己的 sidecar（173448）实际上已随强杀消失。
4. **quit 时后端自身退出被 SSE 长连接拖住**：首轮即使走对 quit，uvicorn 的优雅关闭会等前端
   `/api/events` 长连接，可能超出壳 15s 预算 → 只能强杀，慢且日志像失败。

### 8.3 修复（本分支）
1. **token 握手**：`frontend/src-tauri/src/main.rs` 启动时若发现注入的 `QIO_SESSION_TOKEN`，
   由壳写入约定令牌文件（不打印内容）→ 前端 `qio_backend_info` 立即成功。
2. **关闭行为壳侧执行（不再依赖前端动作）**：
   - 新增 `ShellRuntime.close_behavior/close_ack`；前端在 `ui.load()` / 保存设置后
     `qio_set_close_behavior` 同步一份缓存；
   - 系统 CloseRequested 由壳在后台线程解析行为：**环境覆盖 > 每次现读后端设置 > 前端缓存 > ask**
     （每次现读保证「API/设置页改了立即生效」，后端不可达才退回缓存）；
   - tray：壳直接 `window.hide()`；quit：壳直接 POST `/api/lifecycle/shutdown`（自带极简
     localhost HTTP 客户端，不新增依赖）→ 等/结束后端进程树 → 核验 → `app.exit(0)`；
   - ask：通知前端弹框；前端收到后立刻 `qio_close_ack`，壳 1.8s 没等到 ACK（前端异常）就
     **兜底隐藏到托盘**（可逆、不退出），保证「点 X 一定有反应」；
   - 托盘菜单「退出 QIO」同样改为壳侧直接执行；标题条 X 改为 `window.close()`，
     统一由壳按设置执行（前端只承担 ask 的 UI）。
3. **快速、可核验的退出**：后端 `uvicorn.Config(timeout_graceful_shutdown=3)`；
   前端收到 `qio://quit-requested` 先断开 SSE 长连接。修复后同构探针退出 **1.22s**（原 17.49s）。
4. **E2E 脚本健壮性**：`_backend_pids_by_path` 在 CIM 查询为空时用
   `Get-Process -Name qio-backend` 按 `Path` 再核对（**仍按路径，不按名字杀**），
   避免 health 阶段的 standalone backend 被误算成壳的 sidecar（A-118 假失败来源）。
5. `install_e2e.py` shelllease 的 tray/quit 两段语义不变（先 tray 断言隐藏/存活/lease 保留/可恢复，
   再 quit 断言壳退出/sidecar 消失/lease 删除），现在由壳侧执行、不再受 ask 弹窗影响。
