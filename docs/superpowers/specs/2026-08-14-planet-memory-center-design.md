# 星球记忆中心：知识与实体管理（v1）

日期：2026-08-14
状态：已与用户逐节确认

## 背景与目标

QIO 已有「话题星球」：全屏覆盖层里一个 3D/2D 星球 + 右侧 340px 话题边栏（话题列表 → 话题详情：片段/实体标签/知识内联编辑）。知识（Knowledge）与实体（EntityCard）目前**缺少全局管理入口**：

- 知识只有话题详情里的内联「修正/删除」，无跨话题浏览、无状态流转、无手动新建；
- 实体在话题详情里只是**只读标签**，看不到实体卡（属性/别名/关系），也无法编辑/归档；
- 后端知识没有列表接口；实体列表接口返回的是「注入文本」而非结构化数据。

本设计把管理做进星球：右侧面板升级为「记忆中心」，让用户在记忆发生的可视化语境里直接查看、纠错、审核、归档。

## 核心决策（已确认）

| 决策点 | 结论 |
| --- | --- |
| 入口形态 | 星球右侧面板，不做独立路由/设置页 Tab |
| 面板结构 | 顶部三页签：话题 / 知识 / 实体 |
| 布局 | 双态面板：浏览态 340px ↔ 管理态 640px（星球左移、部分遮挡） |
| 知识范围 | 浏览/修正/归档 + 状态管理（批准/打回）+ 手动新建 |
| 实体范围 | 属性 + 关系均可编辑；不做手动新建实体 |
| 属性置信度 | 实体属性保留、展示且可编辑（0~1 数值） |
| 双向联动 | 点星球节点 ↔ 话题页签；知识/实体条目关联话题 → 聚焦星球 |
| v1 不做 | 实体手动新建、恢复已归档、批量操作、分页、关系在星球上的可视化连线 |

## 信息架构

### 星球覆盖层 · 右侧面板

- 顶部页签：**话题 / 知识 / 实体**；页签右侧「管理模式」开关。
- **浏览态（340px）**：页签 + 列表（搜索/过滤）。
- **管理态（640px）**：点开条目进入编辑（属性表、关系编辑器、摘要/别名/分类/内容表单）；星球画布左移、部分遮挡；「✕ 管理模式」或返回按钮退回浏览态。
- 切页签/开关只影响面板，不关闭星球；话题页签保持现有「片段选择起点 / 从这里开始」能力。
- 状态记忆：当前页签、管理模式开关状态在会话内保持（不强制持久化，沿用现有 floatingState 风格即可，非必须）。

### 话题页签（保持现有 + 小改）

- 话题列表（搜索）+ 话题详情：片段选择、实体标签、知识内联编辑。
- 小改：实体标签变为**可点击** → 跳转「实体」页签并打开该实体卡；知识条目保持内联修正/删除。

### 知识页签

- **列表**：搜索框 + 分类过滤（用户画像/自我/目标/常识/工具经验）+ 状态过滤（默认 active）；每条显示内容（截断）、分类 badge、状态 badge、关联话题名。
- **条目动作**：
  - 修正：管理态编辑内容 → 保存（走 revise，生成新版本，旧版自动 revoked）；
  - 归档：revoke；
  - 批准：`pending_review → verified → active`（补上用户审核入口，高影响分类本来就需要用户确认）；
  - 打回草稿：`pending_review → draft`（reject）。
- **手动新建**：列表顶部「+ 新建知识」→ 分类下拉 + 内容 + 可选关联话题 → 创建即 active（用户权威：create + verify(verified_by="user") + activate）。
- 点击关联话题名 → 星球聚焦该话题并切到话题页签。
- 知识置信度（系统维护）在列表**只读展示**，不提供编辑。

### 实体页签

- **列表**：搜索（名称/别名）+ 可选类型过滤；每条显示名称、摘要一行、类型 badge、属性数/关系数。
- **管理态详情/编辑**：
  - 摘要（多行）、类型（文本）、别名（标签增删）；
  - **属性表**：键=值+置信度（0~1 数值），行内增/删/改；置信度保留展示且可编辑（决策 A）；
  - **关系编辑器**：类型 + 目标实体名（目标输入带已有实体名提示），可增/删；
  - **归档**：revoke。
- 话题详情里的实体标签 → 可点击，跳转实体页签并打开该卡。

### 双向联动

- 点星球话题节点 → 话题页签选中该话题（现有行为保持）。
- 知识/实体条目里的关联话题 → 星球聚焦该话题。
- 实体不上星球渲染（星球是话题图），v1 不做实体节点定位。

## 后端 API 变更

### 知识

- `GET /api/knowledge?category=&state=&q=`：列表（结构化；含 content/category/state/confidence/topic_id/topic_name/created_at/updated_at）。后端 `KnowledgeService` 新增 `list_items(category, state, q)`，接口联表 nodes 直接附带 `topic_name`，前端不自行映射。
- `POST /api/knowledge`：手动新建 `{category, content, topic_id?}` → `create + verify(verified_by="user") + activate` → 返回 active 条目。
- `POST /api/knowledge/{id}/verify`：批准待审（`verify(verified_by="user") + activate`）。
- `POST /api/knowledge/{id}/reject`：打回草稿（`reject`）。

### 实体

- `/api/entities` 与 `/api/entities/{id}` 改为**结构化输出**：`{id, name, aliases, kind, summary, attributes:[{key,value,confidence}], relations:[{type,target_name}], state, created_at, updated_at}`（现有返回是注入文本 `format_card`，前端管理页不需要该文本；注入仍走内部 `match_cards`，不受影响）。
- `POST /api/entities/{id}/relations`：`{type, target}` 新增/更新关系边（复用 `_sync_relations` 或新增方法，目标名自动建/查节点）。
- `DELETE /api/entities/{id}/relations`：`{type, target}` 删除关系边（`EdgeService` 需新增 `remove(src, dst, edge_type)`）。
- `revise`（attributes/aliases/summary/kind）已存在，直接复用。

### 前端

- `api.ts` 补齐：`listKnowledge` / `createKnowledge` / `verifyKnowledge` / `rejectKnowledge` / `listEntities`（结构化）/ `getEntity` / `reviseEntity` / `revokeEntity` / `addEntityRelation` / `removeEntityRelation`。
- `PlanetView.vue` 面板重构为三页签 + 双态宽度；新增 `KnowledgePanel` / `EntityPanel` 子组件（或同文件分区块，实现时按可维护性拆分）。
- 实体目标名提示：前端用已拉取的实体列表做过滤联想（数据量小，客户端完成）。

## 数据流要点

- 知识「批准/打回/归档/新建」全部即时写库；列表变更后局部刷新该页签。
- 实体「修正/关系增删」即时写库；实体页签列表与话题详情实体标签保持同步（返回星球时重新拉取话题详情）。
- 所有写操作失败给出 toast 提示（沿用 SettingsView 的 toast 模式）；成功给出轻提示。

## 边界与非目标（v1）

- 不做实体手动新建（实体由记忆提炼而来）。
- 不做恢复已归档条目、批量操作、服务端分页（数据量小，前端过滤）。
- 不做关系在星球上的可视化连线、不做实体节点定位。
- 知识置信度只读（系统维护）；实体属性置信度可编辑（决策 A，当前为溯源字段，不影响注入行为）。

## 验收要点

1. 星球面板三页签可切换；管理模式开关在 340↔640px 间平滑过渡，星球画布随宽度重排。
2. 知识：跨话题列表 + 搜索/分类/状态过滤；修正/归档/批准/打回/新建全部生效且状态正确。
3. 实体：列表搜索；详情可编辑摘要/类型/别名/属性（含置信度）/关系；归档生效；话题详情实体标签可点击跳转。
4. 双向联动：点知识/实体条目的关联话题 → 星球聚焦该话题并切到话题页签。
5. 后端接口 + 前端交互单测通过；现有测试（话题/实体卡/知识生命周期）不回归。
