# 首次引导（Onboarding）v1 设计

日期：2026-08-18
状态：已与用户逐节确认（§1–§6）

## 背景与目标

QIO 是本地优先的个人记忆助手（话题图 / 记忆 / 知识 / 实体卡 / 凭据都在本地）。当前首次使用体验是「空对话页 + 无主凭据警告条」，用户需手动去设置页配 API Key，且 QIO 对用户一无所知。

本设计引入「像操作系统开始界面一样的首次引导」：全屏向导，双线目标——
1. **帮用户设置 QIO**：连接模型（API Key）、偏好（主题/回答风格）；
2. **帮 QIO 认识用户**：采集称呼/介绍/标签/目标，主动写入记忆体系（`user_profile` 知识、「我」实体卡、种子话题），让首日就有记忆底座。

## 核心决策（已确认）

| 决策点 | 结论 |
| --- | --- |
| 步骤结构 | 6 步：欢迎 / 连接模型 / 认识你 / 偏好 / 目标 / 完成 |
| 触发与完成 | 首次启动必现；完成判定 = 主凭据已配 且 称呼已填；未完成 → 对话页轻提醒；设置页可重跑 |
| 画像落库 | 结构化采集 + 主动落库（user_profile 知识 + 「我」实体卡 + 种子话题） |
| 视觉形态 | 全屏向导（OS 安装风） |
| 不做账号 | 保持单用户本地优先（已确认） |

## §1 触发与完成

- **触发**：真正的首次启动（设置中无 `onboarding.wizard_seen` 记录）且 onboarding 未完成 → 弹出全屏向导；向导一旦打开即记录 `wizard_seen=true`。
- **此后**：即使未完成，也不再自动弹全屏向导，只在对话页显示「继续设置」轻提示；重跑入口在设置页。
- **完成判定**：主凭据已配置 **且** 称呼已填写。
- **未完成时**：对话页顶部一条**可关闭**的「继续设置」轻提示（关闭状态持久化到设置）。
- **重跑入口**：设置页「重新运行设置助手」；重跑时已配项预填、落库幂等（不重复建知识/实体/话题）。

## §2 六步内容与交互

- 全屏覆盖层；顶部 6 段步骤进度条；底部统一「跳过 / 上一步 / 下一步」；每步可跳过（跳过 = 该部分留空，之后可补）。

1. **欢迎** — 品牌 + 一句话定位 + 「开始设置」按钮。
2. **连接模型** — API Key 输入（复用 `identifyCredential` 自动识别 + 测试），成功即创建 `credentials`；可跳过。
3. **认识你** — 称呼（必填才算完成判定）+ 一句话介绍（可选）+ 标签 chips（身份/职业/兴趣/习惯，可增删）。
4. **偏好** — 主题（亮/暗，写入现有 `qio-theme`）+ 回答风格（简洁/详细/俏皮）。
5. **目标** — 多选「你想让它帮你做什么」（学习/写作/编程/生活/陪聊等）→ 生成种子话题。
6. **完成** — 总结已设置项 + 「进入对话」/「进入星球」→ 标记 onboarding 完成。

## §3 数据落库

- 凭据 → `credentials`（复用现有创建/识别/测试能力）。
- 认识你 → `user_profile` 分类知识（称呼/一句话介绍）+ **「我」实体卡**：称呼/介绍进摘要，标签（身份/职业/兴趣/习惯）进属性（key=身份/职业/…，value=…，confidence=1.0），回答风格进属性。
- 偏好 → 主题写 `qio-theme` 设置；回答风格写「我」实体卡属性。
- 目标 → 按选项生成种子话题（复用 `create_topic` 或 TopicService 幂等建）。
- 完成 → 设置存 `onboarding.done=true` + 完成时间。

幂等规则：重跑/重复提交时，知识/实体/话题按「存在即更新、不重复创建」处理（名称/属性 upsert，种子话题按标题去重）。

## §4 后端接口（新增 + 复用）

- `GET /api/onboarding/status` — 返回 `{done, has_credential, has_name, wizard_seen}` 及已配项摘要。
- `POST /api/onboarding/seen` — 记录向导已打开（写 settings `onboarding.wizard_seen`）。
- `POST /api/onboarding/profile` — body `{name, intro, tags:[{key,value}], style?, goals:[...]}`；幂等写 user_profile 知识 + 「我」实体卡 + 种子话题；返回落库摘要。
- `POST /api/onboarding/complete` — 标记完成（写 settings `onboarding.done`）。
- 复用：`/api/credentials`、`identifyCredential`、主题设置、话题创建。

## §5 前端

- 新增 `OnboardingWizard.vue`（全屏向导，6 步组件化）；App 启动时按 `GET /api/onboarding/status` gating（未完成且首次 → 显示向导）。
- 对话页顶部「继续设置」轻提示条（可关闭，状态存 localStorage/settings）。
- 设置页「偏好」区新增「重新运行设置助手」入口。
- 复用设计令牌与 QInput/QSelect/QSlider 等控件；延续全屏覆盖层模式（参考 PlanetView）。

## §6 边界（v1 不做）

- 不做账号系统（已确认）；不做数据导入/迁移；不做多语言；不做强制完成（主凭据可跳过）。
- 不做「隐私说明」独立步骤（本地应用，隐私默认在本机）。

## 验收要点

1. 全新数据目录首次启动 → 全屏向导出现；走完 6 步进入对话页，设置/凭据/画像/种子话题全部落库。
2. 完成判定正确：缺凭据或缺称呼 → 对话页出现「继续设置」条（可关闭）。
3. 设置页「重新运行设置助手」→ 向导可重跑，已配项预填；重跑不产生重复知识/实体/话题。
4. 落库校验：user_profile 知识、「我」实体卡（含标签属性/回答风格）、种子话题出现在星球/知识/实体页。
5. 后端接口 + 前端单测通过；现有测试不回归。
