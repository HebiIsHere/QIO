# QIO 第四阶段设计规范：视觉语言、交互收口与动效语言（v3 · 2026-09-15）

前置：`docs/superpowers/specs/2026-08-09-qio-frontend-design.md`（v2，含 §8 动效与 §12/§13 修订）。
本文是 v3，**只补充与修订视觉 / 交互 / 动效语言**，不改变前三阶段的状态语义、安全边界与业务流程。

## 0. 本阶段目标与优先级

唯一目标：把前三阶段已经建立的能力，用**同一套**视觉语言、交互语言、动效语言表达出来。

优先级：**一致性 > 交互舒适度 > 动效层级 > 空间连续性 > 材质语言 > 视觉细节 > 炫技效果**。

反目标（明确不做）：程序化构筑物（Topic 建筑 / 城市生长）、信息架构重做、后端状态机改动。

---

## 1. 动效语言

核心定义：**非线性、阻尼控制下的缓动弹性、适度惯性、连续收束。**

不是「越少越短越直线」，也不是游戏化弹跳。三个极端都要避免：

| 反模式 | 表现 | 为什么不要 |
| --- | --- | --- |
| 机械线性 | 全站一条 `ease`、时长接近 | 没有呼吸感，层级消失 |
| 过冲回弹 | 多次回弹、明显弹簧感 | 卡通化，与「安静未来」冲突 |
| 全局零动效 | 一切瞬切 | 状态变化丢失连续性，用户看不出发生了什么 |

### 1.1 三层动效

| 层 | 用于 | 时长 | 曲线 | 关键词 |
| --- | --- | --- | --- | --- |
| **高频** | Button / Toggle / Hover / 选中 / 保存→已保存 / Tab / 展开收起 / 列表项状态 / 卡片局部状态 | 80–180ms | `--ease-1`（标准）、`--ease-1-out`（离开） | 简洁、利落、安静 |
| **中频** | 打开 Topic Detail / 展开 Fragment 原文 / 侧板 / Tool Creation 状态推进 / 局部编辑进出 / Approval 详情 / 返回 Conversation | 200–280ms | `--ease-2`（柔顺） | 柔顺、从容、自然 |
| **低频** | Planet 入口展开 / Planet 退出收拢 / 关键空间级过渡 | 560–760ms（分阶段） | `--ease-3-in` + `--ease-3-settle` + `--ease-3-elastic` | 优雅、记忆点、非线性、空间感 |

高频层**不排除弹性**，只是弹性幅度极小到几乎不可见；中频层允许轻微非线性；低频层是「优雅预算」的主要去处。

### 1.2 曲线集（刻意保持少）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--ease-1` | `cubic-bezier(.2,.8,.24,1)` | 高频统一曲线（沿用 v2 的 `--ease`） |
| `--ease-1-out` | `cubic-bezier(.4,0,.7,.2)` | 高频离开（先慢后快、不拖尾） |
| `--ease-2` | `cubic-bezier(.32,.72,.24,1)` | 中频结构动效：起步不僵硬，中段有推进感 |
| `--ease-2-out` | `cubic-bezier(.42,0,.42,1)` | 中频离开/收起 |
| `--ease-3-in` | `cubic-bezier(.5,.02,.2,1)` | 低频进入：慢起 → 快速推进 |
| `--ease-3-settle` | `cubic-bezier(.24,1.04,.32,1)` | 低频收束：约 3% 单次柔和过冲后收紧（**不是 bounce**） |
| `--ease-3-out` | `cubic-bezier(.5,0,.24,1)` | 低频收拢/退出 |

规则：**同一层共享曲线**，不为单个组件发明曲线；Planet 的 `--ease-3-*` 不得被复制到按钮与列表上。

### 1.3 时长令牌（分层命名 + 兼容别名）

新增的规范名（`--mo-*`）是唯一事实来源，v2 的 `--dur-*` 改为别名指向它们，既有组件无需改动即获得新分层。

| 规范名 | 值 | 映射的旧名 | 用途 |
| --- | --- | --- | --- |
| `--mo-1-press` | 80ms | `--dur-press` | 按下 |
| `--mo-1-state` | 150ms | `--dur-toggle` | 悬停/选中/开关 |
| `--mo-1-fast` | 140ms | `--dur-fast` | 高频通用 |
| `--mo-1-exit` | 150ms | `--dur-exit` | 高频离开 |
| `--mo-1-menu` | 170ms | `--dur-menu` | 菜单/小型浮层 |
| `--mo-1-wide` | 180ms | `--dur-base` | 高频上限 |
| `--mo-2-in` | 240ms | `--dur-page-in` / `--dur-panel` | 中频进入 |
| `--mo-2-move` | 210ms | `--dur-panel` | 中频结构位移（与宽度过渡同时发生） |
| `--mo-2-out` | 200ms | `--dur-page-out` | 中频离开 |
| `--mo-2-wide` | 280ms | `--dur-slow` | 中频上限 |
| `--mo-3-prepare` | 180ms | `--dur-planet-settle` | 低频 A 阶段 |
| `--mo-3-expand` | 520ms | `--dur-planet-in` | 低频 B 阶段（体量展开） |
| `--mo-3-settle` | 220ms | `--dur-planet-backdrop` | 低频 C 阶段（场景接管） |
| `--mo-3-collapse` | 420ms | `--dur-planet-out` | 低频收拢（单段） |

### 1.4 位移令牌

位移必须能整体降级（reduced-motion），因此不允许在组件里写裸数值：

`--shift-1`（1px 按下）、`--shift-2`（2px 微位移）、`--shift-4`（4px 浮层进入）、`--shift-8`（8px 面板进入）、`--shift-panel`（16px 抽屉）。

## 2. Planet 连续体

### 2.1 原则

**入口小球不是按钮、不是图标、不是装饰球，而是全屏 Planet 的抽象压缩态。** 它与全屏 Planet 是同一个对象的不同尺度状态，而不是两个互相淡入淡出的组件。

> **2026-09-20 修订（用户实测）**：入口小球现在由**真实星球场景本身**承担 ——
> 关闭星球时把同一个场景、同一个渲染器缩到入口尺度常驻渲染（慢速自转、~15fps 低功耗），
> 不再另画一个 2D 压缩态（WebGL 不可用时才退回 2D）。代价：three.js 会在对话页懒加载并常驻。

### 2.2 共同视觉语言（小球与全屏必须共享）

1. 同一套几何：球体轮廓 + 3 层 SDF 融合环（内粗外细），环的形状由**真实话题点位置**决定；
2. 同一套数学：`planet/sdfRings.ts::levelField` + `smin`，不是「画几个椭圆装作环」；
3. 同一套颜色：`--accent` / `--link` / `--accent-soft`，随主题切换；
4. 同一套生命感：低频呼吸 + 轻微内部流动，幅度小到「不像加载动画」。

小球**不承担**信息展示：不显示数量、不显示标签、不做进度指示（运行中的活动点除外，那属于状态而非信息）。

### 2.3 进入（三阶段）

| 阶段 | 时长 | 发生什么 |
| --- | --- | --- |
| A 入口激活 | 180ms | 小球被激活：轻微放大、内部细节与环亮度增强；周边 UI（对话页）轻微退后（降透明 + 微缩放）；用户意识到「这个对象即将展开」 |
| B 体量展开 | 520ms | 同一个对象放大：球体轮廓从入口矩形位置连续长大到全屏构图，相机视角协同推进，话题点密度随尺度增加（0 → 可交互密度） |
| C 场景接管 | 220ms | Planet 成为主视觉对象，玻璃浮层（退出控件、话题信息层）轻量进入，话题进入可交互密度 |

> **2026-09-20 修订（用户实测：「进入时有两段动画，一段放大进入、一段回正」）**：
> A 阶段**不再是一段独立等待** —— 星球层与入口小球同帧可见，A 只在冷路径
> （入口小球还没拿到数据）里真实存在，作为「小球等着内容」的停顿；
> 热路径下打开读起来就是 **B 一段连续动作**。
> 同时「聚焦当前在聊的话题」必须与 B **同刻开始、同刻收束**（聚焦时长直接取长大时长）：
> 把聚焦排在展开之后，就会变成「先放大进入、再回正」两段。

### 2.4 退出（反向连续体）

`话题交互层降密度 → 玻璃浮层收回 → Planet 回到抽象态 → 体量收缩 → 沿原路径回到入口位置 → 重新成为小球`。

不允许「整个 Planet 直接消失」，也不允许「小球淡出 + 大 Planet 淡入」这种伪连续。

### 2.5 空间连续性

- 进入不是页面跳转，退出不是关闭模态框；
- 增长的**起点**是入口小球的矩形中心与直径，**终点**是全屏 Planet 中球体的实际屏幕尺寸；
- 收缩的终点必须是入口小球的当前位置（含贴边隐藏状态），而不是「屏幕中心」；
- 打开时对话页不卸载、不移除滚动位置，只做轻微退后。

### 2.6 不做的事

本阶段不引入程序化构筑物（Topic 建筑、城市、生长体）。Planet 只做「对象本体 + 转场 + 空间连续性 + 浮层材质 + 交互气质」。

## 3. 晶体玻璃材质

### 3.1 定义

**高透晶体玻璃 ≠ 深色毛玻璃 + 一道高光。** 需要同时具备：

- 高透明度、低雾化（`backdrop-blur` 小、背景色极淡）
- 轻微背景折射感（用饱和度的轻微提升模拟，而不是 heavy blur）
- 细致的边缘厚度感（内描边 + 顶部内高光）
- 轻微冷暖边缘分离（极轻的色散暗示：暖边 + 冷边各一条，透明度 ≤ 0.18）
- 内外层亮度差（玻璃内表面比外表面略亮/略暗一档）
- 克制：不炫目、不像液态胶片、不像塑料高光片

### 3.2 适用 / 不适用

| 适用 | 不适用 |
| --- | --- |
| Planet 周围浮层（退出控件、话题信息卡） | 全部对话消息 |
| 轻量信息卡 / 关键确认层 | 全部按钮 |
| 局部悬浮 UI（浮动窗口、设置入口） | 所有列表项、长文本主体、高频输入表单 |

玻璃的作用是把某一层表达成「悬浮在场景中的信息层」，不是「让界面变漂亮」。

### 3.3 令牌

`--glass-bg` / `--glass-bg-strong` / `--glass-blur` / `--glass-border` / `--glass-edge-top` / `--glass-inner` / `--glass-tint-warm` / `--glass-tint-cool` / `--glass-shadow`，随主题切换。
类：`.qio-glass`（浮层）/ `.qio-glass--panel`（较大面板）/ `.qio-glass--chip`（小控件）。

## 4. 统一组件语言

收敛到少量原语（`frontend/src/styles/base.css`），新功能不再自带一套视觉语法：

| 原语 | 类 | 说明 |
| --- | --- | --- |
| Button | `.qio-btn`（`.primary` / `.danger` / `.mini` / `.quiet`） | 状态连续：default → hover → pressed → loading → success → failed → disabled |
| Card | `.qio-card`（`.qio-card--quiet` / `.qio-card--focus`） | 统一圆角 `--r-lg`、内边距 `--sp-4`、状态推进**原位发生** |
| Panel / Floating | `.qio-floating`（+ `.qio-glass`） | 浮层统一阴影与进入/退出 |
| Confirm | `.qio-confirm`（inline / popover / layer） | 取代一切原生 `confirm` / `alert` |
| Inline edit | `.qio-inline-edit` | 默认阅读态，编辑局部进入 |
| Feedback | `.qio-feedback`（`ok` / `warn` / `err` / `info`） | 四级反馈的唯一渲染原语 |
| Tag / State badge | `.qio-tag` / `.qio-state` | 状态徽章统一字号、圆角、底色来源 |
| List row | `.qio-row`（`.is-active` / `.is-selected`） | 统一 hover / focus 亮度，active 与 selected 可区分 |
| Toolbar | `.qio-toolbar` | 分段标题 + 操作区，统一右对齐与间距 |

### 4.1 状态规则（全局）

hover 轻（只改描边/底色一档，不加发光）；focus 必须清晰（`:focus-visible` 焦点环）；active 必须有反馈；disabled 不得看起来可点；selected 必须与 hover 可区分（不能两者同色）。

### 4.2 视觉层级与注意力

普通用户模式下：**Assistant 回答与用户当前正在操作的对象永远最高优先**。Tool status、tag、state badge、小提示、开发者信息一律不得抢过主内容。
技术信息（路径、指纹、参数、内部枚举）只能出现在折叠详情或 Developer Mode 中，且字号不得大于内容字号。

## 5. 反馈层级

| 级 | 用于 | 形态 | 停留 |
| --- | --- | --- | --- |
| 字段级 | 输入错误、字段校验 | 字段下方 inline | 到修正为止 |
| 组件级 | Card 内操作结果、Knowledge 保存、Entity 修改、Approval 局部状态 | 卡片内一行 | 成功短（~1.6s）自动回收；失败保留 |
| 任务级 | Tool Creation / Tool Runtime / Subagent | 该卡片的状态推进（原地） | 跟随任务生命周期 |
| 全局级 | 连接中断、严重错误 | 顶部安静状态行 | 到恢复为止 |

规则：**减少无意义 Toast**。多数成功只需「按钮 → 处理中 → 已保存 → 恢复」；失败比成功更值得停留。
原生 `window.confirm` / `window.alert` / `window.prompt` 全部替换为 QIO 确认层；确认层强度按危险程度分档（inline → popover → 轻量浮层 → 模态），高风险动作才用强确认层。

## 6. 阅读态与编辑态

**默认阅读，按需编辑。**

- 默认以浏览/阅读/理解为主，不铺满输入框、删除按钮与管理按钮；
- 编辑在**局部**发生（就地进入、就地退出），退出后恢复阅读态；
- 危险动作（归档/删除/清除凭据）从阅读态的显式入口进入，并走确认层；
- 适用于 Knowledge、Entity、Topic Detail、Settings 的复杂区域。

Topic Detail 的目标是「浏览一个长期话题的内容空间」，不是「管理一个 Topic 数据对象」：标题层级 → 摘要 → 事实行 → 片段历史 → 相关知识与实体，管理动作降到次级（阅读态不常驻）。

## 7. 状态切换的连续性

**每一个状态变化都应有连续性**：出现 / 消失 / 选中 / 展开 / 收起 / 成功 / 失败 / 替换 / 进编辑 / 出编辑 / 数据更新 / 结构切换。

- 列表项新增、删除、归档、恢复、筛选变化：不得跳变，需有高度、透明度、轻位移与连续重排；
- Tab / Panel 切换：至少淡入淡出 + 轻位移，不做三维翻页；
- Card 状态推进：同一对象原位变化，不做「一个状态一张新卡」；
- 弹层退出期间不得拦截点击（模态遮罩除外），且不得依赖动画事件决定状态。

---

## 8. 无障碍与 reduced-motion

新增动效必须支持 reduced-motion、键盘导航、焦点可见性与语义控件。

reduced-motion 下：

- **保留**必要的淡入淡出与全部状态文字（连续性不能消失）；
- **移除**位移、缩放、旋转与弹性（`--shift-*` 归零、`--ease-3-elastic` 退化为标准曲线）；
- 时长压缩到 ~90ms；
- JS 补间（星球相机）读同一份 `html[data-motion]` 并压到最短路径；
- 功能不得依赖动画事件。

---

## 9. 代码层要求

样式、材质、动效收敛为令牌（本文 §1、§3）；禁止在页面组件里继续散落硬编码色值、时长、缓动与位移。
新增交互优先复用 §4 的原语类；不得为单个功能新增一套视觉语法。
