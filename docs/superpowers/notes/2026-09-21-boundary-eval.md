# 分段边界：确定性策略与离线评测（阶段 4.4）

日期：2026-09-21　策略版本：`boundary-v1`

## 这一版实际启用了什么

| 边界类型 | 判断依据 | 默认状态 |
| --- | --- | --- |
| 容量（轮数 / 长度） | 轮数到点，或内容长度到点，且停在完整轮次边界 | **生效**（沿用既有封块路径，在轮次结束后执行） |
| 明确进入新的交付工作 | 出现开工指令「开始编写 / 开始实现 / 进入实施 …」，且不在否定、引号、假设句里 | `fragment.boundary_mode=enabled` 时生效；**默认 shadow（只记录建议）** |
| 短确认（好 / 继续 / 开始吧） | 长度 ≤ 12 字且属于确认类 | 不切分（同一阶段继续） |
| 追问 / 反驳 / 修正 / 补充 | 命中「不过 / 其实 / 补充 / 改成 …」 | 不切分 |
| 单次插话、长时间间隔、语义相似度下降 | —— | **不单独作为切分依据**（返回 uncertain，保守不切） |
| Embedding / 语义阶段信号 | 复用现有嵌入能力（未在本版启用） | 只保留接口；这一版**没有任何语义切分** |

模式开关：设置键 `fragment.boundary_mode`，取值 `off` / `shadow` / `enabled`；
默认 `shadow`（先观察「如果生效会切在哪里」，不先把对话切开）。

**边界延迟**：本版没有观测手段（切分只在轮前规则命中时发生），记 N/A。

**降级表现**：本版未接入 Embedding 信号，因此"模型不可用时的降级"这一项 N/A；
策略本身不联网、不依赖模型，天然不受凭据与网络影响。

## 这些数字不能说明什么（重要）

1. **用例是本次实现时写的**，且只有 16 条 —— 它证明的是「规则按标签工作」，
   **不是**生产环境的准确率。真实对话里的说法远比这些例句多样。
2. 留出样本也是同一批人写的，只做到「换一种措辞」，**不是**独立标注。
   要得到可信数字，需要真实对话的独立标注（至少要覆盖同一阶段的连续偏移、
   跨阶段的长程案例，以及被引用/假设包裹的指令）。
3. 首版刻意保守：除容量与明确开工之外一律返回 uncertain，不实际切分。
   也就是说，「漏切」在真实数据里会明显高于这张表。

## 结论

这一版可以放心启用的只有两类边界：**容量**（本来就有的行为，只是补上了长度维度）
与**明确的开工指令**（且默认处于 shadow）。语义层面的阶段切分仍然是观察项：
有接口、有开关、有日志，但没有经过校准，不参与实际切分。
