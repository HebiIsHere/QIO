### 定向验证入口本身是坏的（先修入口，这是它的必要前置步骤）

* 首次派发 `targeted-verify.yml`（run 38286554304，`windows` 单项）**不是测试失败**：
  job 在第一步就报 `Can't find 'action.yml' … Did you forget to run actions/checkout before running your local action?`
  —— 该工作流每个 job 的第一步就是 `uses: ./.github/actions/verify-checkout`，
  而**本地 action 必须先在仓库里签出才能被加载**：鸡生蛋问题。
* 这不是本分支特有：`targeted-verify.yml` 与 `action.yml` 在 **tag 与 main 上逐字相同**（`git diff` 为空），
  且 2026-10-11 的那次派发（38150350556）同样是 failure。
* 修入口（本轮提交）：在每个用到本地 action 的 job 前面加一步引导签出
  （`actions/checkout@v5` + `ref: ${{ needs.verify-sha.outputs.sha }}`）；
  **SHA 证据仍由 verify-checkout 自己产出**（它再签出一次并断言 `git rev-parse HEAD`），
  断言逻辑一行未改、也没有放松。`ci.yml` 未动。
* 该入口应同步回 main（本次只在本分支修，避免动 main；已在交付报告里列为待办）。
* **第二次派发又暴露第二个入口缺陷**（仍然不是测试失败）：引导签出生效、SHA 断言也通过
  （requested == actual == 派发 SHA），但 `scripts/targeted-verify/verify_sha.py` 在
  windows-latest 上打印中文证据行时 `UnicodeEncodeError`（cp1252）直接崩 ——
  `ci.yml` 各 job 早就设了 `PYTHONIOENCODING: utf-8`，而**这个本地 action 没设**。已补上同一条。
* 另有一条使用陷阱（值得写进文档）：`gh workflow run ... -f ref=<branch>` 里的 `-f ref` 只是**输入**，
  工作流文件本身来自 `--ref`（默认 default branch）。第一次修正后的派发仍用 main 的旧工作流，
  必须 `--ref <branch>` 才会跑本分支修好的版本。
