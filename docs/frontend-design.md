# 前端设计（星球架构）

版本：v1（2026-08-03，用户逐点确认）
前置约束：docs/frontend-requirements.md（硬要求）
后端基准：docs/architecture.md

## 1. 页面结构（2 页）

- 对话页：主场景，唯一常驻
- 设置页：凭据（资产）+ 偏好（分区）
- 设计原则：用户尽可能专心在对话上；对话页只保留高频操作
- 补充：凭据异常状态在对话页状态条轻量提示（revoked/预算耗尽），点击跳设置页

## 2. 星球核心概念（话题星球）

### 2.1 职责定位（用户确认）

- 星球承担的唯一职责：**呈现相关性**——话题间的关联通过 3D 空间邻近表达（聚类、聚集、大陆感），这是列表无法做到的
- 星球不承担搜索导航的主要职责：查询/定位由右侧简明列表 + 搜索承担
- 双层通道分工：星球 = 相关性可视化；列表 = 查询定位

### 2.2 空间模型

- 真 3D 球体；话题 = 球面地点
- 相似话题聚合为地区/大陆（视觉分组，基于话题指纹相似度）
- 位置惰性：地点创建后位置固定（新地点放最相似话题邻近空位，永不重排已有地点）
- 冷热分层：冷话题（阈值可配置，默认约 90 天无活动）离开星球表面进档案区，列表/搜索可达，可召回
- 默认视角固定：正面呈现当前活跃/相关层；旋转可探索背面（档案层）

### 2.3 导航交互

- **意图驱动自动导航**：用户通过列表/搜索/点击表达意图，球体自动旋转定位到目标话题并放大——球运动由系统完成，用户不手动找
- **手动拖动并存**：用户可自由拖动旋转浏览，不被自动导航限制
- 交互原则：球不依赖用户旋转，球服务用户意图；手动旋转是探索手段

### 2.4 实体

- v1：实体不占星球位置，作为话题地点上的标记（点击标记可搜索跨话题提及）
- v1.5：实体星球视角（数据同源：mention 边 + entity_ids 共现计算），与话题星球并列，切换动画复用

## 3. 对话页组成

- 消息流（虚拟滚动，长对话不卡）
- 输入区 + 记忆强度滑块（注入预算控制）
- 悬浮球（见 §5）
- 状态条：SSE 连接、CAPABILITY 三态、FALLBACK 横幅、凭据异常提示
- 模态层：审批弹窗（工具创建/凭据授权/高影响知识）、工具创建向导（提案解释 → 测试结果 → 审批 → 结果）
- 注入指示：MEMORY_INJECT 事件在消息流中以来源标记呈现

## 4. 星球页布局

```
┌──────────────────────────────┬─────────────────────────┐
│ 星球主体（左/中）             │ 右侧面板                │
│                              │                         │
│ 3D 球体，可拖动/缩放          │ 简明话题列表（查询通道）  │
│ 当前话题高亮 + 相机自动定位   │ 选中话题详情：           │
│                              │  片段列表（时间线）      │
│                              │  片段内消息预览          │
│                              │  话题属性（名称/关键词）  │
│                              │  相关实体（标记）        │
│                              │  知识子域条目            │
│                              │  "从这里开始" 按钮       │
└──────────────────────────────┴─────────────────────────┘
```

### 4.1 "从这里开始"语义

- 上下文最小单元始终是话题，不是片段
- 选择片段 = 注意力偏置：提示词发生变化，让模型注意力集中在该片段
- 后端现状（截至 2026-09-12）：注入检索已支持**话题级**亲和（`anchor_topic_id`）；
  **片段级**的 `anchor_fragment_id` 偏置尚未实现——选中片段目前只影响提示词，
  不改变记忆检索权重。缺口记录在 `docs/status.md` 的「尚未完成」。

### 4.2 编辑边界（不可越界）

- 记忆原文：append-only，只读
- 可编辑：话题属性（名称/关键词）、知识条目（revoke/更新，走状态机）、记忆摘要修正（作为纠错反馈触发知识域更新，不直接改写）
- 面板必须清晰区分可编辑区与只读区

## 5. 悬浮球（微缩星球）

- 形态：对话页悬浮的微缩星球，即"软件图标"级视觉资产
- 双重职责：入口 + 位置指示器（微缩球面高亮当前话题位置）
- 位置策略：可拖动、贴边收纳
- 与软件图标联动：同一 3D 场景离屏渲染生成图标资产（注意小尺寸简化轮廓）

## 6. 动画架构与原则

- **单一 3D 场景 + 相机状态**：悬浮球 = 远景相机，全屏星球 = 近景相机；切换 = 相机推进/拉远，空间连贯无重建
- 动画着力于**运动质感**（推进、惯性、缩放、缓动），不做光污染/粒子雨等持续性特效
- 时长：相机过渡 400–700ms；动画是导航过程不是等待
- 性能分级：对话页悬浮球低帧率（静态帧 + 交互动画），全屏全帧率；GPU 不可用自动降级（关后处理/减粒子），保证不崩

## 7. 设置页

- 偏好区：模型端点、记忆强度默认值、冷热阈值、行为开关
- 凭据异常提示与对话页状态条联动

## 11. v3 修订（2026-09-15，第四阶段：视觉统一 / 交互收口 / 动效语言）

完整规范：`docs/superpowers/specs/2026-09-15-visual-language-phase4-design.md`。
本节只写「改了什么」，避免同一套规则两处维护。

### 11.1 动效语言：三层

核心定义 = **非线性、阻尼控制下的缓动弹性、适度惯性、连续收束**。要避免的是两个极端：
机械线性（全站一条曲线）与游戏化弹跳（多次回弹、过冲过大）；「全局瞬切」同样不可接受。

- **高频**（80–180ms，`--mo-1-*`）：Button / Toggle / Hover / 选中 / 保存→已保存 / Tab / 展开收起 /
  列表项状态 / 卡片局部状态。要短、原位、少位移、不拖沓。
- **中频**（200–280ms，`--mo-2-*`）：打开 Topic Detail / 展开 Fragment 原文 / 侧板 / Tool Creation 状态推进 /
  局部编辑进出 / Approval 详情 / 返回 Conversation。更柔顺、更完整的缓动，无强烈回弹。
- **低频**（`--mo-3-*`）：Planet 入口展开 / 退出收拢 / 关键空间级过渡。这里才是「优雅预算」的主要支出处。

曲线刻意保持少：`--ease-1` / `--ease-1-out` / `--ease-2` / `--ease-2-out` / `--ease-3-in` /
`--ease-3-settle`（约 3% 单次柔和过冲，不是 bounce）/ `--ease-3-out`。
**同一层共享曲线**，不为单个组件发明 easing；Planet 的曲线不得被复制到按钮与列表上。
v2 的 `--dur-*` / `--ease` 全部降级为别名，指向新的分层令牌。

### 11.2 Planet 连续体

**入口小球 = 全屏 Planet 的抽象压缩态**，与全屏 Planet 是同一个对象的不同尺度状态，
不是「按钮 + 页面」。两者共享同一套几何（球体轮廓 + 3 层融合环）、同一套数学
（`frontend/src/planet/sdfRings.ts` 的 `levelField` / `smin`）、同一套颜色令牌与同一套生命感；
小球不承担信息展示（不显示数量/标签/进度）。

- 进入三阶段：**A 入口激活**（小球细节增强、周边界面退后）→ **B 体量展开**（同一个对象从入口矩形
  连续长大到全屏构图，话题点密度 0→1）→ **C 场景接管**（玻璃浮层进入、话题可交互）。
- 退出严格反向：交互层降密度 → 浮层收回 → 回到抽象态 → 体量收缩 → 回到入口**当前位置** → 重新成为小球。
- 不允许「小球淡出 + 大 Planet 淡入」这类伪连续，也不允许 Planets 像页面跳转/模态框那样进出。
- 保留既有约束：聚焦距离 2.25、球体结构、融合环内外粗细参数不变；本阶段**不引入程序化构筑物**。

### 11.2.1 虚空、画布与遮罩（2026-09-20 修订）

> 2026-09-20 二次修订（用户要求）：**入口小球改为真实星球渲染**。
> 关闭星球时不再把星球层隐藏或暂停，而是把同一个场景缩到入口尺度常驻渲染
> （`.planet-view.ball`，与全屏星球同一个 canvas、同一个渲染器），平常慢速自转（~15fps 低功耗），
> 展开完成后聚焦到当前在聊的话题点。代价：three.js 会在对话页加载并常驻（仍然懒加载 + 空闲挂载）。
> WebGL 不可用时退回 `PlanetOrb`（2D 压缩态），不假装是同一个渲染。
> 另外融合环是「按屏幕像素定宽」的，整层缩到 ~0.12 倍时环会被缩没，所以按缩放加了环宽补偿
> （小球上约 1.7px，长到满屏回到 5/3.25/2px）。

星球页的「虚空」是设计令牌 `--planet-void`（暗 `#0f0a10` / 亮 `#f4f1ec`），由**铺底**绘制；
WebGL 画布本身是透明的（`alpha: true`、不设 `scene.background`），球体之外的像素没有颜色。

这样做的原因：入口小球长大成 Planet 时整个星球层会被缩放到小球尺度，画布若自带一块不透明底色，
缩放中就会露出矩形边界。透明清屏之后，任何尺度下都不存在「画布矩形」，
原先为遮住它而临时加的 CSS 圆盘遮罩已经删除（探针 S2.6 守着这条）。

另外，展开动画要等「话题数据装配完 + 连续几帧帧间隔恢复正常」再开始：
冷启动会把主线程阻塞一段，动画在那段时间里一帧都画不出来 —— 用户看到的是星球直接跳出来，
而不是从小球长大（2026-09-20 实测发现并修掉）。

### 11.3 材质：晶体玻璃（不是磨砂）

高层级浮层需要的是**晶莹剔透、薄水晶感、高透玻璃感**：高透明 + 低雾化 + 轻微背景折射感 +
细致的边缘厚度感 + 极轻冷暖边分离 + 内外层亮度差，整体克制。
禁止重雾化毛玻璃、强烈珠宝感、炫目彩虹边、塑料高光片。

玻璃只用于「把某一层表达成悬浮在场景中的信息层」：Planet 周围浮层、轻量信息卡、关键确认层、
少量局部悬浮 UI。**不用于**全部消息、所有按钮、所有列表项、长文本主体与高频输入表单。

### 11.4 组件与反馈

- 视觉收敛到少量原语（`frontend/src/styles/base.css`）：Button / Card / Panel-Floating / Confirm /
  InlineEdit / Feedback / Tag-StateBadge / ListRow / Toolbar。新功能不再自带一套视觉语法。
- 反馈分四级：字段级 / 组件级 / 任务级 / 全局级。**成功更短更局部，失败更清晰更持久**；
  多数成功只需「按钮 → 处理中 → 已保存 → 恢复」，不做无意义 Toast。
- 浏览器原生 `confirm` / `alert` / `prompt` 全部由 QIO 确认层取代，确认层按危险程度分档
  （inline → popover → 轻量浮层 → 模态），高风险动作的确认按钮不使用品牌主操作色。
- **默认阅读、按需编辑**：Knowledge / Entity / Topic Detail / Settings 复杂区域默认以阅读为主，
  编辑在局部发生，退出后恢复阅读态；阅读态不常驻铺满输入框与危险按钮。

### 11.5 reduced-motion 语义（行为变更）

旧实现把所有 `transition/animation` 时长归零 —— 结果是状态变化全部瞬切，连续性丢失，
与「每一个状态变化都应有连续性」直接冲突。新语义：

1. **保留**必要的淡入淡出与全部状态文字（时长压缩到约 90ms，仍是一次看得见的过渡）；
2. **移除**位移、缩放与弹性：`--shift-*` 归零，`--ease-3-*` 退化为标准曲线；
3. JS 补间（星球相机）读同一份 `html[data-motion]`，走最短路径；
4. 功能不依赖动画事件；系统偏好仍可被设置里的「标准」显式覆盖。
