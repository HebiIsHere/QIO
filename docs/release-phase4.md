## 1. 第四阶段修改摘要

### 设计系统

- 建立**设计令牌 v3**（`frontend/src/styles/tokens.css`）：三层动效时长、曲线集、位移令牌、
  晶体玻璃令牌、状态层（hover / selected）、技术信息字号、星球虚空色。
- v2 的 `--dur-*` / `--ease` / `--press-shift` **全部降级为别名**，指向新的规范名
  （`--dur-planet-in:var(--mo-3-expand)` 等），既有组件不改一行代码即获得新分层。
- 组件原语落到 `frontend/src/styles/base.css`：Card / Row / Toolbar / Tag / StateBadge /
  InlineEdit / Feedback / Floating / Glass / Confirm + 过渡工具类（fade / rise / list / collapse / swap）。
- 新增 `--planet-void`：WebGL 场景背景（`scene.background`）与星球页铺底**同源**，
  这是「球体外围不能出现一块颜色不同的矩形画布」在代码层的保证。

### 动效系统

- 高频 / 中频 / 低频三层，各有一组时长令牌与曲线（共 7 条曲线，刻意保持少）。
- 旧 `--ease-out` / `--ease-in` 收敛进曲线集（分别对应「进入的减速」与「离开的加速」）。
- 星球开合改为**分段编排**：A 入口激活 → B 体量展开 → C 场景接管；退出严格反向。

### Planet 连续体

- 新增 `components/planet/PlanetOrb.vue`：入口小球不再是 SVG 椭圆环，而是**用 canvas 画同一套
  融合环距离场**的 Planet 压缩态（正交投影 + `levelFieldDir` + 2× 超采样）。
- 新增 `planet/ringField.ts`：把距离场数学抽成**无依赖**模块，`sdfRings.ts`（three 版，测试用）
  与 `PlanetOrb.vue`（不能引入 three）用**同一个函数**。这既是性能约束（three.js 不进首屏 chunk），
  也是「小球与全屏 Planet 是同一个对象」在代码层的依据。
- 新增 `composables/planetContinuum.ts`：入口与全屏共享的阶段状态（activating → expanding → ready /
  collapsing → returning → idle），带代号（epoch）防止迟到回调改回新一次打开的状态。
- `usePlanetScene` 新增 `setReveal(t)`（信息密度：0 = 抽象态，1 = 完整 Planet）与
  `sphereScreenRect()`（球体在屏幕上的真实中心与半径）。

### 晶体玻璃材质

- `--glass-*` 令牌（暗/亮两套）+ `.qio-glass` / `--chip` / `--panel` 原语：高透低雾 + 边缘厚度
  （顶部内高光）+ 内外亮度差 + 极轻冷暖边分离（左右边各一条 ≤0.18 的色偏，不是彩虹渐变）。
- 只用在 Planet 周围浮层：退出控件、话题悬停/选中标签、HUD、加载与错误条。

### 组件统一

- 卡片家族（Approval / Tool Creation / Subagent / 知识候选 / 工具调用）统一为
  **`.qio-card` 骨架 + `data-state` 原位状态 + `.qio-state` 徽章 + 真实高度过渡的展开详情**。
- 工具卡与工具创建卡的「展开详情」从 `v-show` 瞬切改成 `0fr → 1fr` 网格行过渡。
- **凭据卡也按同一原则收口**（2026-09-20 补）：一张凭据默认只给结论（名称 / 状态徽章 / 掩码 /
  预算 / 模型 / 版本）与两个入口（详情、管理），7 个管理动作收进可展开的「管理」区，
  收起时同时 `inert`（不可见也不可聚焦，键盘不会掉进看不见的按钮里）。

### 反馈统一

- **7 处浏览器原生确认全部替换**（`views/PlanetView.vue` 1 处、`views/SettingsView.vue` 3 处、
  `components/planet/KnowledgePanel.vue` 1 处、`components/planet/EntityPanel.vue` 1 处，
  另有 1 处随重构一并消失），统一走新增的 `components/ui/QConfirm.vue`（inline / popover / layer 三档）。
- 归档类动作的确认文案改成「动作 + 影响 + 后果」（例如「归档后它不再参与回答，也不会被删除」）。
- `components/ContinueBar.vue` 里「提交失败只写 console」改为就地可见、可重试的失败反馈。
- **失败文案分层**（2026-09-20 补）：数据/详情加载失败的首行只说人话（「星球数据加载失败」），
  接口路径、状态码与原始响应收进可展开的「技术详情」——实测截图里首行原本是
  `/api/planet/overview -> 500: {...}`，那是给排查看的。

### Knowledge / Entity 重构

- 两处都改成**默认阅读、按需编辑**：管理动作（修正 / 归档）默认退场，`hover` / 键盘聚焦 / 触屏才出现；
  点「修正」就地进入 `.qio-inline-edit`，取消即丢弃草稿。
- 状态底色统一到 `.qio-state` 的语义档（ok / warn / quiet），分类与关键词改用 `.qio-tag`。
- 实体卡从「一屏输入框」变成「摘要 + 别名 + 属性 + 关系」的字段组阅读态。
- Topic Detail 的知识条目同样改成阅读态 + 就地修正 + 就地确认归档。

### Approval / Tool / Subagent 重构

- Approval：`.modal` 纳入 `.qio-card` + `data-state`，风险与验证标签改用 `.qio-state`；
  按钮尺寸从「18px 圆角 + 26px 内边距」改回统一按钮原语（高度 34 / `--r-md`）。
- Tool Creation：阶段徽章改用 `.qio-state`，失败/成功行改用 `.qio-feedback`，详情展开有过渡。
- Subagent 卡与工具卡共用同一骨架与状态徽章；状态推进用 `data-state` 表达，仍是同一张卡。

### 可访问性

- **重写 reduced-motion 语义**：不再把所有时长归零（那会让状态变化全部瞬切），改为
  90ms 保留淡入淡出、位移令牌归零、低频弹性曲线退化为标准曲线。
- 系统偏好可被设置里的「标准」显式覆盖（`:root:not([data-motion="standard"])`）。
- `QConfirm` 的 layer 档：`role="dialog"` + `aria-modal` + `aria-labelledby` + 焦点陷阱 +
  Esc 取消 + 关闭后焦点归还触发元素；危险动作的确认按钮用中性实心，不用品牌主操作色。
- 浮窗贴靠（`useFloatingWindow`）的收尾时长改为**从 CSS 令牌读**，reduced-motion 下同一份值生效，
  避免「动画早结束了类名还挂着 / 位移没到就判定完成」。
- **星球的虚空由铺底提供，画布本身透明**（2026-09-20 补）：WebGL 用 `alpha: true` 且不设
  `scene.background`，球体之外的像素是透明的 —— 缩放中的画布不再可能露出一块矩形底色，
  原先为了遮住这块底色而加的 CSS 遮罩已经删掉。

## 2. 原有问题：原因与修改方式

| 问题 | 原因 | 修改方式 |
| --- | --- | --- |
| 同一个产品里存在多套完成度 | 各模块各自发明圆角、字号、状态底色与按钮尺寸 | 建立令牌 v3 + 组件原语，并把卡片家族收敛到 `.qio-card` + `data-state` + `.qio-state` |
| 动效层级错误（不同重要性的动作质量接近） | 全站只有两条曲线、时长档位混用 | 三层时长 + 7 条曲线；旧名降级为别名，同层共享曲线 |
| 入口小球不是 Planet 的压缩态 | Dock 是手绘 SVG 椭圆环，与 WebGL 星球是两套视觉 | 压缩态改用同一套距离场数学渲染；`ringField.ts` 成为两侧共用的数学来源 |
| 进入 Planet 像页面跳转（小球淡出 + 大球淡入） | 两个组件各自计时、各自淡入淡出 | 共享阶段状态 + 从**入口矩形**连续长大（实测 scale 0.13 → 1.00），退出严格反向 |
| 玻璃材质不像透明介质 | 只有零散 `backdrop-filter`，缺少边缘厚度与内外亮度差 | 晶体玻璃令牌 + `.qio-glass` 原语，只用在高层级空间浮层 |
| 界面「管理感」太强 | Knowledge / Entity / Topic Detail 默认铺满输入框与危险按钮 | 默认阅读、局部编辑；管理动作用 hover / focus / 触屏揭示 |
| 反馈各自为政 + 原生 confirm | 有的用 Toast、有的写顶部、有的只 `console.error`；7 处直接用 `window.confirm` | 统一 `.qio-feedback` 四级 + `QConfirm` 三档确认层；失败就地可见并可重试 |
| 状态切换不连续（瞬切、跳变） | 展开详情用 `v-show`、列表增删直接重排 | 过渡工具类 + 真实高度过渡（`0fr → 1fr`）+ 列表 `move/enter/leave` |
| reduced-motion 下失去连续性 | 旧规则把所有 `transition/animation` 时长归零 | 改为「保留淡入淡出 + 去掉位移与弹性」，时长压到 90ms |
| 星球画布在缩放中露出矩形边框 | 画布自带场景背景色，与页面底色不一致 | 新增 `--planet-void` 同源给场景与铺底，并在转场期间把画布遮罩成球体圆盘 |

## 3. 动效系统

| 层 | 令牌 | 时长 | 曲线 | 使用位置 |
| --- | --- | --- | --- | --- |
| 高频 | `--mo-1-press/state/fast/exit/menu/wide` | 80 / 150 / 140 / 150 / 170 / 180ms | `--ease-1`、`--ease-1-out` | 按钮、开关、hover、选中、Tab、工具卡局部状态 |
| 中频 | `--mo-2-in/move/out/wide` | 240 / 210 / 200 / 280ms | `--ease-2`、`--ease-2-out` | Topic Detail、片段原文展开、侧板、局部编辑进出、卡片详情展开 |
| 低频 | `--mo-3-prepare/expand/settle/collapse` | 180 / 520 / 220 / 420ms | `--ease-3-in`、`--ease-3-settle`、`--ease-3-out` | Planet 入口展开与收拢（唯一允许使用弹性曲线的地方） |

「优雅弹性」的定义（实现层）：`--ease-3-settle = cubic-bezier(.24,1.04,.32,1)` ——
单次约 3% 过冲后收紧，**不是 bounce**；测试里锁死了「y1 必须 > 1 且 < 1.12」这条边界。

## 4. Planet 连续体

**入口小球如何定义**：它是 `PlanetOrb` 渲染的 Planet 压缩态 —— 正交投影下，用与全屏星球同一个
`levelFieldDir` 计算 3 层融合环（内粗外细），颜色只读 CSS 令牌，低频呼吸（约 3.5fps）。
它不显示数量、标签或进度：小球不承担信息展示。

**如何展开**：

1. 打开那一刻读入口矩形（`[data-planet-entry]`）与球体的真实屏幕半径，算出起始缩放
   `k = 入口半径 / 球体半径`（实测 ≈ 0.13）与位移；
2. 星球层先**无过渡**地落到这个位置与尺度（`data-stage-k` 可观测），下一帧才打开过渡
   （否则冷启动时的低帧率会让浏览器把这次赋值当成「从 identity 追到小球尺度」）；
3. A 阶段铺底淡入、悬浮球交棒；B 阶段缩放过渡到 `scale(1)`，同时信息密度 0 → 1
   （话题点、网格、选中环、标签按密度出现）；C 阶段玻璃浮层进入、话题可交互。

**如何收回**：先降密度与收回浮层（相机轻微后撤）→ 转场到 B 的反向：缩放回**关闭那一刻重新读取**的
入口矩形（悬浮球可能已被拖走或贴边半隐藏）→ 恢复常态阶段，悬浮球在同一位置接住它并给一次极轻的接收反馈。

**为什么是同一个对象**：同一套距离场数学、同一套颜色令牌、同一套环结构；转场是这一层的
`transform` 与信息密度在变化，不是两层交叉淡入淡出。实测（同一脚本多次运行，按区间看待）：
进入 `scale 0.129 ~ 0.132 → 1.000`，退出 `scale 1 → 0.15 ~ 0.18`。

## 5. 晶体玻璃材质

**用于**：Planet 周围的退出控件、话题悬停/选中标签、HUD、加载与错误条。
**不用于**：消息正文、全部按钮、列表项、长文本主体、高频输入表单。

**如何避免变成「普通高光玻璃 / 重雾毛玻璃」**：

- 底色是**极淡的渐变**（暗色下白色 7.5% → 2.8% 再带一点品牌色），不是深色块；
- `backdrop-filter: blur(10px) saturate(118%)` —— 模糊半径刻意小（低雾化）；
- 边缘厚度 = `inset 0 1px 0 rgba(255,255,255,.22)`；内表面亮度差 = `inset 0 0 0 1px rgba(255,255,255,.045)`；
- 折射暗示 = 左边一条暖色（品牌侧）、右边一条冷色，透明度 ≤ 0.18，**不用彩虹渐变**；
- 亮色主题单独一套（净白背景上靠更亮的边界与更弱的色偏，而不是「加白」）。

## 6. 统一组件语言

**核心原语**（`frontend/src/styles/base.css`）：
`.qio-btn`（primary / danger / danger-solid / quiet / success / mini / busy）、
`.qio-card`（quiet / focus + `data-state`）、`.qio-row`（is-active / is-selected）、
`.qio-toolbar`、`.qio-tag`、`.qio-state`（ok / warn / err / info / quiet）、
`.qio-inline-edit`、`.qio-lift`、`.qio-feedback`、`.qio-floating`、`.qio-glass`、
`.qio-confirm`（inline / popover / layer）+ 过渡类 `.qio-fade/rise/list/collapse/swap`。

**状态表达方式**：hover 只加一档亮度（`--layer-hover`）；selected 用 `--layer-selected` + 描边，
与 hover 可区分；focus-visible 统一焦点环；disabled 一律降透明度且不改文案冒充可点；
卡片状态用 `data-state` 属性表达 → 状态推进**原位发生**。

**反馈方式**：字段级（就地 inline）/ 组件级（卡片内一行，成功约 1.6s 回收、失败保留）/
任务级（卡片状态推进）/ 全局级（顶部安静状态行）；危险动作统一走 `QConfirm`，
按危险程度选择 inline / popover / layer，高风险的确认按钮不使用品牌主操作色。

## 7. 可访问性与 reduced-motion

**被降级的动画**：位移（`--shift-*` 归零）、低频弹性曲线（`--ease-3-*` 退化为标准曲线）、
所有时长压到 90ms（但**不归零**）。Planet 三段编排在 reduced 下跳过，直接到终态。

**连续性如何保留**：淡入淡出仍然发生（90ms 是一次看得见的变化），状态文字一律保留
（例如「收起中…」「运行中」「已归档」），所以「发生了什么」仍然可读；功能不依赖动画事件
（Planet 的体积过渡由状态机决定，不由 transitionend 决定）。

**keyboard / focus**：`.skip-link`「跳到输入框」保留；`QConfirm` 的 layer 档有焦点陷阱与焦点归还；
话题列表、实体列表可用 Enter/Space 选择；`Esc` 的分层语义（先收边栏、再收星球）与审批窗口的
「Esc 不做决定、按最上层处理」都保持原样。新增浮层（退出控件）有 `aria-label`，禁用态语义不变。

## 10. 剩余问题

### 10.1 用户实测反馈修掉的两个动画问题（2026-09-20）

**问题一：打开星球时看不到「变大」**（只有第二次及以后；首次打开正常）。

- 根因：`sphereScreenRect()` 用 `canvas.getBoundingClientRect()` 量球体在屏幕上的尺寸，
  而 canvas 在 `.planet-stage` 里，那一层带着 `scale()` —— 第二次打开时层上还残留着上一次的
  `--stage-k`（≈0.14），量到的画布高度只有真实的百分之十几，算出的起始缩放被 clamp 到 ≈1，
  于是「星球直接出现」。
- 为什么之前没测出来：探针每次都是**全新页面只打开一次**，首次打开永远是干净的。
  现在补了 S2.7（收起后再打开）来守这条。
- 修法：尺寸与位置改用**布局值**（`offsetWidth/offsetHeight` + `offsetParent` 链），
  它们不受 transform 影响；球体屏幕半径改为按投影三角计算（`asin(R/d)`）。
  实测起始 `data-stage-k` 从 0.951 变成 0.120（用户浏览器里复验同样通过）。

**问题二：对话页没有随星球变大/变小而渐隐渐显**。这一条有**两层**原因，第一层修完还是不对，
第二次才挖到底：

1. 铺底（把对话页盖住的那层虚空）用的是 `entered` 类，在**阶段 A 就置位**，而阶段 A 之后还要等
   话题数据与渲染就绪 —— 铺底在自己的 180ms 里就走完了，等星球真正开始长大时对话页早就黑掉。
   修法：新增 `curtain` 状态，由脚本在**长大的同一刻**置位、**收缩的同一刻**撤掉，
   时长分别等于 `--mo-3-expand` / `--mo-3-collapse`，曲线与长大共用 `--ease-3-settle`。
2. **真正的元凶**：`.planet-view` 这一层自己带着 `background: var(--bg-base)`（不透明）。
   它一挂载就把对话页盖死了 —— 画在它**上面**的铺底再怎么淡都看不见，所以第 1 步等于白做。
   修法：整层背景改为 `transparent`，让「盖住对话页」只由铺底这一层承担。

为什么第一次没测出来：探针当时量的是 `::before` 的 `opacity`（代理指标），它一路正常，
但真实可见性由父层的不透明底色决定 —— 典型的假阳性测试。
现在换成**直接看像素**：打开前量一次对话文字区域的明暗差，星球还小的时候再量一次。
修复前实测 `204 → 0`（对话页完全没了），修复后 `204 → 135`（对话页明显还在，只是被压暗）。

### 10.1.1 收起时的「第一段缩小」：相机后撤的遗留物（2026-09-20）

用户反馈「星球收起有两段动画：一段先缩小一点，第二段才缩回对话页小星球」。

- 根因：收起的第一段里有一记 `planet.pullBack(0.45)` —— 相机轻微后撤。那是**旧编排**
  （收势 + 整层淡出，见 v2 规范 §12.5.1）的遗留物：那时需要先退一点再淡出。
  改成「同一个对象收拢回入口」之后，它就成了多余的第一次缩小：相机后撤让球体看起来变小，
  紧接着星球层再缩回小球。
- 量化：探针在收势阶段（星球层 scale 仍为 1）采样球体屏幕半径，漂移 **16.7%**（377~453）。
- 修法：收势阶段不再动相机。现在收势只做「玻璃浮层退场 + 信息密度回到抽象态 + 对话页开始渐显」，
  体量收缩只有一段。修后探针实测漂移 **0.0%**（453~453）。
- 守它的验收：S2.10（`scripts/baseline/qa/phase4.mjs`）。

### 10.1.2 入口小球改为真实星球渲染（2026-09-20，用户要求）

用户要求：对话页上的星球入口**直接用真实星球渲染**，平常缩小时微微旋转，放大后聚焦到当前在聊的话题点。

这就是原设计（v2 §6「单一 3D 场景 + 相机状态：悬浮球 = 远景/小尺度，全屏 = 近景」）的落地，
第四阶段早先的实现是折中版（入口另画一个 2D 压缩态），现在换掉：

- **同一个场景、同一个渲染器**：关闭星球时不再 `display:none` / 暂停，而是把整层缩到入口尺度
  常驻渲染（`.planet-view.ball`）。入口那枚按钮只负责点击、拖动、贴边与无障碍标签。
- **慢速自转**：球态连续运行，`planetGroup.rotation.y` 以 `dt*0.1` 自转（探针实测 1.5s 转过 ~0.1 rad）；
  帧率压到 ~15fps（低功耗），减少动画下不自转。
- **放大后聚焦当前话题**：展开完成时 `phase=ready` 且 `selectedTopicId` 就是会话里在聊的那个话题
  （探针 S2.11 断言 `selected` 非空）。
- **环宽补偿**：融合环的宽度是按屏幕像素定的（fwidth，设计值 5/3.25/2px），整层缩到 ~0.12 倍后
  像素宽也一起被缩掉 —— 实测三层环几乎消失，小球只剩一个空圈。新增 `uWidthScale` uniform，
  按当前缩放把环宽铺回去：小球上约 1.7px，长到满屏回到设计值（探针实测 2.83 → 1.00）。
- **球态也要真实数据**：融合环的形状来自真实话题点，没有数据就只有空圈（实测 `windowSize=0`）。
  所以进入球态会先取一次轻量数据（概览 + 第一批窗口），且**不聚焦任何话题**（球态要保持自转）。

**代价（必须说清楚）**：three.js 与 WebGL 场景现在会在**对话页**加载并常驻（此前只有打开星球才加载）。
缓解手段：仍然是懒加载（不在首屏 chunk）、空闲时挂载、正在跑一轮对话时不抢主线程、球态 15fps。
实测（无头软件渲染）空闲挂载耗时约 1.2–4s；真机上应当更快，但这是本改动实打实的成本。
WebGL 不可用时不置 `ballLive`，入口继续由 `PlanetOrb`（2D 压缩态）承担 —— 不假装是同一个渲染。

守它的验收：S2.1（入口就是这颗星球本身）、S2.11（收起后回到球态 + 真实话题形状 + 自转）、
S2.12（收起后对话页真的回来了）。

**打开延迟（2026-09-20 收尾）**：球态常驻之后，「已预热」的打开路径**不该再等一次数据刷新** ——
实测它把「点击 → 开始长大」拖到 1240ms、「点击 → 场景接管」拖到 1891ms（设计值约 920ms）。
现在分两条路：

- **已预热**（默认：入口小球已经喂过数据）：不在展开前等数据，直接按 `prepare → expand → settle`
  走完，**展开结束之后再聚焦当前在聊的话题**（这也正是用户要的顺序）。实测 391ms / 915ms。
- **未预热**（首屏直接点开 / WebGL 不可用）：仍然先等数据与渲染就绪，否则数据装配会和长大抢
  主线程，动画一帧都画不出来。减少动画两条路都跳过等待（实测 5ms 到场景接管）。

球态数据有 30s 保鲜期：回到球态时若超过就后台刷一次，既不阻塞动画，也不让小球长期陈旧。

**进入只剩一段动作（2026-09-20，用户实测「一段放大进入 + 一段回正」）**：

- 现象：打开星球时先放大进入、再回正，读起来是两段。
- 根因有两层：① 我把「聚焦当前话题」排在了展开**之后**（上一轮为了满足「放大后聚焦」）；
  ② 展开前还有一个 180ms 的「激活阶段」等待，把动作切成「等 → 长大 → 转向」。
- 修法：聚焦与长大**同刻开始、同刻收束**（聚焦时长直接取长大时长），
  并去掉人为的激活等待 —— 层与入口小球同帧可见，激活段只在**冷路径**
  （数据还没到）里真实存在，作为「小球等着内容」的停顿，不再是一段独立动画。
  顺带把「数据等待 + 聚焦」提到所有帧等待之前，动作之间不再出现可感知的空档。
- 守它的验收：S2.14（长大过程中的帧里，聚焦对象已确定且自转已经在动）。

**拖动松手后星球本体没跟着走 + 去掉入口文字标注（2026-09-20，用户实测）**：

- 现象：拖动入口小球松手后，「话题星球」四个字随贴边动画移动，但星球本体停在原地、过一会儿才
  「闪现」到贴边位置。
- 根因：球态跟随只挂在**属性观察器**（内联 `style` 变化）上，而贴边是 **CSS 过渡** ——
  内联 `left/top` 只在开始时改一次，过渡期间的每一帧位置变化不会触发观察器，球层自然停在原地。
- 修法：贴边补间期间（`fw-snapping` 存在时）逐帧跟随，过渡结束时再对齐一次并停表。
  实测贴边中球层与入口中心**逐帧 0px 偏差**；守它的验收是 S2.15。
- 同时按用户要求**移除入口的「话题星球」文字标注**（保留 `title` 与 `aria-label`，
  无障碍与悬停提示不受影响）。

**入口小球「轮廓全是像素」（2026-09-20，用户实测 → 采用方案 A）**：

- 现象：缩小后的入口小球轮廓是一圈断续的像素点。
- 根因：球态当时是把**全屏尺寸的渲染结果**用 CSS `scale()` 缩到 ~10% 显示。
  那圈轮廓在 WebGL 里是 **1 个设备像素**宽的线（`LineLoop`，WebGL 忽略 linewidth），
  缩到 0.1× 后只剩 0.1px，采样大部分落空 —— 于是变成断续的点；融合环同理发糊。
- 修法（方案 A：让小球按**自己的分辨率**渲染，不做降采样）：
  球态把画布设成 `108px` —— 这个数不是随手取的：球体在画布高度里占 88.7%
  （固定 FOV 的投影比例），108 × 0.887 / 2 ≈ 48px，正好等于入口按钮的半径，
  于是球态 `scale ≈ 1.000`：既没有降采样也没有放大，展开那一刻的尺寸也严丝合缝。
- 踩到的坑（值得记）：`renderer.setSize()` 默认会把 CSS 尺寸写进 canvas 的**内联 style**，
  而内联样式优先级高于类规则 —— 结果「球态把画布设成球大小」的规则永远不生效
  （实测：选择器匹配、变量也解析，画布还是 1439px）。改用 `setSize(w, h, false)`，
  尺寸统一交给 CSS，渲染器只负责读 `clientWidth/Height` 设绘图缓冲。
- 顺带收益：球态渲染的像素量从 1440×900 降到 108²（低功耗更省）。
- 守它的验收：S2.16（画布=球尺寸、scale≈1）；S2.5 / S2.11 / S3.3 的判据也一并改成
  「回到球态 = 画布缩回球大小」，不再用「整层缩放很小」这个旧契约。

**球态为什么不像「等比例缩小」（2026-09-20，用户实测追问）**：

- 这是环宽补偿的副作用，不是渲染比例的问题：融合环按**屏幕像素**定宽（5/3.25/2px ≈ 球体直径的 0.6%），
  全屏时球体直径约 750px；小球只有 ~96px。为了「看得见」，我一度把小球上的目标宽度定成固定 **1.7px**
  —— 那占了小球直径的 1.8%，是相对粗度的 2.7 倍，于是小球看起来是一圈圈加粗的同心环（靶心）。
- 修法：环宽目标改成**跟随球体屏幕直径成比例**（0.75%），只在低于 **1.3px** 时才保底。
  实测球态相对宽度 1.35% vs 全屏 0.56%（比值 2.4 —— 保底那一档带来的）。
  同时把球态的 `reveal` 从 0.2 提到 0.55：小球保留话题点，读起来是「缩小的星球」而不是只有环的空壳。
- 取舍要写清楚：更接近严格等比例（比如 1.0px）会让三层半透明环叠加变淡、结构几乎读不出来
  （实测过），所以停了在 1.3px。这个数可以按观感回调（`ringWidthScaleFor` 里的 0.0075 / 1.3）。
- 守它的验收：S2.17（球态与全屏的「环宽 / 球体直径」相对值在同一量级）。

**收缩的最后一帧与静止球态「完全不同」（2026-09-20，用户实测）**：

- 根因：**密度不一致** —— 收起时把 `reveal` 设成 0.12（话题点几乎清零），
  而球态是 0.55（有点阵与网格）。于是回到对话页的那一瞬间，点阵和网格「突然冒出来」。
  尺寸其实是连续的（收缩终点屏幕直径 96px vs 球态 96–99px）。
- 修法：抽出 `BALL_REVEAL` 常量，「收起回到的抽象态」与「球态」用**同一个值**，只此一处定义。
- 量化验收（S2.18）：在球的位置固定取一小块，比「收缩动画最后一帧」与「静止球态」的平均像素差 ——
  修复后 **0.67/255**（≈0.26%，肉眼不可分）。
- 顺带把探针的测量方式改成**页面内逐帧记录**（`installPlanetTrace`）：之前用「点击后跨进程轮询」，
  软件渲染下单次往返能到几百毫秒，第一帧就已经落在长大后半段 —— 于是「起点是不是球那么大」
  这类断言会被测量误差判成失败（实测出现过 690px 的假起点）。现在量到的是真实的第一帧：
  S2.2 屏幕直径 **96px → 905px**、S2.7 第二次打开最小 **96px**。

**收起时右侧话题栏没跟着退场（2026-09-20，用户实测）**：

- 现象：打开星球 → 展开右侧话题栏 → 收起星球回到对话页，话题栏**留在对话页上**。
- 根因：入口小球常驻之后，收起不再是「整层隐藏」（`v-show`），而右侧面板的显隐只由
  `open` / `entered` 驱动 —— 于是它跟着球态一起留在屏幕上。
- 修法：① 收势阶段面板**退场**（宽度收到 0、透明度 0、不再接收指针），不再只是「降到 35%」；
  ② 球态下右栏一律不出现（承接收起动画的末态）。探针 S2.13 守着这条
  （修复前：面板宽 461、不透明 1；修复后：宽 1、不透明 0）。

**收缩尾段改在「球自己的分辨率」下渲染（2026-09-20，用户批准的下一步）**：

用户在看到「最后一帧与缩小状态不同」修好之后，批准了这条后续：**让收缩的最后一段直接在
球分辨率下渲染**。做完了，但过程里推翻了自己一次结论，两件事都记下来。

做法（`PlanetView.runCollapseMotion`）：

1. 体量收缩的前段仍然是原来的 CSS 过渡（全窗口画布 + `scale`）；
2. 屏幕上球直径降到入口球的 1.35 倍时（`TAIL_SWITCH_RATIO`），把星球层切成
   **入口小球那套布局**（画布 108px，见 `.planet-view.tail`）——
   只有画布的 CSS 尺寸等于它在屏幕上的尺寸时，才是真的 1:1（1 设备像素宽的轮廓线
   不会被降采样吃掉）；
3. 换布局的那一帧用**当前 computed transform** 反算出球此刻的屏幕球心与半径，再写回
   新坐标 —— 与 `alignStageToEntry` 同一套布局值算法，所以切换是几何精确的；
4. 之后由脚本每帧用**同一条令牌曲线**（`--ease-3-settle`，用
   `frontend/src/utils/easing.ts` 求值）继续推进到终点。
   换布局会打断 CSS 过渡，如果重新起一段过渡，曲线会在中途折一下（用户对「两段动画」
   很敏感）；继续用同一条曲线就没有这个问题 —— 视觉路径逐点相同，只是换了坐标系与分辨率。

为什么尾段要脚本接管而不是「最后直接换一次画布」：换布局就得重写坐标，重写坐标就得让
过渡从当前位置重新开始，于是曲线会折。

也试过「把绘图缓冲改小」（`setPixelRatio`）这条更短的路：**更差，而且坑不只一个** ——
画布内容是按它自己的 CSS 尺寸绘制的，缓冲小于 CSS 尺寸只会被放大；那次实验同时踩了
环宽补偿的换算基准（缓冲一变，`uWidthScale` 该给多少也跟着变），截图里的小球直接变成
一圈圈粗环，一度被我误读成「缓冲改小更糊」的证据。两个坑都记在这里：只有
「画布 CSS 尺寸 = 屏幕尺寸」才是真正的 1:1。

客观验收：

- 新增 **S2.19**：收缩尾段出现且画布就是球尺寸（108）；尾段最大半径 ≤ 入口的 1.45 倍；
  半径单调收；**球心偏离应有轨迹 ≤ 4px**（实测 **0.01px**）—— 换布局那一下没错位。
  这条判据刻意不用「单帧位移」：本机软件渲染帧间隔 p50=19ms / p90=90ms / 最大 281ms，
  一帧里球本来就可能走十几像素，用单帧位移会把掉帧判成错位。
- **S2.18** 顺带修掉一个测量错误：它以前用 CDP `Animation.setPlaybackRate` 只放慢 CSS，
  而脚本时间线照跑 —— 420ms 的收尾真的跑完了，过渡却只走了不到 5%，截到的「最后一帧」
  其实是刚起步的全屏构图。现在改用产品自带的 `?planetdemo=slow`（令牌与脚本时长一起放大）。
  修复后实测「收缩最后一帧 vs 静止球态」平均像素差 **1.1–4.1/255**（主要来自球态那点慢速自转）。

**必须说清楚的一点（我推翻了自己的静态结论）**：中途我用「冻结渲染循环 + 手动摆几何」的静态
对照图判断「全窗口画布渲染出来是虚线、球布局是连续细线」，并据此认为最后一帧明显更差。
但那是**冻结状态的假象**：过渡动画期间浏览器会按当前动画尺度重新栅格化，冻结之后不会，
于是静态图里出现了实际动画中不存在的断续。真实动画里量到的是：

- 收缩末段（屏幕直径 ~96px）的轮廓亮度与球态基本一致（最暗 20 vs 21、轮廓亮度 48 vs 50），
  也就是说**交接那一下的画质差本来就很小**（上一轮说的「肉眼基本看不出」是对的）；
- 当时我还声称「中间段有间歇性断续（暗采样 37–44%）」。**这条后来被 pilot 推翻了**（见 §10.5）：
  那个量法是沿 1 设备像素宽的轮廓采样一圈，圆稍微偏一点就整圈落在背景上 ——
  连静止的球态自己都会读成 41–88% 暗点。换成墨迹量以后，真实动画里两条路径逐档相同。

所以这一轮的净收益是**把最后一段的渲染质量钉死**（结构上保证 1:1、交接不换渲染路径），
而不是修掉一个原本就很明显的缺陷。中间段的间歇断续仍在，见下面「仍然没做完」。

### 10.2 顺手修掉的一个死结：失效的审批无法清除（2026-09-20）

实测触发：一条审批在后端已经没有记录（别处已应答 / 已过期）时，前端点批准或拒绝都是 404，
弹窗只会显示「可重试」，而重试永远不会成功 —— 用户被卡在一条处理不掉的待办上。

修法（不让它静默消失，但要给出口）：后端返回 404 时把该项标记为 `stale`，
弹窗改为只显示「知道了」并说明「这项确认已经有结局……未做出任何授权」，
点掉即从队列移除；其它失败（500 / 网络）**仍然保留待办并可重试**，这一点有单独测试守着。

### 10.3 验收脚本不再污染正在使用的页面（2026-09-20）

审批场景会 POST 一条测试审批事件到共享后端，而前端是 SSE 订阅：**所有打开着的页面都会弹窗**。
实测就是这么把「工具创建审批」弹到用户脸上、并盖住整页让后续点击全部失效的。
现在该场景默认不跑（计入「未运行」），需要时用 `QIO_QA_INJECT=1` 显式打开，并会打印提示。

### 10.4 这一轮修掉的四处「量法」问题（2026-09-20）

加 S2.19 的过程中，发现验收脚本自己有四处会把**正常行为判成失败**（或反过来量错东西）
的问题。它们都属于「代理指标骗人」，一并修掉：

1. **S2.18 用 CDP 只放慢 CSS**：脚本时间线照跑，截到的「最后一帧」名不副实（见 §10.1 末尾）。
   改成产品自带的 `?planetdemo=slow`。
2. **S2.9 追不上「星球还小」的那一瞬间**：长大的曲线是低频档柔性收束 ——
   0.25 的时间走完 78% 的路程，120–420px 的窗口只有 ~40ms，跨进程轮询整段错过（实测报「直径≈无」）。
   试过「CDP 文档级放慢」，但主线程被首帧重活占住时过渡照样跑完（实测循环启动时星球已到 797px）。
   最终改成**点击前装好观察者 → 过渡一出现就按住 → 手动拖动 `currentTime` 扫过长大过程 →
   停在球还小那一帧截图**：量的是真实存在过的画面，且完全可复现
   （实测定格在 292–300px，铺底不透明度 0.276，对话区对比度 148/204 —— 正是设计想要的关系）。
3. **S2.10 把尾段算进了「收势」**：尾段切到球布局后星球层 scale 又回到 ≈1，
   只按 `scale > 0.98` 过滤会把「确实在缩小的尾段」当收势，判出 88% 的假漂移。
   改成按连续体阶段过滤（`collapsing` 才是收势，`returning` 是体量收缩）。
4. **S2.15 用固定像素阈值判「跟随」**：贴边是 CSS 过渡（合成器推进），球层是 rAF 跟随，
   天然可能落后一帧；本机单帧位移能到 84px，「偏差 < 8px」必然误判。
   改成判**形状**：偏差不得超过「入口自己一帧走了多少」（实测超出量 0px），
   同时要求球层确实跟着走了几十像素。
5. **S2.2 / S8.4 的口径**：S2.2 的「至少一帧中间态」在软件渲染下会因采样落到两帧之间而假失败
   （实测 0 帧），改用 `?planetdemo=slow` 采样同一形状；
   S8.4 还在用旧契约「关闭后星球层隐藏」，而现契约是**回到入口球态**（那个小球就是这一层），
   判据改成「回到球态（或降级时确实隐藏）」。

改完这一轮跑：**PASS 42 · FAIL 0 · 未运行 3**（未运行的三条仍是审批注入与工具创建卡，
见 §10.3 与上一节的说明）。

### 10.5 pilot：把「缩小」搬进渲染器值不值得（2026-09-20）

在 §10.4 之后有人问：有没有更彻底的做法？有 —— **别再让合成器缩一张位图，改成缩放投影**：
把投影矩阵前两行乘以 `zoom`（w 分量不变，所以 `ndc' = zoom · ndc`，是真正的平面等比缩小，
不是相机后退那种会改变透视缩短的做法），位置用常量屏幕位移；画布始终不加 transform、
始终 1:1。这样理论上「任何一帧都不会被重采样」。pilot 用三条量法判它值不值得，结果是不值得：

1. **几何等价**（静态，同一目标直径、两条路径各渲染一次）：
   球的包围盒/球心一致到 1–5%；投影路径在目标 300px 时量到 302px、目标 96px 时量到 98px ——
   投影缩放确实是「平面等比缩小」，数学没错。
2. **实时墨迹量**（真实收缩 ×3 轮，按屏幕半径分档，取「阈值以上亮像素数 / 周长」）：

   | 屏幕半径 | 现状（缩放合成层） | 候选（缩放投影） |
   | --- | --- | --- |
   | 40–60px | 4.6（5 帧） | 4.5（4 帧） |
   | 140–220px | 2.9（2 帧） | 2.5（1 帧） |
   | 350–1000px | 18.5（3 帧） | 18.4（4 帧） |

   候选路径是「不可能被降采样」的对照组，它**没有**更多墨迹 —— 也就是说
   现状路径在真实动画里并没有被吃掉轮廓。反过来，同一套墨迹量在**冻结渲染**的静态对照里
   差 3–29 倍（96px 时 167 vs 4913），这说明断续只在「画面被冻住、浏览器不再按动画尺度
   重新栅格化」时才出现。**上一节那条「中间段间歇性断续」是假阳性，已改正。**
3. **帧间隔**（探针自身轮询负载下，两条路径同样受扰）：现状 p50=16ms / p90=163ms，
   候选 p50=34ms / p90=202ms。数字本身不公平（探针在抢主线程），但方向与预判一致：
   候选把动画的唯一推进者从合成器换成了渲染循环，主线程一忙就更明显。

**结论：不做这个改造。** 现状（合成器缩层）+ 尾段钉死 1:1 已经够用，而且不引入
「主线程一卡动画就卡」这个新风险。pilot 的插桩（`setProjectionStage` / `?planetproj=1` /
两个 DEV 钩子）全部撤回，探针脚本留档在 `scripts/baseline/qa/planet-flash-probe.mjs`
（它只依赖公开的 DEV 钩子与 CDP，不需要任何产品侧插桩）。要重做的话：`setProjectionStage`
约 40 行（把投影矩阵前两行乘 zoom、按 `ndc += d` 写常量屏幕位移），
探针按上面第 1、2 条的量法重建即可。

### 10.6 「缩小途中闪一下」——环宽补偿与布局错配（2026-09-20，用户实测）

用户反馈：「星球在缩小的途中动画出现了闪现」。逐帧抓合成画面后定位到**单帧渲染错配**：

**现象与证据**：用 `scripts/baseline/qa/planet-flash-probe.mjs`（CDP screencast 抓每一帧合成画面，
逐帧量球体粉色墨迹并存图）抓到的异常帧里，球**不是细环**，而是**一整块实心亮斑**
（同一位置相邻帧是正常细环；墨迹量比邻居高一个数量级，探针报 ×27）。
HUD/状态/DOM 读数全都正常 —— 这类问题只在像素上看得见。

**根因**：尾段切换布局那一帧，「谁来缩」与「环宽补偿按什么换」对不上。

- 环宽补偿 `uWidthScale` 是**调用方（视图）**按「当前整层缩放」算好再交给渲染器的；
  尾段把画布从 1439px 换成球自己的 108px 时，视图还没拿到新变换，交出去的仍是
  旧约定下的 ≈2.0（对应 0.13 倍整层缩放）；
- 而渲染器已经按新布局渲染（缓冲像素 = 屏幕像素）—— 5×2.0 = 10 个 buffer 像素的环
  在 1:1 下就是 10px 宽，于是那一帧画出一块实心斑；下一帧读到新变换才恢复正常。

**修法（结构性的，不是补丁）**：环宽补偿改成**渲染前按当时几何现算**
（`usePlanetScene.applyRingWidthCompensation`）：视图只交「环在屏幕上的目标宽度」
（`setRingScreenWidth`），倍数用渲染那一刻的 `画布 rect 宽 / 布局宽` 现推。
这样**任何**布局/变换变化都不可能再让两者错配 —— 包括这次这个，也包括将来再换布局。
顺带把尾段切换的顺序理顺：`.tail` 生效 → 量新布局 → 写新坐标 → 交环宽目标 →
**最后**才重建绘图缓冲补那一帧（此前补充帧发生在写坐标之前，是同一个错配的另一半）。

**验收**：

- 新增 **S2.20**：收缩全程逐帧抓合成画面，落点窗口内的球体墨迹不得比邻居高 3 倍以上
  （阈值是粗判；修复前那一帧的实心斑在探针里是 ×27）。为了量干净，量之前把铺底钉成全不透明 ——
  对话页的代码块语法高亮与球体是同一色相，不钉住就会把「粉色像素」量到控件上去（实测两次踩坑：
  整幅量到恒定值、按水平连续段量到 24px 的假环厚）。
- 逐帧画面复核：`node scripts/baseline/qa/planet-flash-probe.mjs <tag> --slow`，
  看异常帧 PNG —— 修复后尾段每一帧都是细环，没有向上的跳变。

**定位**：这是上一轮尾段改动**引入**的缺陷（换布局改了换算基准，而补偿倍数还是旧约定下的值），
不是第一阶段遗留问题。修法刻意做成结构性的 —— 「补偿倍数由渲染器在渲染时按当时几何现算」，
这一类错配从此不可能再出现；证据留在 S2.20 与逐帧探针两处。

### 10.7 打开时把「当前在聊的话题」转到正中心（2026-09-20，用户实测）

用户要求：「星球打开时，如果打开前目前的话题并未在最中心，则应该在打开的过程中旋转至中心」。

先按「先量再说」的规矩量三种打开场景（球态直接打开 / 面板开着再打开 / 冷启动直接点开），
球态自转 0.1 rad/s，等到当前话题明显偏离中心再打开：

- **旋转确实发生在长大过程中**：话题锚点从偏离 162px 收到 1px，收束点落在长大进度 96–99%
  的位置（也就是星球快长满时转正，看得见）；
- **终态确实是画布正中心**：三种场景的锚点偏离分别为 6px / 5px / 4px（误差来自焦点补间的收束精度）。

（量的时候先踩了一个坑：直接用选中标签的 `getBoundingClientRect()` 当话题位置，
量出来稳定偏 155px —— 标签自身有 `translate(46px, -50%)` 的 CSS 偏移，宽度一半又加上去。

### 10.8 演示慢放倍率改成可调（`?planetdemo=N`，2026-09-20）

用户要「慢放 10 倍仔细看」。原来的开关只支持 `?planetdemo=slow`（固定 3 倍）。现在：

- `?planetdemo=slow` → 3 倍（旧写法不变）；
- `?planetdemo=10` → 10 倍（1–50 之间任意数字）；
- 不带参数 → 真实时长。

实现要点仍然是**CSS 令牌与脚本时长用同一个倍率**：CSS 走 demoStyle 覆盖的 `--mo-3-*`，
脚本用 `tokenMs()` 读同一批令牌。实测倍率核对（同一台机器上量「点击 → 场景接管」与
「点击收起 → 回到球态」）：

| 参数 | 打开 | 收起 |
| --- | --- | --- |
| 无 | 595ms | 968ms |
| slow（3×） | 1601ms | 2281ms |
| 10 | 5262ms | 6347ms |

10× / 3× 的比值是 **3.29×（打开）/ 2.78×（收起）** —— 打开那一段接近理论值 3.33；
收起偏小是因为「等渲染缓过来」的几段帧等待（`waitForSmoothFrames`，上限 250ms）是固定开销、
不随演示倍率放大。这也解释了 10× / 常速只有 8.84×：常速那 600ms 里有一半是同一批固定等待。

### 10.9 收起时也转：转回「打开前的朝向」（2026-09-20，用户选定方案①）

用户要求「展开和收回的时候**同时**进行球的旋转动画」，并在三个候选里选定：
**反向转回打开前的朝向**，且旋转放在**体量收缩段**（不放收势段）。

做法：

- `usePlanetScene.markReturnOrientation()`：在 `runEnter` 最开始记下球体四元数。
  **必须在聚焦之前** —— 紧接着的聚焦会转动球体，记晚了就变成「转回聚焦后的朝向」。
- `usePlanetScene.rotateBack(maxMs)`：与体量收缩**同刻发起**（`runCollapseMotion` 开头、
  `alignStageToEntry` 之前）。时长按夹角缩放，形状与 `focusTopic` 的 `distanceFactor` 一致
  （完全对齐 0.6×、相差 180° 1.4×），并**封顶在 `--mo-3-collapse`**：超出窗口就会拖到球态，
  和那里的 `rotation.y += dt*0.1` 抢同一个四元数。
- 曲线用 `easeInOutCubic` —— 它是对称曲线，所以收起转回去**正好是**展开转过来的时间倒放。
- 补间期间与「聚焦 slerp」「空闲自转」**互斥**（三者写的是同一个 `planetGroup.quaternion`）；
  重开时 `reopen()` 调 `cancelAnimation()` 把它停掉，避免和下一次展开打架。
- 减少动画模式不发起这段旋转（那条路径本来就直接交还球态）。

**验收 S2.22**（先写断言、对着未实现的代码确认为红）：球态记 q0 → 打开记 q1 →
收起全程逐帧记朝向，断言「末帧 ≈ q0」且**中途真的经过中间角度**（不是瞬间归位）。
实测：展开转了 **159°**；收起逐帧采样 39 帧，**首帧偏离 = 159°**（说明转不是发生在收势段）、
**末帧偏离 = 4°**、中途经过中间角度。若某次打开本来就没转多少（话题恰好在中心），本条报「未运行」而非失败。

**要写清楚的取舍**：大角度会在收起窗口内转得较快（159° / 420ms ≈ 6.6 rad/s）——
这是「放在体量收缩段 + 封顶在窗口内」的必然结果，也是方案①的代价。
要放缓只能放宽到收势段（你明确不要）或允许略微超出窗口（代价：交接点要和球态自转重新对齐）。
另外，两个方向现在都转，但语义不同：展开转到「当前在聊的话题」，收起转回「打开前的朝向」；
**信息密度**仍各按语义（展开随长大浮现，收起先降到抽象态再收）。
