## 2. 五项修复：触发条件、改动与可见结果

### 2.1 默认组名（契约 §9.1）
- **触发：** 两张卡片重叠成组 / 手动新建组 / 两个已有组合并；留空或取消改名。
- **改动：** 后端 `models.DEFAULT_GROUP_NAME = "默认组名"`（`default_group_name()` 保留参数位但固定返回默认名）、
  `board.py` 的默认名正则同时认「默认组名」与历史「组 N」、归一化保留历史 `defaultName`；
  前端 `board.ts` 的 `nextDefaultGroupName` 不再编号，`isDefaultGroupName` 同时认两种形态。
- **可见结果：** 成组后组名输入框显示 `默认组名` 与徽标「系统默认名，可改」；改名后前后端一致；留空后组仍成立且名字不变；
  刷新后组、成员、组名都在。**组身份按 id，默认名可重复。**
- **反例：** 把 `nextDefaultGroupName` 改回编号 → 用例失败（`expected '组 8' to be '默认组名'`）；
  后端改回 `f"组 {index}"` → `assert '组 1' == '默认组名'` 失败。

### 2.2 批次不能按创建时间猜（契约 §9.2）
- **触发：** 本地批次记录被清除 / 写入失败 / 被禁用 / 达到容量上限 / 内容损坏。
- **改动：** **删除** `approval.ts` 里「`createdAt` 截断到秒」这级归批；只保留会话记录与真实 `submissionId`；
  记录有界（条数上限 + 7 天 TTL + 读侧上限），任何异常都降级为「这批不成批」，绝不合并。
- **可见结果：** 反例场景 13（实机）：一次创建动作产生四项且**创建时间落在同一秒**，
  清掉本地记录后刷新 —— 批量入口**不出现**（`entry:false`）；有记录时正常出现。
- **反例：** 恢复「创建秒」归批 → 用例失败（`expected [{key:'second:1791345600'}] to have length 4 but got 1`）。
- **文档更正：** 契约 §8.5 标注「已作废」并写明「宁可不出批量列表，也不把不同批次相加」这句与实现不符的原因。

### 2.3 同批达到四项后列表保留到处理完（契约 §9.3）
- **触发：** 同一批产生的意图总量 ≥4，随后用户处理掉其中若干项。
- **改动：** `batchesWithList` 资格改成「总量 ≥4 且 `pendingIds > 0`」；新增剩余/已处理计数与
  「已处理项不可再选」判断；组件显示「待审批 N 项（共 M 项，已处理 K 项）」。
- **可见结果（实机，场景 9，10/10 通过）：** 四项 → 入口出现、默认收起 → 刷新后仍在 →
  展开 4 条 → 处理 1 项后入口仍在并显示「待审批 3 项（共 4 项，已处理 1 项）」→ 剩 2 项、1 项仍在 →
  全部处理完入口消失。
- **反例：** `batchesWithList` 改回 `pendingIds ≥ 4` → 用例失败（`expected [] to have length 1`）。

### 2.4 聊天草稿持久化与恢复（契约 §9.4）
- **触发：** 输入草稿后刷新 / 收起面板 / 页面隐藏；发送失败；存储不可用；保存回执迟到。
- **改动：** `interactive/drafts.ts`（存储、序号、迟到回执判定）+ `stores/session.ts`
  （按话题持久化、防抖 400ms、收起/隐藏落盘、受理成功才删、失败恢复原稿、不覆盖新输入、明确失败与重试）。
- **可见结果（实机，场景 14，3/3 通过）：** 输入后 **471ms** 落盘（轮询到真实写入，不是固定延迟）→
  刷新后输入框恢复原文 → 恢复过程 **0 次** `/api/turns` 请求（不自动发送）。
  另有实机证据：发送失败保留文字并提示；受理成功后草稿记录被删；存储拒绝写入时提示「草稿未保存」并可重试成功。

### 2.5 卡片草稿保存失败不静默（契约 §9.5）
- **触发：** 草稿保存请求失败；防抖未触发就离开编辑器/页面。
- **改动：** `stores/interactive.ts` 建立 idle/saving/saved/error + 失败原因 + 重试（串行化 PUT、丢弃旧返回、
  板面重载不覆盖未保存草稿）；新增 `CardDraftHint.vue` 并在卡片编辑器内接线；`confirmEdit/cancelEdit` 调 `flushDrafts()`。
- **可见结果（实机，场景 15，4/4 通过）：** 保存失败时编辑器内显示「草稿未保存：…（输入内容已保留）」+「重试保存」，
  编辑内容保留，**没有**创建正式卡片、**没有**提交板面、**没有**调用 QIO。

## 5. 草稿恢复与异常路径证据

- 草稿落盘等待的是**真实写入结果**（页面内轮询 localStorage 直到出现目标文字，实测 471ms），不是固定延迟。
- 刷新后恢复：输入框原文恢复、消息流 0 条、`/api/turns` 0 次。
- 发送失败：保留输入 + 「发送失败：…（输入已保留，可以重试）」，存储记录仍在。
- 存储失败：提示「草稿未保存：本机存储已满…（文字还在输入框里，可以重试）」+ 重试按钮，重试成功后记录写回。
- 卡片草稿失败：编辑器内提示 + 重试，未确认草稿不变成正式卡片。

## 6. 已知限制与未验证项

1. **跨调用持久化无法在本环境验证：** 探针 Chrome 每次调用新建实例，localStorage 跨调用不保留
   （同一次运行内 `location.reload()` 正常）。因此「关掉浏览器再打开」这一条没有实机证据；
   草稿与批次记录的恢复证据都是同一次运行内刷新。存储层本身是 `localStorage`，单元用例覆盖了损坏/禁用/写满降级。
2. **真实 QIO 未接入：** `delivery.delivered` 恒为 false，提交只落库并标记未接入；界面与文档都如实显示。
3. **健康探测 130ms：** 相关用例复跑 5 次全过，未复现；作为待确认的稳定性现象记录，未降低门槛、未删测试。
4. **未做：** 触摸 / 高 DPI / 最小窗口的像素级检查；批量列表与聊天面板的拖拽调整大小；
   三浮层（聊天 + 批量 + 任务浮层）同开时的连续采样。
5. **依赖别人的小项：** 提交区（`SubmitCluster.vue`）自身仍偏高，工具栏用容器级 `:deep()` 收束才达到 84px；
   如果以后改提交区，需要同步复核工具栏高度。
6. **批次判定仍是前端 adapter**（服务端没有批次字段，本轮不改数据库）：本地记录丢失时该批不再出现，
   如实说明「批次不可恢复」，不会误合并。

## 7. 边界

- 本轮**没有**开发真实 QIO 板面理解、附件系统或新的任务执行机制；没有合并两条开发线；没有合入 `main`。
- 未提交板面与未勾选注释不会经聊天或工具泄露：聊天只发文字、不附带板面、不调用提交接口（实机请求级证据见场景 8/14）。
