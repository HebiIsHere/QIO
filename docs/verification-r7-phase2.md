## 4. 未验证与边界（如实）

### 4.1 实机装置限制：带附件时「发送」没有发出 \`POST /api/turns\`（S2/S4 三条未取到）

现场诊断（summary.json 原文）：

\`\`\`json
{"attempt":0,"valueBefore":9,"valueAfter":9,"sendButtonEnabled":true,
 "composer":"默认话题 Enter 发送 · Shift+Enter 换行 r7-就绪附件.bin 62.9 MB 已保存副本 打开 × 附件 路径 ↑",
 "notices":[]}
\`\`\`

即：附件已是「已保存副本」、输入框有文字、发送按钮**可用**、没有任何拒绝提示，但按 Enter 与点按钮都**没有**产生 \`POST /api/turns\`（重试 15 次仍为 \`no-request\`）。
因此这三条（S2 就绪后执行 / S4 重试复用保存副本 / S4 内联审批与历史附件）在本次实机取证中**未取到证据**，我**没有**把它们当成产品结论。
补充观察（待 Lead 定性，**未定性为缺陷**）：r6 阶段的实机脚本用同一套点按方式**成功发过带附件的一轮**；本轮前序场景（S1/S2b 的 94MB 附件准备）之后就开始出现该现象，不能排除是**状态污染**或组件回归。
**替代证据**：后端 \`test_r7_readiness_prepared_verify.py\`（真实发送接口 + 闸门）+ \`test_r7_disconnect_cancel_verify.py\`（真 uvicorn + 真 TCP 断连）+ A 的 \`test_preparation_cancel_http.py\`；前端 A 的组件级用例（PreparingAttachments 等 7 条：提示文案、中止按钮、\`already_started\` 分支）。

### 4.2 实机不可注入的暂存读取故障

暂存读取失败需要**进程内打桩**（patch \`Path.read_bytes\`），实机（独立 uvicorn 进程）做不到 → 该条只在后端验收件里取证；
实机只验证了**正常长正文路径**（完整交付、无「不完整」提示、宽窄窗口截图）。

### 4.3 其余边界

1. **60s 生产等待值未真实等待验证**：我的用例只验「不放行不执行、放行后执行」，没有把等待推到 \`PREPARE_WAIT_MS\`/60s 有界点（要占 CI 一分钟）。
2. **准备期进程崩溃路径无用例**：我用的是优雅关闭（\`ctx.turns.shutdown()\` 与真断连）；**SIGKILL/断电**后的预留行回收未验证。
3. **真实磁盘故障只做 OSError 注入**：ENOSPC/EACCES/EIO 都是注入的，真实满盘/只读挂载未测。
4. **多实例共用 tmp 的清理竞争未验证**：暂存文件按 \`delta_id\` 命名，两个实例共用同一 \`<data>/tmp\` 时的清理竞争没有用例。
5. **重新打开对话后警告是否仍可见 = 未验证**：取决于轮次事实是否持久化；按 Lead 裁决**不**把说明塞回正文，因此这条保持未验证。
6. **HTTP/2 / 反向代理下的断连行为未验证**：真断连证据来自 HTTP/1.1 + 真 TCP FIN。
7. **真实厂商 / 原生桌面 / 安装包未验**：全部证据来自本机假 provider 与 msedge 无头浏览器。
