## 2. 页面结构

- `.planet-view`（`fixed; inset: 0; overflow: clip`）内部新增 `.planet-content`：`position: absolute; inset: var(--titlebar-height) 0 0 0`。
  **顶部全局栏仍是应用原来那一条**（`WindowChrome`，逻辑、入口、状态未改），内容区域天然位于它下方。
- 星球层绝对定位铺满内容区，**尺寸全程不随管理区变化**（画布不 resize）；管理区绝对定位在右侧，
  展开只把画布 `translateX(calc(var(--mp) * -50%))` → 球心从「内容宽/2」连续移到 0，只剩右半球。
- 默认浏览态不裁切（球顶弧与基线一致），只有管理展开时 `.managing` 打开裁切。
- 窄窗口：`内容宽 >= 880` 且 `内容宽 - 管理区宽 >= 球体半径 × 1.15` 时左右排布，否则上下排布
  （星球在上、管理在下、内容区一层纵向滚动），全程无横向滚动。实测：**900×700 左右排布**（半径 316.87 → 316.87 不变、
  画布 left=-450、球心 x=0、管理区 left=486 / 宽 414、无横向滚动）；**760×820 上下排布**（管理区 top=398、宽 760；
  星球区域被压到 328 高，半径按 ∝ 画布高度等比变为 164.97；无横向滚动）。

## 3. 星球过渡

- 唯一进度来源：`frontend/src/composables/usePlanetManageTransition.ts`（`--mp` / `data-mp` / `.managing`）。
- 旋转落在场景内**独立姿态组**（`usePlanetScene` 的 `poseGroup` + `setManageYaw`），不碰 `planetGroup` 的
  四元数、空闲自转、聚焦 slerp 与 OrbitControls —— 与拖动旋转共用一致的姿态管理，互不覆盖。
- 曲线取 CSS 令牌（展开 `--ease-3-settle` / 收起 `--ease-3-out`，时长 `--mo-3-expand` / `--mo-3-collapse`）；
  连续反向从当前进度与**瞬时速度**用三次 Hermite 衔接，不重置朝向、不瞬移、不突然反转。
- 减少动态效果（`prefers-reduced-motion` 或 `html[data-motion=reduced]`）一帧到位；运行中切换立刻落位。
- 动画结束停止不必要渲染（静置 2.5s 渲染计数 208 → 208、CDP 帧 Δ0，交互后恢复）。
- 动画期间不重建渲染器/场景/星球资源（画布尺寸不变，只有 transform 合成）。

实测（`scripts/mp-verify/frames.mjs`，最终 HEAD，1440×970，真实数据）：

| 动作 | 帧数 | 时长 | 球心 x | 选中标签 x | 长帧（dt>60ms） | teleports |
| --- | --- | --- | --- | --- | --- | --- |
| 展开 | 48 | 1817ms | 720 → **0** | 719 → 355 | 10 | 1 |
| 收起 | 63 | 1969ms | **0 → 720** | 355 → 719 | 7 | 1 |
| 中途反向（880ms 触发，mp=0.441） | 83 | 2196ms | 720 → 720 | 719 → 719 | 10 | 3（过冲 0.074） |

曲线图与逐帧 JSON：`docs/mp-verify/c-planet/frames/curves.md`。判读口径：本机 headless 软件渲染帧间隔**双模态**
（7ms / 100–180ms），所以用「按帧时间归一化的步进」判断（`normStep>1.6` 记 teleport），并单列长帧；
所有 teleport 标记帧都紧邻 `dt>60ms` 长帧、且长帧内 Δmp≈0（采样器滞后写方一帧），邻域三帧聚合速率 1–5/s（曲线峰值≈8/s）。
展开起始 300ms 内依次出现 0.046 → 0.265 → 0.461 → 0.874（有过程，不是瞬跳）。

## 4. 管理区（记忆 / 知识 / 实体 + 待处理 + 整理记录）

- 三个标签页同一块内容区域（不是三栏并列），首次激活才挂载，之后 `v-show` 保活：切换保留列表位置、搜索、
  筛选、已打开条目，且**不触发任何星球换景**（画布矩形与 `--mp` 不变）。
- 辅助入口「待处理（真实数量）」「整理记录」占据同一块管理内容区域（不新开侧栏/抽屉），返回时恢复进入前的
  标签页、条目与浏览位置。
- 待处理数量 = `GET /api/memory/pending` 的 total（知识建议 + 记忆整理问题）+ `GET /api/entities/candidates` 的 total
  （实体更新候选）；单侧失败保留上次真实值、两侧失败不清零（不把「不知道」显示成 0）。

## 5. 记忆页与话题浏览

- 话题列表（搜索、已结束分组、结束/恢复）→ **话题概览**（名称与概览、讨论记录预览 + 进入完整讨论记录、
  关联知识、关联实体、「继续讨论」）→ **完整讨论记录**（真实 `fragmentMessages` 分页、只读说明、可返回概览）。
- 「对话当前话题」（会话起点）与「正在浏览的话题」并排写清；点其他话题只改浏览记忆，**只有明确点「继续讨论 /
  从这里继续」才走既有锚点切换机制**（先 `cancelContinuation` 再 `setAnchor` / `continueFromHistory` 的既有边界保留）。
- 关联知识/实体点击 → 切到对应标签页并定位打开条目；记忆页话题与浏览位置保留。

## 6. 知识与实体：列表 → 详情 → 返回，草稿化编辑

- 两个标签页都是列表 → 条目详情 → 返回列表；返回后恢复原搜索、筛选与滚动位置（组件保活，不重建列表）。
- 详情复用真实数据、来源、关联、编辑能力：知识的分类/状态/来源/适用范围/关联话题/依据数/版本链/结束恢复/归档；
  实体的摘要/类别/别名/属性（含置信度）/关系/身份/创建依据/证据数/更新候选。
- **草稿化编辑**：进入明确草稿态后，别名、属性、关系增删全部只改本地；点「保存」才一次性提交
  （实体 = 字段 + `relations{add,remove}` 同一请求、后端同一事务）；取消丢弃；失败保留草稿 + 可读原因；
  编辑期间数据被改动 → 409 冲突提示、保留用户输入、展示服务端当前内容，不静默覆盖；
  返回/切标签/收起管理/离开页面时未保存内容先经确认（`QConfirm` 层），不静默丢弃。

## 7. 待处理与整理记录

- 待处理：真实来源合并（知识建议 / 记忆整理问题 / 实体更新候选），列表 → 事项详情（判断所需内容、before/after、
  依据与来源）→ 确认 / 修改后确认 / 不保存 / 回答 / 稍后处理 / 采纳 / 丢弃；完成后回列表并保留位置、数量同步。
- 「修改后确认」走既有原子接口 `submitKnowledgeApprovalRequest(id,"approve_modified",…)`：一次事务里以用户确认后的
  内容生成生效版本，**不会先确认原文再改**；409 / 已被处理时刷新真实状态、不重发过期内容。
- 整理记录：列表 → 单次详情（整理摘要、触发原因、统计、起止与耗时、受影响条目）；受影响条目默认折叠，
  点开才展开修改前后快照；撤回/单条恢复复用中央弹窗 `MaintenanceRestoreDialog` 的预览与确认，保护整理之后的新修改。

## 8. 全局搜索

- 入口在页面工具行（不新建顶部全局栏）；一次搜索并行覆盖话题/知识/实体三类，结果按三类分组，范围不随当前标签页缩小。
- 加载中 / 无结果 / 失败三态为 QIO 自绘；请求序号丢弃旧响应（旧关键词的迟到结果不覆盖新结果）。
- 点结果 → 切到对应标签页并打开条目详情；「返回搜索结果」保留关键词与结果；关闭搜索恢复进入搜索前的管理上下文。

## 9. 视觉一致性（星球美术未变）

方法（可复核）：
1. 球体半径与画布高度成正比（1440×900 画布 → 452.67；1440×830 画布 → 417.46），所以对照必须对齐**画布高度**：
   基线窗口 1440×900（画布 900）↔ 改版窗口 1440×970（内容区 900）。
2. **同姿态逐像素**：基线截图时记录 `__qioPlanetStage().debug.quaternion`，改版用 DEV-only 姿态钩子
   （`__qioPlanetSetPose`，同时冻结 `focusTopic/go/rotateBack` 与在跑补间）摆成同一姿态再截图，同裁剪框逐像素比对 →
   变化像素 **14,176 / 810,000 = 1.750%**。对照：不对齐 19.4%、图像平面单轴对齐 19.4%（残余是绕世界 Y 轴的旋转，
   平面旋转补不回来）、姿态未冻结时 3.35%。残余与「基线四元数采样到截图之间约 200ms 的自转（≈1.1°，在 452px 半径上
   ≈8px 表面位移）」同量级，且集中在环与话题点边缘，球体/轮廓/网格/环宽/配色结构探针逐项相同
   （热图与原始数字：`docs/mp-verify/c-planet/same-pose/c-same-pose-diff.png`、同目录 json）。
3. **噪声地板**：基线自己连跑两次也有 11.6% 像素差、像素扫描直径差 37px（因为入口球态空闲自转累积量随加载时间变化，
   采集时朝向不可复现）。作为对照：基线 ↔ 改版 像素扫描直径差 **-1px**、DEV 钩子半径**逐位相同**（452.66504294495525）。
4. **结构探针（旋转无关）**：轮廓环圆周众数色、球内众数色、融合环最强色三组逐项相同；环宽笔画峰相同（内 10 / 中 6.5 / 外 4 全宽）。
5. 代码层面：`usePlanetScene` 的球体/融合环/相机常量（FOV、`RADII.focus = 2.25`、环宽、透明度）无改动。

## 10. 界面规范核查

- **圆角 14px**：记忆星球页所有面板/卡片/按钮/输入/菜单/提示浮层/局部弹窗一律 `var(--qio-ui-radius)`；
  源码审计：本页新增/改写的 13 个文件里 `border-radius` 全部是该令牌（0 处其它取值），
  页面内也不再出现 `--r-pill` 等近似值（守卫测试兜住）。运行期 DOM 审计：除共享滚动指示条（4px 宽胶囊）外无其它圆角。
- **无原生控件**：页面 DOM 内 `select / datalist / checkbox / radio / file / date / range / color / list=datalist` 数量 = 0；
  源码无 `alert / confirm / prompt`；滚动条外观全局已由 QIO 统一处理。
- **颜色与字体**：新增/改写文件的颜色全部走 `var(--*)`（无硬编码色值）；标题/话题衬线、正文无衬线、数据等宽。
- **无横向滚动**：1440×970（默认/管理）、1024×768、900×700 三种窗口逐层检查 `scrollWidth <= clientWidth + 1`。

## 11. 迭代与数据变化

## 13. 未完成事项与已知限制

   （不制造用户处理不了的假待办）；要支持需补后端确认关系目标端点，超出本次最小补齐范围。
4. 逐帧采样在无 GPU 的软件渲染环境（SwiftShader，25–40fps、偶发 100ms+ 长帧）下会放大单帧步进；
   交付里的动画质量以「归一化步进 + 长帧单列」口径判断，不用原始 |Δmp| 当结论。
5. 录屏为 CDP `Page.startScreencast` 真录屏（本机 7–13fps），**不要用视频帧数反推动画帧数**，帧级数据看 `frames/*.json`。
