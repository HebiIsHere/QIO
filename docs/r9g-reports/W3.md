## 2. 批量语义（契约 §6）

* 统一展开为 `BatchItem(item_id, effect, label, payload, fingerprint, status, reason)`；
* **逐项 authorize**：fs_delete 的每个 path、附件回收/写回的每个对象独立调用网关，一个对象的 allow 绝不覆盖整批；
* 逐项状态：`allowed / denied / waiting / invalidated / completed / failed`；
* 需要确认的项合并为**一个**审批操作（`fs.delete` / `attachment.recycle` / `attachment.batch_write_back` 的 payload `items` 逐项含 `item_id/path/action/identity/内容摘要`），不逐项弹窗；已允许项直接执行，被拒项如实列出；
* 批次结果 `data.items`（逐项状态）+ `data.results`（兼容既有消费方）+ `pending_approval`；
* 恢复/重试：执行器只处理审批单列明项；已不存在的对象按身份重核对 → `invalidated`，**不会重复成功**；未执行且仍获准项继续（新增幂等重放测试）；
* 依赖/一致性策略：fs.delete、附件回收、附件写回都是**逐对象独立**批次（无跨对象依赖），因此单允许项可继续、被拒/失效项保留；要求整体一致性的批次（如事务性多文件替换）当前 W3 入口不存在，属于边界（见 §6）；
* 目录/通配符展开新增对象：每个 path 在授权前重新取身份并逐项判定，没有「用目录/前一项授权覆盖新增对象」的路径；
* 移动/重命名/复制/外发：本模块**没有**这类文件工具入口（`fs_move/fs_rename/fs_copy` 均不存在），因此契约的「源+目的两侧核对」在 W3 无落点；命令行/外发由 W2 负责（见 §6 边界）。

## 3. 要求绑定（契约 §3）

* 读取点：`security/context.py` 的 RequirementBinding contextvar（Lead 合入后生效；当前按接口名探测，未合入返回 None）；
* 绑定只放在 `effect.detail["requirement_binding"]`（+ `requirement_binding_source`），**不信任模型参数**：工具只读取 path/content/paths，模型传入的 `requirement_binding`/`requirement` 被忽略（有测试）；
* 审批单 payload 与 fingerprint 携带同一份绑定；批次 payload/fingerprint 携带批次绑定；
* 绑定缺失 → None + `source=unavailable`，**不调用** `requirements.current()`、**不回退最近一条要求**（有测试用伪造模型字段验证）；
* 不同 turn 的两个绑定分别进入各自 effect，不串用（有测试）。

## 4. 执行前重核对（契约 §7）

覆盖入口：`fs_write`、`fs_patch`、`fs_delete` 每一允许项、`read_attachment` 读取前、附件写回/批量写回、附件回收每项，以及批准后重放执行器（fs.write/fs.patch/fs.delete/attachment.write_back/attachment.recycle/attachment.batch_write_back）。

重核对内容（按可用性）：
1. Lead 的 `RecheckService.recheck(OperationBinding, effect=...)`（合入后自动走；OperationBinding 按 dataclass 字段构造，含 requirement/mode/operation_kind/fingerprint/content_digests/authorization_id）；
2. 回退（当前基线）：用**当前**模式重新走 `gateway.authorize`（`AuthContext.requirement` 扩展后自动带绑定）；要求绑定仍有效（`validate_binding`）；对象身份与内容摘要未变；
3. 执行器侧：`ctx.authorize_started()`（模式快照/只读收紧）+ 要求版本校验 + 当前引擎重新判定（明确 DENY → 不执行；APPROVE 不自动放行，交由审批恢复流程）+ 对象身份/内容摘要/审批单内容摘要比对。

失效处理：单文件操作返回明确 `code`（`recheck_denied` / `recheck_needs_user_decision` / `recheck_identity_changed` / `recheck_content_changed` / `recheck_requirement_invalid`），文件原样保留；需要重新确认时重新提交**同一操作**的审批；批次中该项 `invalidated`，其余无依赖已授权项继续。
