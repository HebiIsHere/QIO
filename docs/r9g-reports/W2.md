## 2. 契约实现

### §4 固定查询（fixed_queries.py）

冻结接口保持：`FixedQueryFacts(kind, program_path, program_name, argv, cwd, shell)`、
`classify_fixed_query(facts) -> FixedQuery | None`（`FixedQuery.kind` 为
`version|cwd|system_info|list_dir|stat`，`facts` 携带可审计细节）。

- **单一来源**：程序身份 + 精确 argv 结构；不搜索命令/用户文字，不做关键词/正则/句式/否定/问号/引号判断。
- **安全规则**（命中任一即 `None`，退出固定查询走普通流程）：
  - `shell=True` / 真正的 shell 程序（cmd/powershell/pwsh/sh/bash/dash/zsh/fish/wsl）；
  - 程序路径为空、相对路径、非文件、无执行位（POSIX）、真实 basename 与请求名字不符；
  - 程序在请求 cwd 内、或在临时目录（含 Windows `%TEMP%`）内 —— 同名替身不得自动放行；
  - 未知参数/任意多余参数；argv token 含 `| & ; < >` 或控制字符；
  - 解释器只允许精确版本形式（python 的 `-V`/`--version`；node/npm/pip/uv/... 同理），
    脚本、`-c`、`-m`、未知参数 → `None`；
  - Windows 官方包装入口 `.cmd/.bat`（npm/pnpm/yarn 等）只在「真实路径 + 名字匹配 + 不在 cwd/临时目录」时接受；
    这是「名字+路径」层面的身份，无法证明包装脚本内容未被改（依赖系统 ACL）——已在残余风险说明。
- 覆盖形式：`--version`/`-V`/`-v`（按程序白名单）、`pwd`（空/`-P`/`-L`）、
  `whoami`、`uname`（空/`-a`/`-s`）、`id`、`hostname`、`date`（空/POSIX `+format`）、
  `ls`（短/长选项白名单 + 目标路径）、`stat`/`file`（结构化选项白名单 + 目标路径）。
- **不采信工具自报**：`RunProgramTool` 的 payload 只带 `fixed_query_kind` 供审计；engine 必须用
  `fixed_query_facts_from_detail(effect.detail)` 从 `detail['execution']` 重算
  （本分支用测试证明：仅凭 effect.detail 可重新得到 `version`）。
- **只读模式**：只读证明改为固定查询分类（`readonly_allowed = 固定查询 且 非永久删除`）；
  shell/解释器/未知参数一律在引擎判定前被执行层拒绝，且不进入引擎/不启动进程。
- 分类器与模式无关（纯函数，无 mode 参数）——模式政策在 engine/执行层。

### §5 永久删除（deletion.py）

冻结接口保持：`DeleteObject(path, identity, is_directory)`、
`DeleteIntent(permanent, objects, method, program, argv, shell_cmd, verified, reason)`、
`detect_delete_intent(*, effect_kind, detail, facts)`。

- **命令识别按实际程序身份 + 参数语法**：`rm`/`rmdir`/`unlink`/`shred`（POSIX 选项白名单、组合短选项、
  取值短选项）、`find ... -delete`、`git rm`/`git clean -f`（对象集合由 git 展开 → `verified=False`）、
  Windows `del`/`erase`/`rd`/`rmdir`（`/f /q /s /p /a` 白名单）。
- **shell 命令**：先做极简 token 化；含 `| & ; < >` 或换行 → 返回 `None`（**属于普通流程**，不是
  「没命中词就放行」）；含引号/展开/转义 → 仍识别为永久删除但 `verified=False`（对象集合可能不完整）；
  前置 `VAR=value` 可跳过；解释器内联代码/sudo/xargs/嵌套 shell → 不解析（普通流程）。
- **讨论/引用/输出不触发**：从不全文搜索命令文字；`echo rm -rf x`、`git log --grep 'rm -rf'`、
  `python -c print('rm -rf')` 都不产生意图（测试覆盖）。
- **文件工具**：默认删除（回收站）不产生 permanent intent；只有明确 `permanent=True` 的合法工具/参数
  才产生 `fs.permanent_delete` 意图（对象身份可回读）。
- 对象身份：`agent.services.file_identity.identity_of`（volume+file_id），目录标记来自实际 stat；
  相对路径按 cwd 解析，解析不了 → `verified=False`（不编造对象）。

### 政策表（§5 + §8，cmd_tools 执行层）

| 模式 | 固定查询 | 非固定查询/脚本/shell | 永久删除 |
| --- | --- | --- | --- |
| read_only | 允许（精确形式） | 拒绝（执行层，不进入引擎） | 拒绝 |
| restricted | 引擎按分类器 ALLOW（不弹确认） | 引擎 APPROVE → 审批；DENY → 拒绝 | 必须**明确人工确认同一组具体对象**；模型 ALLOW / 一般授权记录不能替代；只有 decision 带 `approval_id`（明确人工记录）才可复用 |
| unrestricted | 放行（仍受执行边界） | 放行 | 放行 |

- internal data：三次确认优先、**不叠加第四次**；永久删除内部数据仍按三次确认（payload/标签同时带永久删除警告）。
- 明确确认单：payload 带 `explicit_confirmation_required/recycle_bin=False/irreversible=True/warning`，
  指纹带 `permanent_delete`（方法、verified、对象 `identity_set`）+ 重算后的 `payload_digest`；
  label 列出对象路径（对象集合不可靠时如实说明）。
- 效果审计：`Effect.detail` 保留 legacy 键（`program/argv/cwd/shell/command/risk/script_sha256`）
  并新增 `execution`（真实程序路径/名字/argv/cwd/shell/shell_cmd/spec_digest/program_sha256/argument_files/
  content_digests）与 `delete_intent`；引擎可独立重算（不读工具判断结果）。

### §7 操作绑定与执行前重核对

- 审批指纹（`_pending_facts`）新增：`requirement`、`operation_binding`（契约 §7 字段：
  requirement/mode/operation_kind/fingerprint/spec_digest/content_digests/conditions/authorization_id/delegation/
  permanent_delete）、`delete_intent`；payload 记录 `requirement_binding/operation_kind/operation_summary/
  execution_facts`。
- `execute_proc_run_program`/`execute_proc_shell` 执行前（不排队、不先执行）：
  1) payload 与审批单整份一致；2) effect 快照 + spec_digest + 程序内容摘要 + 脚本/参数文件摘要；
  3) 要求绑定：payload 与指纹一致 + 台账 `validate_binding`（W1）或只读 `by_id+status/version` 核对；
  4) 模式：read_only 拒绝；无限制→受限的批准失效（不能靠旧宽模式批准绕过新受限模式）；
  5) 内部数据确认次数 ≥3；
  6) 永久删除：前后两次结构化识别的对象 `identity_set`、目录标记、verified 必须一致；审批时无可靠身份、
     执行时对象却存在的 → 不能核对同一对象 → 失效；
  7) 注入式 `RecheckService`（`ctx.recheck` / `ctx.recheck_service.recheck(binding, *, effect)`）
     若存在则调用，否决 → invalidated；未注入 → 本地兜底并在 `detail['recheck']` 标
     `mode=local_fallback`（不谎称已走服务）。
- 重放网关 `_ApprovedReplayGateway` 增加：execution 真相（kind/program_path/program_name/shell/spec_digest）
  与 delete 意图/对象身份逐项核对；永久删除要求审批 payload 带明确确认标记。
- §9/§10：旧记录缺 requirement 绑定 → 执行期 invalidated（不默认补成宽泛授权、不沿用旧许可）；
  要求版本变化/撤回/不存在 → invalidated；审批有效期与重复回调由审批执行器/存储负责（见未完成项）。

**残余风险（必须诚实告知）：**

- **任意程序副作用不可结构性约束**：`python -c 'os.remove(...)'`、`xargs rm`、`sudo rm`、
  嵌套 `cmd /c`/`sh -c`、shell 展开/通配符等情况，删除动作不被识别为「可解析的永久删除」，
  按普通审批流程处理；QIO 无法证明这类命令没有删除副作用（这正是契约要求的边界）。
- shell 永久删除含引号/变量/通配时 `verified=False`：审批单只能覆盖命令原文并明确警告，
  无法列全具体对象；restricted 仍要求明确人工确认，但用户需理解这一限制。
- Windows `.cmd/.bat` 包装的固定查询（npm/pnpm 等）身份依赖真实路径与系统 ACL；程序内容被替换不在
  分类器可检测范围。
- `find -delete`、`git clean -f` 的对象集合由程序内部展开 → `verified=False`（要求明确确认，
  但审批单不能列出每个被删文件）。
- 固定查询分类器是纯函数，不校验程序文件内容（由 `program_sha256` 绑定在审批/执行层面负责）；
  read_only 固定查询会执行真实程序，其副作用边界仍由程序本身语义决定（版本查询不会改文件，但不构成沙箱）。
- 本分支证明的是 W2 组件 + 目标执行路径；最终「引擎按分类器决策、策略表全链路」需 Lead 集成树验证。
