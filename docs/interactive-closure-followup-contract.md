## 0. 本轮共同规则（六条反例的统一根因，不为单条反例加特例）

1. **候选与已保存版本必须分开接收。** 服务端 `seq` 是「已保存事实」；用户正在编辑的是候选。
   一次 PUT 成功 = 「服务器接受了那一版」的版本事实，必须被吸收（`boardCleanRev` 前进、候选带上新 `seq`），
   但**绝不整块替换候选正文**。任何 GET/PUT 回执落地前都要与「请求发出时刻的基线」比较，
   而不是只看 `dirty`：已保存成功的新版本与未保存的新输入受同样保护。
2. **取消影响确认 = 丢弃候选，并且必须真的撤回。** 丢弃候选要同时把版本记账收回（`boardLocalRev = boardCleanRev`），
   否则回读会被「仍有未保存候选」的保护挡住，出现「dirty=false / idle 但板面还是被取消的正文」。
   回读失败必须如实提示并保留可处理状态，不假装撤回成功。等待期间更晚的输入不得被旧取消响应清掉。
3. **本机记录的处理目的必须显式保留。** 「删除本机冗余副本（`remove-local-copy`）」与
   「整份草稿清除（`clear-draft`）」是两个不同决定：前者只删记录、**绝不写 `cleared` 依据**；
   后者才允许幂等补写 `cleared` 依据。重试不得把前者变成后者。无法判断目的的旧记录保留两份候选并说明，不一律当整份清除。
4. **影响确认必须绑定真实范围。** 只使用户**看到并确认过**的改动与后果生效；
   服务端保存前重新核对受影响任务与后果，出现未说明的**新增运行中**受影响任务时拒绝（不落库、不暂停、不推进快照）并给出重新说明的原因。
   前端必须在确认框里重新展示完整范围，由用户重新确认；不得自动确认、不得无条件保存、不得循环重试绕过校验。
5. **兜底路径也必须能完成确认。** 服务端以 `impact_confirmation_required` 拦下保存时，
   前端要补取与当前候选、服务器版本一致的影响预判（含 `checkId`）后再交给用户决定；
   补取失败保留候选与真实原因，不无限弹窗。
6. **无关变化不制造无意义确认。** 已暂停任务、无关任务、普通位置变化不得反复阻断保存；
   判定依据是真实影响（任务状态 + 依赖材料语义），不是整个任务列表或总数量。

## 1. 六条反例与正确行为（本轮验收矩阵）

| # | 触发 | 应有结果 |
| --- | --- | --- |
| R1 | 编辑运行任务依赖的材料 → 影响确认 → 取消 | 正式板面回到该次改动前的已保存状态；新输入仍在草稿里、可继续编辑；任务继续；回读失败如实提示 |
| R2 | 旧 GET 开始 → 用户完成新编辑并保存成功 → 旧 GET 最后返回 | 已保存的新正式板面不被回退；编辑框不被回退；正常的最新读取仍然可用；按板面身份保护 |
| R3 | 有运行任务 → 第一版保存未返回时完成第二版 → 第一版成功 → 继续保存第二版 | 第二版正文保留，同时吸收第一版保存成功的版本事实；下一轮保存能正常预判、确认并收敛 |
| R4 | 冲突中选「用服务器上的」→ `removeItem` 临时失败 → 存储恢复后重试 → 关闭重开 | 重试只删本机冗余副本，不写 `cleared`；重开后服务器稿、输入框与请求集合保留正确正文 |
| R5 | 前端任务清单滞后 → PUT 被 `impact_confirmation_required` 拒绝 → 用户确认 | 前端补取到与当前候选一致的 `checkId` 与完整范围，确认后真实落库、相关任务暂停并保留进度 |
| R6 | A 运行 → 预判仅列 A → 等待期间 B 被批准并运行（板面 seq 不变）→ 用旧 `checkId` 确认 | 服务端拒绝（不落库、不暂停 B、不推进快照）；前端重新展示完整范围，用户再次确认后才生效 |

## 2. 实现落点

- **前端（主智能体）**：`frontend/src/stores/interactive.ts`
  - `refreshBoardFromServer`：记录 `requestedBoardId` / `readLocalRev` / `readCleanRev` / 读取代次；
    期间板面被推进或已有更新读取落地时只合并草稿，不整块覆盖。
  - `saveNow`：旧回执成功时吸收版本事实（`seq` / `updatedAt`）而不替换候选；
    409 `impact_confirmation_required` 补取影响预判；409 `stale_check` 重新预判并重新展示范围。
  - `cancelImpact`：丢弃候选 + 收回版本记账 + 回读；失败恢复候选并显示原因。
  - `pendingLocalRemovals`：`{ purpose, expectVersion, guard }`，重试按目的分派。
- **草稿底层（A）**：`frontend/src/interactive/drafts.ts` 目的化原语（只增不改既有语义）。
- **后端（B）**：`backend/src/agent/interactive/intents.py` 保存确认时按真实影响复核范围；
  `backend/src/agent/api/interactive_store.py` 的 409 形状。
- **界面（C）**：确认/取消/失败文案与入口、可读性、窄窗口与双面板避让。
- **独立验收（D）**：独立命名探针、基线失败证据与候选 SHA 上的独立复核；不改产品代码。

## 3. 证据分层与边界

分层：①状态/单元 ②真实组件 DOM ③ASGI/API + 真实临时数据库 ④真实前后端 HTTP ⑤真浏览器 ⑥实际进程关闭重开。
mock 故障、网络延迟、存储故障必须标注为模拟；不得把「新建 Pinia store」称为实际关闭重开。

边界：不开发附件、记忆、真实模型板面理解或任务执行能力；`delivery.delivered` 继续如实反映未接入状态。
所有服务/脚本/浏览器实例必须显式使用独立临时 `QIO_DATA_DIR`。
