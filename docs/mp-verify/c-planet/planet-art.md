# C 组视觉核查证据（记忆星球页改版）

全部脚本在 `scripts/mp-verify/`（用法见该目录 README），产出的原始数据都在本目录下。
环境：Edge headless + SwiftShader（本机无 GPU），后端隔离数据目录 + 真实接口数据。

## 0. 一句话结论

- **美术没变**：球体半径（DEV 钩子）`452.66504294495525` 改前后**完全相同**（浮点逐位相同）；
  球心行像素扫描直径 837 → 836（Δ -1px，在 ±1px 判据内），且**比基线自己跑两次的波动（Δ -37px）还小**。
  轮廓环实色、球体内部众数色、融合环最强色三组结构探针一致。
- **管理展开几何**（int 分支实测 1440×970）：`--mp=1`、`managing`、画布 left=-720/宽 1440 → **球心 x = 0**；
  球体可见范围左边界 = 0（贴内容区左边），右边界 = 球心 + 447px = 0.987×半径（右半球完整，判据 ≥0.95）；
  管理区左边界 800 > 452.67，**不遮挡**；展开后选中话题标签 x 从 718 → 356（落在可见右半球中部）。
- **动画结束停止渲染**：静置 2.5s 渲染计数 208 → 208（Δ0），CDP Frames Δ0，`loopActive=false`；
  点一下画布 → 212（恢复绘帧）。交互没有被冻住。
- **中途反向**：定时触发（326.9ms，`--mp`=0.423）后反向，球心 720 → 415 → 720，
  无跳变（`jumps=0`，判据见下）、过冲 0、终点精确落位。
- **减少动态效果**：`data-motion=reduced` 生效，展开在 193ms 内到位 —— 在本机单帧约 110ms 的环境里
  相当于「点击后下一帧就到位」。

## 1. 美术对照的方法与噪声地板（必须先看这一节）

**基线自身的最终朝向不可复现**：入口球态空闲自转（`rotation.y += dt*0.1`）的累积量取决于加载时长，
聚焦 slerp 在相机补间结束时被截断，于是停下来的滚转角每次都不一样。实测同一份基线代码连跑两次：

| 对照 | 变化像素 | 球心行扫描直径 |
| --- | --- | --- |
| 基线 vs 基线（第二次） | 95,844 / 810,000（11.6%） | 874 → 837（Δ **-37**） |
| 基线 vs 改版（本分支） | 156,915 / 810,000（19.4%） | 837 → 836（Δ **-1**） |

所以「逐像素差」在本项目里**不能直接当美术结论**。本组采用三层证据：

1. **数值几何**：`sphere.radius` 来自 `sphereScreenRect()`（`asin(R/d)`），只由相机距离与画布高度决定 ——
   改前后逐位相同，说明 FOV / 相机距离 / 画布高度 / 球半径都没动。
2. **像素扫描**（`lib/png.mjs` 的 `scanSphereRow`）：球心所在行左右各取最外侧玫红像素，
   左右半径之和 = 该高度上的球轮廓直径。基线两次差 37px，改版与基线差 1px。
3. **结构色探针**（旋转无关）：
   - 轮廓环：沿整个圆周按轮廓半径采样取众数色 —— 基线/改版都是 `203,108,158`（同一主题下同一透明度叠加结果）；
   - 球体内部众数色：两边都是 `245,242,237`；
   - 融合环/话题点最强玫红：两边都含 `179,30,112` / `203,108,158` / `228,92,186`；
   - 环宽笔画直方图峰：两边都是 `2px` + `8px`/`9px` + 少数 `3-4px`（内 10 / 中 6.5 / 外 4 全宽的横切投影）。

**单轴对齐搜索**（Lead 要求）：`compare.mjs` 以球心为圆心，在 -180°..+180° 内搜最佳对齐角
（2° 粗搜 + 0.25° 细化）后再算差异，并把角度写进 `compare.md`。实测最佳角 10°，
但**对齐后残余仍有 19.4%** —— 原因写在这里，避免误读：两次运行之间差的是**绕世界 Y 轴**的旋转
（球面图案沿水平方向移动并前后缩放），它**不是图像平面内的滚转**，无法用二维旋转对齐消除。
因此本组不宣称「对齐后逐像素一致」，而是用上面的三层证据 + 噪声地板给出结论。

## 3. 渲染收尾 / 交互恢复 / 减少动态效果

数据：`probe/rev-1440x970-probe.json`

- 静置：`renders` 208 → 208（2.5s），`cdpFrames` 1 → 1，`loopActive=false` → **确实停帧**。
- 交互：点击画布后 `renders` 212（+4）、`loopActive=true` → **恢复绘帧**。
- `data-motion=reduced`：展开 193ms 到位（本机单帧 ≈110ms，即下一帧到位），无中间态。

2. **窄窗口（1024×768 / 900×700）本组未跑完**：A 的窄窗口上下排布还在收尾，需 A 合并后复测。

4. 录屏（`record.mjs`，CDP screencast → mp4）脚本已可用，但本轮未产出 mp4（A 修首帧/收起曲线后一并补录）。
5. 减少动态效果只验证了「展开」，未验证「展开中途切换偏好」以外的组合。
## 5. 同姿态逐像素比对（本轮新增，最强的一层）

`scripts/mp-verify/same-pose.mjs`：从基线报告里取出它截图时的四元数，
在改版页面上用 **DEV-only** 的 `window.__qioPlanetSetPose({ quaternion })` 把球摆成同一姿态并冻结自转，
再用**完全相同的裁剪框**截图逐像素比。数据：`same-pose/c-same-pose.json`、`same-pose/c-same-pose-diff.png`。

| 对照方式 | 变化像素 | 说明 |
| --- | --- | --- |
| 不对齐（原始，见 §1） | 19.4% | 两边朝向差 40–60°（绕世界 Y 轴） |
| 图像平面单轴对齐（10°） | 19.4% | 世界 Y 轴旋转不可用二维旋转对齐（见 §1） |
| **同姿态（四元数对齐）** | **3.35%** | 残余主要是基线采集时序：基线没有停帧，`debug.quaternion` 采样与截图之间隔了约 200ms，球以 0.1 rad/s 自转 ≈ 1.1°，在 452px 半径上就是 8px 的表面位移 |

结论：同姿态把差异从 19.4% 压到 3.35%（**降低 5.8 倍**），剩余部分与「约 1° 姿态残差」的量级一致，
不是材质/颜色/透明度/环宽/话题点几何的变化（那三项由 §1 的结构探针逐项对照过，完全相同）。

## 7. 录屏（CDP 真实录屏，不是逐帧拼接）

脚本：`scripts/mp-verify/record.mjs`（CDP `Page.startScreencast` 抓浏览器真实合成帧 → JPEG 序列 → ffmpeg 编 mp4）。
产物：

| 动作 | 输出 | 真实帧数 | 真实取样帧率 |
| --- | --- | --- | --- |
| 展开 | `record/rev-1440x970-expand/capture.mp4` | 9 | 7.5 fps |
| 收起 | `record/rev-1440x970-collapse/capture.mp4` | 8 | 7.3 fps |
| 中途反向 | `record/rev-1440x970-reverse/capture.mp4` | 21 | 13.1 fps |
| 展开（缩到 720 宽再录） | `record/rev-1440x970-expand-s720/capture.mp4` | 14 | 7.6 fps |

**必须说明的口径**：这是**真录屏**（浏览器合成帧），但本机无 GPU、WebGL 走 SwiftShader，
CDP 的 screencast 取样率只有 7–13fps，缩到 720 宽也没有明显提升（瓶颈是每帧编码 + 渲染，不是像素数）。
所以：视频用来**目视确认动作连续、方向正确、没有闪断**；**帧级定量结论一律以 `frames/*.json` 为准**
（那里是页面内 rAF 逐帧采样，含 dt / Δmp / 归一化步进）。mp4 按 30fps 编码只是为了播放流畅，
不要拿视频帧数反推动画帧数。

## 8. A 修复后的复测（int b9e10c76：先跑过渡再挂载内容、面板固定宽度 + translateX、断点 880）

逐帧重采（1440×970，`frames/curves.md` 有曲线图：横轴 ms、纵轴 `--mp`、灰色竖条=长帧、竖线=反向触发）：

| 动作 | 帧数 | 球心 x 起→终 | 选中标签 x | 长帧 | teleports |
| --- | --- | --- | --- | --- | --- |
| 展开 | 35 | 720 → **0** | 732 → **363** | 7 | 2 |
| 收起 | 46 | **0 → 720** | 363 → 730 | 9 | 2 |
| 中途反向（t=737ms 触发，`--mp`=0.763） | 89 | 720 → **720** | 730 → 730 | 13 | 3 |

**关于残余 teleports 的判读（按 Lead 定的口径）**：本机与 A 那台机器的 headless SwiftShader 帧间隔都是
**双模态（约 7ms / 100–180ms 交替）**，所以不看原始 |Δmp|，而看「归一化步进 + 长帧单列 + 几何不变式」。
对每个被标记的帧做了**邻域聚合速率**核对（取该帧前后各一帧、共 3 帧的 Σstep / Σdt）：

| 动作 | 标记帧 | 邻域 3 帧的 Σdt / Σstep / 速率 | 结论 |
| --- | --- | --- | --- |
| 展开 | t=419 / t=424 | 139.1ms / 0.337 / **2.4/s** | 邻帧是 117.7ms 长帧且 step=0.051（mp 滞后一帧），聚合速率低于令牌曲线峰值（settle 在 520ms 上峰值 ≈8/s） |
| 收起 | t=649 / t=1068 | 519.7ms / 0.405 / **0.8/s** | 邻帧是 380.6ms 长帧（step 仅 -0.104），聚合速率远低于峰值 |
| 反向 | t=449 / t=463 / t=1061 | 434.6ms / 0.763 / **1.8/s** | 邻帧 184ms / 111ms 长帧，聚合速率低于峰值 |

即：**每个被标记的「跳」都紧邻一个长帧、且长帧里 mp 几乎没动**（采样器比写入方滞后一帧），
聚合到邻域后速率全部落在令牌曲线的量级内；几何不变式（球心 720→0、0→720、反向 720→720、
终点精确落位、过冲 0）全部成立。结论：**没有发现真实的瞬移**；残余标记是双模态帧下的采样相位差。
