### 3.1 验证状态不是一件事

| 状态 | 事实来源 | 展示位置 |
| --- | --- | --- |
| 配置已保存 | `credentials` 行 + 版本 | Key 详情 → 概览 |
| Key 已启用 | `enabled` / `status`（active / revoked / expired） | Key 列表 + 详情 |
| 模型发现 | `credential_models` 的 `discovered_at` 与发现错误 | Key 详情 → 模型 |
| 模型调用验证 | `credential_models.verify_state` + `verify_fingerprint` | Key 详情 → 模型（逐模型） |

验证结果按 **(连接, 模型, 配置指纹)** 记录：换 Key / 改地址 / 改协议后旧结论
`applies_to_current_config=false`，不会继续当作新配置的验证结果；单模型失败不判定整把 Key 失效；
迟到的验证结果不会覆盖已变化的配置。正常流程只验证用户选中的模型，不对发现的全部模型自动发起付费请求。

## 4. 数据迁移、用途解析与调用接入

### 4.1 数据模型

```
credentials（一条连接 = 一把 Key；地址 / 协议 / 标签 / 用量上限 / 用量账本 / 审计）
  └── credential_models（这条连接下已知的模型；来源 legacy / discovered / manual）
model_usages（用途 → 连接 + 模型；mode = explicit | legacy | inherit）
settings['model.default']（默认模型 = 连接 + 模型）
```

- 用量账本**只挂在连接上**：一把 Key 的额度是键级额度，不按模型复制、不重置、不重复计算。
- 同名模型来自不同连接时按 `(credential_id, model_id)` 区分，界面按服务商与连接分组显示。
- 迁移 73 追加两张表 + 索引 + 一次性回填；迁移 74 是补偿入口（只含可重放 DDL）。
  `SCHEMA_VERSION` / `COMPENSATION_VERSION` 随之前移，历史迁移一行未改。
- 回填规则：`default_model` 非空 → `credential_models(source='legacy')`；历史 tags → `model_usages`
  的 `mode='legacy'` 行；`is_default=1` → `settings['model.default']`。`default_model` 为空的旧凭据
  **不猜模型、不产生分配**；旧验证结论照抄但不伪造指纹。
- **为什么历史 tags 写 `legacy` 而不是 `explicit`**：基线里 tags 只参与「选哪把 Key」的政策，从不锁定
  模型。写成显式会让老用户那把它已经停用 / 欠费的 Key 把主对话直接打成硬失败 —— 违反「保留既有凭据
  选择政策」。`legacy` 行保留可见性与映射（历史不丢），实际仍按默认模型或既有 policy 选择。

### 4.2 用途解析（运行时唯一入口）

```
显式指定（model_usages.mode='explicit'）
  → 默认模型（settings['model.default']）
    → 基线 CredentialPolicy 回退（含 tags 政策）
```

- 显式指定不可用（停用 / 撤销 / 过期 / 预算耗尽 / 验证失败 / 连接缺失）→ **如实失败**并带原因码，
  绝不静默换用别的 Key。
- 默认模型不可用 → 按基线政策回退，但**标记降级**并给出原因与实际使用的目标（不静默）。
- 老库没有 `model_usages` 表或没有 `model.default` 键 → 直接走 policy，不抛异常。
- 已开始执行的调用保留原配置归属；一次 turn / 派生批次开始时冻结目标，后续调用用新保存值。

### 4.4 联网搜索

- 模型凭据与搜索凭据分开：博查 Key 不进模型列表、不进用途选择器。
- 回退顺序：博查 → SearXNG → Exa → Parallel → DuckDuckGo → 必应 → 百度。关掉免密钥通道只移除
  Exa / Parallel / DuckDuckGo 三条，其余配置与顺序不变。
- 新增 `GET /api/settings/search/status`（通道级 configured / check_state / checked_at / 原因码，不含密钥）
  与 `POST /api/settings/search/check`（真实一次极小请求，8 秒超时，区分 ok / 未配置 / 已关闭 /
  不可达 / 超时 / 限流 / 凭据无效 / 被拦截 / HTTP 错误 / 响应异常）。没有检查过就显示「未检查」，
  不会显示成已验证可用。
- 修正基线缺陷：默认返回条数与正文字符预算此前**只存不读**，现在工具每次调用读设置
  （范围 1–20 与 1000–40000，缺省 5 / 15000）。

## 6. 已知限制（不粉饰）

1. **未做真实联网与真实 Key 联调**：全部验证由 fake/mock 提供方驱动。服务商的真实可用性、真实
   模型列表形态、真实限流行为都未在真实端点上确认。
2. **研究（research）没有独立调用路径**：只有历史标签与 policy 回退，界面如实标注「未接通」，
   不提供看起来生效的选择器。
3. **写代码没有独立调用**：与主对话同一路径。
4. **视频 / 语音 / 嵌入沿用现有处理方式**：不继承默认对话模型；嵌入仍走本地方案，显式换外部模型
   只给出维度与重建影响的事实，未做自动重建。
5. **搜索连接检查结论是进程内状态**：重启后回到「未检查」，需要重新检查（诚实，但不跨重启保留）。
6. **公共模型目录**只做标注区分，未做「按 Key 过滤公共目录」的二次校验。
7. **旧 Key 管理与首次引导共用的凭据组件未重写**：设置页用新面板，首次引导继续用旧表单（同一套
   保存与验证逻辑与后端一致，但视觉不是新面板）。这是有意的范围控制，避免动首次引导机制。
8. 窄窗口（480 宽）下分类导航折成两行，属可用但需要产品确认的排布。
