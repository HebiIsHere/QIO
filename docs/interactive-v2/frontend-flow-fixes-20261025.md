## 2. 逐项结果（复现 / 根因 / 改动 / 用户可见变化）

### F01 恢复材料变更的影响确认（P1）

- **基线复现**：编辑执行中任务依赖的材料后，`impact-check` 返回 `impactConfirmationRequired=true`，顶栏停在「有改动尚未保存」，正文没有落库；DOM 里 `impact-dialog` / `role=dialog` 均为 0，页面没有任何确认或取消入口。旧 `ImpactConfirmDialog` 已从页面移除，统一审批层不承担材料影响确认。
- **根因**：`stores/interactive.ts` 仍会写 `pendingImpact`（含真实受影响任务、材料、checkId、stateVersion），但互动页没有挂载任何读取它的界面；保存门因此永久停在等待态。
- **改动**：新增 `v2/ImpactConfirmLayer.vue` 作为唯一影响确认面：读取 `store.pendingImpact`，显示真实任务 / 材料 / 后果与「等待确认，尚未保存」；确认调用既有 `confirmImpact`（校验 checkId + 板面版本 + 语义签名，过期 / 范围变化重新核实后重新展示），取消调用既有 `cancelImpact`（候选回退到已保存事实）；保存失败 / 预判失败保留候选并给重试入口。顶栏保存状态在等待确认期间显示「等待确认，尚未保存」（不再显示已保存）。与工具 / 权限审批共用「同一时刻只有一个阻塞确认面」规则：影响确认等待期间不自动弹审批，审批已打开时影响确认让位。
- **真实页面验证**：等待态文案、任务名、材料、后果均正确；「取消本次改动」后服务端未落库、任务继续运行；再次编辑并「确认改动」后服务端保存成功、执行中任务变为 paused、任务面板显示「已暂停」；刷新页面后仍是已保存内容 + paused，没有自动批准或重复提交。

### F02 提交—理解—意图确认—执行—成果同步（P1）

- **基线复现**：`InteractiveView.vue` 自己维护一份 `intentViews`，`store` 另有一份 `intents`；页面只 watch 最近一次提交 id；读取失败直接清空。延迟理解返回后新意图不会自动出现；同一意图还会在新链虚拟意图层与旧链预览层各出现一份。
- **根因**：意图状态没有唯一维护位置，刷新触发点只覆盖「下一次提交」，旧链预览没有对新链视图让位。
- **改动**：`intentViews` 收进 store，成为唯一维护位置（板面身份 + 读取代次 + 在飞去重 + 节流）；理解轮询 / 手动刷新理解 / 重试理解 / 按身份查证 / 恢复任务 / 确认与拒绝后统一刷新意图、正式板面、可见范围与执行记录；回前台与断线恢复只做只读核实；卸载 / 板面切换清理计时器与监听；迟到回执按板面身份与代次丢弃。集成收口：`BoardCanvas.previewIntents` 过滤掉 `store.intentViews` 已承接的 intent_id，旧链预览不再重复画。
- **真实页面验证**：同一板面上虚拟意图 4 个、旧链预览元素 0 个；对状态为 proposed 的意图点「确认这一条」后，服务端返回真实 turn_id，卡片原地从「待确认」变为「已确认（等待执行）」，提示明确写「已确认不等于已完成」，无需刷新页面；任务面板与执行记录同步刷新。

### F03 任务与批量操作入口（P1）

- **基线复现**：点「任务」只改 `store.tasksOpen`（aria-expanded 变化、body 文本长度不变、无面板）；旧 `IntentStatusPopover` / `IntentBatchTray` 未挂载；运行中任务没有暂停 / 取消入口。
- **根因**：入口仍写旧显示状态，承接组件已从页面移除。
- **改动**：新增 `v2/TaskCenterPanel.vue` + `v2/taskCenter.ts`，由「任务」按钮和提交区「批量审批」入口共同打开（内容、操作资格统一来自 `store.taskRows`：新链视图 + 旧链清单 + 执行记录）。运行中任务提供暂停 / 取消，暂停任务提供继续 / 取消，执行记录可打开；每个操作有进行中与失败反馈；文案明确区分「取消这条互动任务」与「停止当前聊天」。新链有意图视图时旧提交区不再渲染同一批对象的批准 / 拒绝（避免两套操作面），拒绝能力保留在新意图详情。
- **真实页面验证**：任务面板打开显示真实计数（执行中 1 / 已暂停 0 / 待处理 3 / 已结束 0）；点「暂停任务」→ 服务端状态 paused、面板计数与行状态原地更新；「继续任务」→ running；「取消任务」→ cancelled 并移入已结束、出现执行记录入口。批量待确认区显示逐条去向与「同批确认也在虚拟意图卡上」的真实指向。

### F04 重复拖线不得覆盖已有关系（P1）

- **基线复现**：从已连接的两端再次拖线，原关系含义「同一批材料」在关闭编辑器后被落库为空字符串（version 1→2），曲线保留、没有新增重复关系。
- **根因**：`BoardCanvas.finishLinkDraft` 不检查端点对是否已有关系，直接 `addLink(..., false, "")` 并 commit；`board.addLink` 对已有 pair 是「覆盖方向 / 含义」的 upsert。
- **改动**：`board.ts` 新增 `linkBetween`（忽略方向、兼容 `card:<id>`）；拖线落点命中已有关系时只选中 / 打开原关系编辑器，不 commit、不生成新关系；关闭 / 取消原样保留；只有用户明确保存才走 `updateLink` 改对应字段。`addLink` 保留显式「创建或更新」语义并写明界面拖线不得用它覆盖。卡片-卡片（正反方向）/ 卡片-组 / 组-组一致；删除后可按契约重建。
- **真实页面验证**：重复拖线打开编辑器时含义输入框为「同一批材料」；关闭编辑器后板面版本未前进（13→13），关系 id / 方向 / 含义 / 曲线 / version 全部不变。

### F05 恢复事项入口不依赖面板挂载（P1）

- **基线复现**：入口数量 = `Math.max(页面 fallback, 面板回传)`，只增不减；面板只在对话展开时挂载，完整数量依赖面板打开后回传；单条草稿冲突 / 保存失败等事项初始统计不全。
- **根因**：摘要维护在页面和面板两处，且取历史最大值；挂载 / 加载依赖对话布局。
- **改动**：`v2/recoverySummary.ts` 新增 `buildRecoveryItems`（稳定 id 去重，覆盖板面保存失败、卡片草稿保存失败、提交后刷新失败、提交结果未知、正文 / 删除冲突、草稿冲突、可恢复任务、自动重试用尽、影响确认等待）；store 维护 `recoveryItems` / `recoveryEntry`，入口计数只读 store，读取失败如实显示「这不代表没有事项」；处理后立刻减少；RecoveryPanel 一挂载就按 `active=true` 加载，不依赖对话展开。
- **真实页面验证**：受控让保存失败后，SaveFailureBanner 与恢复入口同时出现（计数 1）；收起对话后入口仍在，点开面板显示「板面没有保存 / 保存失败原因 / 重试保存」；恢复网络点重试后保存成功、入口与面板块同时消失（数量归零），服务端内容已落库。

### F06 意图读取失败保留旧内容并重试（P2）

- **基线复现**：`loadIntents` 失败直接 `intentViews = []`，无任何提示；首次失败与真实空态无法区分；旧失败响应可能清掉后续成功内容。
- **根因**：页面级加载没有保留上次成功内容，也没有错误状态与代次保护。
- **改动**：失败时保留最后一次成功内容，页面提示「更新失败，当前显示上次读取的内容」；从未成功读到过时提示「还没成功读到过，当前不能判定为空」；只有成功返回空集合才显示空态；旧失败按代次与板面身份丢弃；数据可疑时确认 / 恢复先暂停并说明；板面读取失败的重试同时恢复意图读取。集成收口：页面多条说明改为纵向堆叠，避免并发失败时互相遮挡导致「重试」点不到；同一数据源的恢复事项读取失败不再重复提示。
- **真实页面验证**：受控让 intent-views 返回 500 后，4 张意图卡保留、出现上述提示、重试按钮可点击（不再被遮挡）；恢复接口后点重试，提示消失、意图仍在。

### F07 菜单移出组避免重叠（P2）

- **基线复现**：从「成员与顺序」移出第一张成员后，被移出卡片停在原位置 (1180,120)，剩余成员被收拢到同一 (1180,120)，完全重叠。
- **根因**：`removeFromGroup` 只改成员列表、卡片不动；`arrangeGroupMembers` 又把剩余成员排到被移出者原来的槽位。
- **改动**：新增 `board.leaveGroupToFreeSpots`：先移除成员、受影响组按既定纵向排列收拢，再复用既有 `v2/geometry.avoidOverlaps` 为每张移出的卡片找「组外、与所有卡片 / 组框不重叠、位移最小」的位置；密集布局找不到完全空位时返回 `limited/conflicts` 并在界面明确说明，不静默叠放；成员变化 + 最终位置一次 commit（撤销一次恢复、重做一致）；拖动出组路径不变（仍按用户落点与既有避让）。
- **真实页面验证**：菜单移出 c_group_a1 后，被移出卡片落到 (1180,66)（组框上方，组框重算为 y=202），剩余成员在 (1180,260)，两者与组框都不重叠；无关卡片位置不变。

### F08 收起组内卡片定位必须可见（P2）

- **基线复现**：收起组后成员卡不渲染（count 0）；搜索命中并点定位后，组仍收起、成员卡仍未渲染、没有高亮 —— 定位实际什么都没发生。
- **根因**：`locate` 只做 `revealDelta + highlight`，没有先展开目标所属组，也没有按实际可用视野（浮动对话遮挡）计算。
- **改动**：`locate` 改为一次性异步流程：目标属于已收起组 → 先展开该组（纯显示态，不写板面）→ `nextTick` + 一帧等布局可用 → 用扣除标题栏 / 底部工具栏 / 审批浮层 / 浮动对话窗口后的实际可用视野定位 → 高亮；请求序号保证只执行最后一次明确请求，之后手动滚动不被抢回；不移动卡片、不改参与 / 成员 / 正文。搜索、书签、工具栏共用同一 `qio:interactive:locate-card` 事件。
- **真实页面验证**：收起组时成员 count=0；搜索「组内材料一」→ 定位后组 `data-collapsed=false`、成员渲染、高亮、卡片矩形 (467,193)-(787,313) 完整落在视口内。

### F09 关系胶囊拖动缩放换算与取消（P2）

- **基线复现**（C 组组件测试）：scale 0.5 / 2 下同一屏幕位移产生的 curve 偏移固定为屏幕像素（未按 scale 折算）；Esc / pointercancel / 失焦 / 卸载无取消，迟到 pointerup 仍提交；pointerId 无约束；拖动结束仍会触发 dblclick 编辑。
- **根因**：`startLabelDrag` 直接拿 `clientX/Y` 差值改板面坐标 `curve.x/y`（该层位于 `.board-surface` 的 `transform: scale()` 内），并用手写闭包监听，没有取消通道与手势身份。
- **改动**：`BoardLinkLayer` 新增 `scale` prop（默认 1，非正 / 非有限按 1）；位移换算统一走 `curveFromPointerDrag`（屏幕位移 / scale，clamp ±240）；拖动中只写临时预览，正常松手恰好 emit 一次；Esc / pointercancel / window blur / 卸载统一取消并恢复起始曲线、成对移除监听；pointerId 约束手势；拖动结束抑制 click / dblclick；拖动期间父层回写（撤销 / 重做 / 保存恢复 / 删除）取消旧拖动。B 在 BoardCanvas 接 `:scale="scaleSafe"`。
- **真实页面验证**：100% 下屏幕位移 (100,40) → curve 变化 (100,40)；200%（实测 1.93）→ (51.7,20.7)，期望 (51.8,20.7)；50%（实测约 0.53）→ (188.3,77.4)，与 100/scale 一致；撤销一次回到拖动前。

### F10 意图位置保存失败时显示与持久化一致（P2）

- **基线复现**：IntentLayer 内部 `localDisplay` 一直覆盖父级 `displayOverrides`，父级保存失败后的回退被本地值再覆盖；失败提示后位置仍停在拖动后的值。
- **根因**：临时显示位置与已确认位置混在一份覆盖表，失败回滚整块回退、没有按对象 / 操作版本归属。
- **改动**：新增 `v2/intentDisplayState.ts`（IntentDisplayAuthority）：区分临时拖动 / 等待保存 / 已确认位置；按对象 + 操作版本归属，旧失败不撤销新成功、单卡失败不影响其他卡；失败回到本次操作前位置；服务器读取的 display 优先于本机缓存，已结束操作清理临时覆盖；IntentLayer 手势结束把最终位置交回父级权威状态，pointercancel 取消回到本次手势开始位置。
- **真实页面验证**：正常拖动后服务端 display = 起点 + 位移，刷新后位置一致；受控让 display 保存接口 500 时，卡片回到拖动前位置（delta 0）、显示「已回到这次操作前的位置」与失败标记；恢复接口后再拖可成功且错误消失；拖动中派发 pointercancel 时位置回到手势开始、不发保存请求；连续两次快速拖动最终位置 = 两次位移之和、服务端 display 与页面一致。

## 5. 已知边界（本轮未改，如实保留）

- 「组收起」在新链前端仍是 `BoardCanvas` 的会话内显示状态（`collapsedGroupIds`），不读取 `board.groups[].collapsed`；刷新后不会自动保持收起。这是基线既有行为，不属本轮 F01–F10 的验收项；F08 已覆盖「收起后定位先展开」。
- 新建关系仍是既有流程：先落一条空含义关系再打开编辑器；F04 只修「从已有关系两端重复拖线覆盖原内容」，没有改变新建关系的既有交互。
- F10 的取消手势走 `pointercancel`（组件在 pointercancel 时回到手势开始位置）；本轮没有新增 Esc 取消意图拖动（F09 的关系胶囊拖动有 Esc 取消）。
- 任务暂停 / 继续 / 取消在真实后端上验证的是意图状态机与面板接线；受控种子意图没有真实模型执行，因此没有验证「真实模型产出成果卡」的端到端链路。
- 延迟理解（提交 → 后台理解完成 → 新意图出现）在真实后端需要模型凭据，本轮用受控测试覆盖该时序；没有真实模型运行的证据。
